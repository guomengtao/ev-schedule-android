## BUG 修复：真机"闪一下就退"（v0.1.0 → v0.2.0）
- 现象：用户装到安卓手机上，图标点开闪一下立即退出。
- 根因：**手工构建时把小米穿戴 SDK 的 class 只当作 `--classpath`（库）传给了 d8，没有作为【程序输入】打进 dex**。v0.1.0 的 classes.dex 只有 15.7KB / 20 个类（全是自己的代码）；运行时 `Wearable.getMessageApi()` 直接 `NoClassDefFoundError`，而它又在 `onCreate` 最前面，所以一启动就死。
- 修复（两处）：
  1. `build.sh`：先 `unzip` AAR 的 classes.jar 到 `out/sdkclasses`，再把 `out/sdkclasses + out/classes` 的 .class **一起作为 d8 的程序输入**（不再用 `--classpath libs/xms-wearable.jar`）。
  2. `MainActivity`：把 `buildUi()` 提到 SDK 初始化之前；`Wearable.getMessageApi()` 等所有 SDK 调用用 `catch (Throwable)` 包住（NoClassDefFoundError 不是 Exception）；新增全局 `UncaughtExceptionHandler` 把堆栈写到 `getFilesDir()/last_crash.txt`，下次启动时显示 —— 手机不在电脑边上也能看到崩溃原因。
- 验证：v0.2.0 dex 共 147 个类，其中 126 个是 `com/xiaomi/xms/wearable/*`；APK 37,291 B，dex 74,140 B。已确认 `Wearable` / `MessageApi` / `NodeApi` / `AuthApi` 都在 dex 里。
- 版本号：versionCode 2 / versionName 0.2.0。签名 keystore 未变（可覆盖安装）。

## 真机实测 + 签名不一致修复（第三轮）
- 用户真机日志（小米手环 10 Pro）：SDK 加载成功、`ServiceApiLevel=1`、`getConnectedNodes` 返回真实设备 `id=2137618976 name=小米手环10 Pro` → **证明小米运动健康可用、手环已连、包名一致**。之后所有设备侧操作全部 `SignatureVerifyFailedException: fingerprint verify failed`（`isWearAppInstalled`/`requestPermission`/`addListener`/`sendMessage`）。
- 根因：**APK 签名与 rpk 签名不是同一把**。查清了两把证书：
  - rpk 的签名密钥在本地 `tom/class/class/sign/{private.pem,certificate.pem}`（`EvBox/evbox/sign`、`tom/class/.temp_class/sign` 是同内容副本，三份 certificate.pem 摘要相同），证书 SHA-256 `46:6A:1E:83:…:9A:11`，**subject/issuer DN 为空**（小米在线签名工具生成），有效期 2026-09-01 → 2036-08-29。
  - 我们之前的自建 keystore 是 `EB:09:C8:3A:…:9D:F9` → 不匹配。
- 修复：`build.sh` 改为自动查找 rpk 的 sign 目录并用它签 APK（支持 `RPK_SIGN_DIR` 覆盖）。最终 APK 证书 SHA-256 = `466a1e83dfbd4dca17a8adc87a9b6a305bfde7a72035a5de2f620832b2399a11`（与 rpk 一致），APK SHA-256 `63150cadea430a364307c6f2373097f36f6f3e4f4c9e8112c92effc2e3869352`，37,289 B。
- ⚠️ **空 DN 证书坑**：JDK 的 X.509 解析器报 `CertificateParsingException: Empty issuer DN not allowed in X509Certificates`，apksigner（JDK 22）直接失败。解决：`apk/tools/BCSign.java` 把 BouncyCastle 注册为最高优先级 provider 再调 `ApkSignerTool.main`；`tools/bcprov.jar` 已下载。签名命令：`java -cp tools/bcclasses:$BT/lib/apksigner.jar:tools/bcprov.jar BCSign sign --key out/rpk-key.pk8 --cert <certificate.pem> --out x.apk in.apk`。
- 升级方式：**签名变了必须先 `adb uninstall com.application.watch.classschedule` 再装**。
- 若重装后仍报签名错 → 说明手环上那个 rpk 不是这把密钥签的，需用当前密钥重出 rpk 并重装（换签名重装会清数据，先备份）。

## v0.3.1：修「回包被吃掉」隐患 + 零风险下行验证（第五轮）
- 用户实测新信息：**`launchWearApp(nodeId, "com.application.watch.classschedule")` 能直接打开手环上的 EV 快应用**（uri 用包名就行）；`已授权: [data_manager]`。但 ping/export 仍然 **0 回包**。
- 用户提示：注意**回复的数据结构**，之前插件就是因为回包信息被屏蔽/丢掉。
- **最大嫌疑已修复**：`OnMessageReceivedListener.onMessageReceived` 是 **AIDL/Binder 线程回调**，v0.3.0 里第一件事是 `logView.append(...)` → 非 UI 线程碰 TextView 会抛 `CalledFromWrongThreadException` → **回包到了但死在"打日志"那一行，界面上一条不留**，与插件当年 `push_log()` 死锁是同一种死法。
  v0.3.1：所有日志统一 `runOnUiThread`；回调里**先无条件记「收到」**（len + UTF-8 + HEX 前 512B），再谈解析；加 TX/RX 计数。
- 新增「手表通知(验下行)」：`NotifyApi.sendNotify(nodeId, title, msg)` 让手环弹通知，**不经过 EV 的 interconnect、不动课表数据**，可单独证明「手机→手环」通不通。权限申请改为 DEVICE_MANAGER + NOTIFY。
- 新增「PING 重试×3」（手环冷启动窗口易丢）。
- 关键代码事实（读 EV 源码得到）：EV 的 `connect.onmessage` **只有在 JSON.parse 抛异常时才会静默 return（不回包）**；其余路径（含无 action → 当 import）都会回包。所以「0 回包」= EV 根本没收到 **或** `data.data` 不是可解析的 JSON 字符串 → 由此定位到「要么没送达，要么数据结构不对」。
- 素材：官方 demo 的 rpk 已下到 `tools/xms-demo.rpk`（15,781 B）；demo 的 `app-debug.apk`(8.3MB) 与 Android 源码 zip(22MB) 下载被限速到 ~29 B/s，**必须让用户从 GitHub 网页手动下**。

## v0.5.1：修首页闪退 + 换图标（第八轮）
- 用户反馈：装 v0.5.0 后**打开 App 立刻闪退**。
- **根因（纯静态就能确定）**：`HomeActivity.buildUi()` 里
  `stepRows[i] = Ui.text(this, stepLine(i, ...), ...)` —— 赋值发生在**最后**，而 `stepLine()` 内部有 `stepRows[i].setTextColor(color)`，执行时 `stepRows[i]` 仍是 **null** → NPE → onCreate 抛异常 → 闪退。
  - 教训：**副作用不要藏在"取值函数"里**；`a[i] = f(g(i))` 这种写法对"先赋值后使用"最容易翻车，拆两行最安全。
- 修复：`stepLine()` 只拼文案（绝不碰 View）；新增 `static int stepColor(int state)` 只返回颜色；三处调用（buildUi / startConnect / onUpdate）都改成先 `setText` 再 `setTextColor`。

  - ⚠️ 此前工程**没有资源目录**，build.sh 新增：`aapt2 compile --dir res -o out/res.zip`，再把它作为 link 的输入。
  - 同时加 `android:theme="@android:style/Theme.Material.NoActionBar"`（`Theme.Material` 是**深色**变体，避免启动闪白）。
