## APK 定位续讨（用户命题：本地课表 + 提醒 + 桌面插件，是否会被双源搞乱）
- 用户要求：**只讨论不写代码**。结论已回写 `MEMORY.md`（APK 产品定位章节）。
- 我的核心答复：**乱不乱取决于"要不要自动双向同步"，与"本地有没有数据"无关**。手动+单向+显式+覆盖前比对 ⇒ 可控。
- 关键论证：**可靠的上课提醒必须本地落数据 + 系统闹钟**（连手环拉必挂，已被 `docs/message-background-alert-review.md` 论证：前台服务被 ROM 杀、轮询受 Doze/15min 限制）→ 本地持久化是"提醒"的技术前提，不等于要做第二个产品。
- 分级建议：阶段 0 本地**只读缓存**+首屏课表+插件+提醒（不定 SSOT，零乱）→ 阶段 1 可视化编辑并选「手机为真源/手环为副本」→ 阶段 2 多套课表。
- 「没手环用户」：**战略放弃、产品不设限**；不为通用课程表特性（单双周/教学周/调休）写代码。
- 新增成本认知：`apk/res/` 只有 drawable，**零 XML**；AppWidget 强制引入 XML（RemoteViews/AppWidgetProvider/res-xml）。
- **待确认**（已抛给用户）：手环 EV 端能否自行增删改课程 —— 决定是否需要 hash 比对+覆盖提示。

## 续：多源写入不必过度担心（与用户达成共识）
- 用户观点：腾讯文档等云办公、GitHub 都是多源写入，别过度担心，给用户明确提醒即可。**我认可并修正了先前偏保守的表述。**
- 修正要点：
  1. 正确类比是 **Git（离线优先、重连三方合并）**，不是腾讯文档（在线实时 OT）；因为我们是两台离线设备偶发蓝牙连接。
  2. 课表是**离散记录列表**，比文本好合并得多；真冲突（同课同字段两边都改）极少。
  3. **最低安全网不是合并，而是"覆盖前显示差异摘要 + 确认"**（新增/修改/删除各几门）——零成本、消灭静默丢失。v1 到此为止。
  4. 有余力再加 record 级自动合并，前提是**课程稳定 id**（无 id 可用 name+day+time 指纹，改名会被识别为删+增）。
  5. 仍保留一条底线：**不要后台自动同步**（属用户预期问题，非技术问题）。
- 现实论据：手环端录入体验差 → 实际双写率极低 → 多数时候 watch 侧 diff 为空，同步即纯推送。

## USB 真机调试调研 → 产出 `docs/android-usb-debug-workflow.md`
- 实测环境：`~/android-sdk/platform-tools/adb`（1.0.41，未进 PATH）；`scrcpy` 未装；`adb devices` 里只有两台 **Emulator-Vela / NuttX**（ro.product.model=Emulator-Vela，Vela OS 12），**没有安卓手机** → 手机尚未被 adb 认可（待开 USB 调试 +「USB 安装」）。
- 发现本项目三个调试缺口（已在文档中给改法）：
  1. `apk/src` **零 `android.util.Log`** → logcat 一片空白，App 内日志面板看不到；建议加 `EvLog`(TAG=`EVProbe`) 并在 SyncEngine 的 log() 出口同步打。
  2. `<application>` 无 `debuggable` → `run-as` 读 `/data/data/**/shared_prefs/ev_settings.xml`、`ev_message_queue.xml` 均不可用，AS Profiler 也连不上；建议 build.sh 用 `DEV_DEBUG` 注入 `debuggable` / 加 `profileable`。
  3. 除 HomeActivity 外 8 个 Activity **非 exported** → `adb shell am start -n pkg/.DebugActivity` 必 Permission Denial。
- 建议新增 `apk/tools/dev.sh`（build → install -r -g → force-stop → logcat -c → start → dumpsys 校验 versionName）。文档未创建该脚本，留给待办。
- 版本确认口径：桌面名「Ev课程表」不带版本号 → 必须 `adb shell dumpsys package <pkg> | grep versionName` 验证真伪。

## 真机接线实测（adb 尚未拿到安卓手机）
- Mac USB 总线上确实有设备：`IORegistryEntry BLN-AL20`，`idVendor=4817`(0x12D1 Huawei)、`idProduct=4222`、序列号 `BTF4C17222009588` → **荣耀畅玩 6X 一类 EMUI 机**，物理连接+取电正常。
- 但 `adb devices` 始终只有两台 Vela(`emulator-5554/5556`, NuttX)，没有这台手机 → adbd 未启动/未授权（华为需在开发者选项开「USB 调试」+「仅充电模式下允许 ADB 调试」，通知栏 USB 模式切「传输文件(MTP)」，重插后点 RSA 允许）。
- ⚠️ 排错记录：`adb devices` 不带 `-l` 时 Vela 行的 serial 是 `emulator-555X` 且不含 "NuttX" 字样，按关键词 `NuttX` 过滤会失效，要按 serial 正则过滤；`adb connect localhost:555x` 会产生无用 offline 条目（`adb disconnect` 清不掉，重启 adb server 才行）。
- ℹ️ 即便连上，这台麒麟 EMUI 机只能验 UI（安装/启动/截图/投屏）；interconnect 链路必须有 `com.xiaomi.wearable`/`com.mi.health` 的手机才测得动。
