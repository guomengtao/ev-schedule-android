# 2026-09-29

- 新文档 `docs/apk-fast-activate-flow-analysis.md`（commit 7eac398）：安卓端激活机制稳定性/便捷性梳理 + 「手环引导 → APK 激活」新默认流程方案。核心结论：值得作为默认流程；服务端零改动，设计要点 D1-D5：
  - D1 暂存「兑换码+deviceId」双份，18 位码到手也存；换码失败→连上后自动补写；18 位码确定性生成所以幂等可取回。
  - D2 多手环需显式确认目标（deviceId 一致性校验，防错绑）。
  - D3 购买按钮用 `Intent.createChooser` 直达爱发电（不探测包可见性）；链接带 deviceId/c/r 追踪。
  - D4 一码一机语义不变：多个手环=多个兑换码；APK 本地存 redeemCode→deviceId→18位码 映射。
  - D5 EV 仓只加推荐卡+APK 下载二维码（activation.ux），原三步流程下移保留兜底；iOS/鸿蒙需明示不支持。
  - 实施顺序：APK 侧 → app-auth 网页 → EV 仓手环推荐卡（需发版）。
- 现状要点：FastActivateActivity 目前单 EditText 无四格 UI、无暂存、未连接即卡死、无购买直达按钮——这四点是新流程要补的。后端 `/api/activate` 幂等复用/一码一机/NA 限额/失败漏斗已完备，直接复用。
