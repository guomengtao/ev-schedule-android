# 课程可视化编辑器方案分析

> 分析日期：2026-09-30（v2，修订：入口设计 / 课程名与课表名方案 / 删除功能 / 周为单位确认）
> 背景：上一阶段上线了通用 JSON 编辑器（`JsonEditorActivity` + `JsonEditorView`，带行号/高亮/校验/复制），「编辑课表」「新建课表」都走它。
> 本次要解决的是：**JSON 编辑对普通用户太硬** —— 想改一门课的教室，要在一堆引号逗号里找位置。需要一个真正"所见即所得"的课程编辑页。

---

## 1. 现状与痛点

### 1.1 现有编辑链路

```
课程表管理（ScheduleListActivity）
  └─ 点 ✏️ → JsonEditorActivity（整张课表 = 一坨 JSON）
       └─ 改完点「更新课表」→ ScheduleStore.updateCourses()
```

### 1.2 数据模型（编辑器要对齐的事实）

- 课程字段就 5 个：`name` / `time`（自由文本，如 `08:00 - 09:35`）/ `teacher` / `location` / `day`（0=周一 … 6=周日）
- **没有"第几节"概念，也没有周次/日期概念**：一套课表就是一个课程列表，天然以周为单位全周统一
- 课程颜色由 `Ui.courseColor(name)` 按课名 hash 稳定生成，任何页面同色
- 课表名 `Schedule.name` 是课表的身份之一：sync 课表 id = `ev_watch_ + 课表名`（同名即同一套）
- 主题是代码动态切换（`Ui.applyTheme` + `themeVersion`），控件全用代码构建，**没有 XML 布局**
- 首页周视图（`HomeActivity.renderWeek`）课程块**目前不可点**，只有日期条/课表名入口/"单"字按钮可点 —— "点课编辑"是全新交互
- 保存后联动链路现成：`updateCourses` → active 课表直写 `CourseCache` → 三插件刷新 + 提醒重排

### 1.3 JSON 编辑器的痛点

| 痛点 | 用户原话（推测） |
|------|----------------|
| 改一门课要在 30 行 JSON 里定位 | "我只想把体育课换个教室" |
| 忘了逗号/引号就报错 | "第 5 行什么问题？看不懂" |
| day 要写数字 0-6 | "0 是周一还是周日？" |
| 没有全局视野 | "我周三下午到底有没有课？" |

**结论：JSON 编辑器保留为"高级模式"，可视化编辑做成默认模式。**

## 2. 方案选型

| 方案 | 描述 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 表单列表式 | 每门课一行，点开进表单页 | 实现最简单 | 看不到一周全貌，加课时不知道哪天哪格空着 | ✗ |
| B. 周视图网格式 | 7 列网格 + 课程色块，点格子操作 | 所见即所得，与首页周视图心智一致 | 自绘工作量略大 | ✓ **主方案** |
| C. 混合式 | 周视图为主 + 单课表单弹层 + JSON 高级入口 | 兼顾小白与进阶 | — | ✓ **推荐** |

## 3. 入口设计

### 3.1 最初的思路（v1）

编辑是低频管理动作，入口放在「课程表管理」页的 ✏️，理由：
1. 首页是"看"的表面，保持只读，避免误触改数据
2. 编辑页和浏览页职责分离，各自的交互不用互相迁就

### 3.2 修订后的入口（v2，采纳"首页直达"）

v1 的入口链路太深（首页 → 课表管理 → 编辑），改一门课要点三层，不符合"改个教室"这类高频小动作。修订为**首页进入编辑态为主入口**：

```
首页周视图头部：  📅 本周课表  [单] [✏️编辑]     ← 新增编辑按钮，与「单」并列
                      ↓ 点 ✏️
              ┌────────────────────────┐
              │  进入【编辑态】页面       │   ← CourseEditActivity，
              │  （网格视觉与首页一致）    │      顶部标题"编辑课表"+ [✓完成]
              └────────────────────────┘
                点课程色块 → 编辑该课（弹底部面板）
                点空格子   → 在该位置添加课程（弹添加面板）
                点 ✕ 角标  → 删除该课（可撤销）
                      ↓ 点 ✓ 完成
              落盘 + 返回首页，周视图立即刷新
```

**为什么是"进编辑态的独立页面"，而不是直接在首页周视图上就地编辑**：

1. 首页还承载今日课程、连接状态条、周切换（weekOffset）等职责，课程块就地可编辑后，误触风险高（本想看详情结果改了数据）
2. 首页周视图带时间轴 + 今日列蒙层 + 翻周状态，把命中编辑、空格添加、拖动换天混进去，浏览逻辑和编辑逻辑会缠在一起
3. 独立编辑页同样是"点一下就进入编辑状态"，**操作心智与预期一致**，但浏览/编辑切换边界清晰，退出（✓ 完成 / 放弃）语义明确

**辅助路径（不进编辑态的轻量查看）**：首页点课程色块 → 只读详情小卡片（课名/时间/教室/老师 + [编辑] 按钮）→ 点 [编辑] 直接进编辑页并打开该课的编辑面板（带参数跳转）。这条满足"在首页看到课有问题，顺手就能改"。

**原入口保留**：课程表管理页 ✏️ 也指向编辑态页面（原来指向 JSON 编辑器的入口改为可视化编辑器），JSON 编辑器降级为编辑页头部的「JSON」按钮。

### 3.3 空格子添加：默认参数规则

点空格子 = 在**当前位置**添加，面板预填：

| 字段 | 默认值 |
|------|--------|
| 星期 | 该列 |
| 时间 | 该列空档的下一个常用时段：优先取该列已有一节课的"下一节"模板（如上节是第1-2节 → 预填第3-4节）；该列没课时 → 预填第1-2节 |
| 课程名 | 弹出「最近使用」课程名 chips，点一下即填（详见第 5 章） |
| 教室 / 老师 | 若选了最近用过的课程名 → 自动带出该课程名上次填的教室/老师；否则留空 |

这样"周三下午加一节数学"实际操作 = 点周三空格 → 点「数学」chip → 点确定，**3 次点击**。

## 4. 可视化编辑页设计（CourseEditActivity）

### 4.1 整体布局

```
┌──────────────────────────────────────┐
│ ←  2026春季课表 ✏️（可点改名） [JSON][✓]│  ← 返回 / 改课表名 / JSON 模式 / 完成
│     来自手环 · 8 门课 · 有未保存修改*    │
├──────────────────────────────────────┤
│  周一  周二  周三  周四  周五  周六  周日 │  ← 星期表头
│ ┌────┬────┬────┬────┬────┬────┬────┐ │
│ │▉高数│▉数据│▉线代│     │▉程序│    │    │ │
│ │A301 │结构 │C203│    │设计 │    │    │ │  ← 课程色块（courseColor 同色）
│ ├────┼────┼────┼────┼────┼────┼────┤ │
│ │▉英语│▉体育×│   │▉物理│    │    │    │ │  ← × 角标：编辑态下显示，点按删除
│ │B102 │体育馆│   │301 │    │    │    │ │
│ ├────┼────┼────┼────┼────┼────┼────┤ │
│ │ ＋  │    │    │    │    │    │    │ │  ← 空格子，点击=按 3.3 规则添加
│ └────┴────┴────┴────┴────┴────┴────┘ │
│   💡 点色块编辑 · 点空格加课 · 长按拖动  │
├──────────────────────────────────────┤
│ [＋ 添加课程]   [✓ 完成]  [放弃更改]    │  ← 底部固定栏；无修改时「放弃」隐藏
└──────────────────────────────────────┘
```

要点：

- **网格行高固定**，每天的课从上往下堆叠 —— 数据模型只有时间字符串，没有节次轴，强行做时间刻度会失真；首页那种时间轴是浏览优化，编辑网格不需要
- 空课表时中央给一个大的「＋ 添加第一门课」引导块
- 顶部副行实时显示「有未保存修改」状态（草稿模型，见第 7 章）

### 4.2 交互定义

| 手势 | 行为 |
|------|------|
| **点课程色块** | 弹出单课编辑底部面板（4.3） |
| **点空格子** | 弹出添加面板，按 3.3 预填默认参数 |
| **点色块右上角 ×** | 删除该课 + Snackbar「已删除 · 撤销」（见第 6 章） |
| **长按色块** | 菜单：拖动换天 / 复制到其他天 / 删除 |
| **拖动色块到别的列** | 松手换 day，色块即时移动（换的是星期，时间不变） |
| **顶部 [JSON]** | 当前草稿序列化成 JSON，跳 `JsonEditorActivity`；返回时合法则回填草稿（双向互通） |
| **返回键 / ←** | 有未保存修改 → 三选弹窗「保存 / 放弃 / 继续编辑」 |
| **点顶部课表名** | 弹重命名输入框（见 5.3 课表名方案） |

### 4.3 单课编辑底部面板（BottomSheet）

**为什么不跳整页**：改个教室不应打断"看着课表改课"的上下文，底部面板半透明露出课表，改完立即看到色块变化 —— 这是编辑体验的核心反馈闭环。

```
┌──────────────────────────────────────┐
│              ──（拖动条）──            │
│  课程名 *                              │
│  ┌────────────────────────────────┐  │
│  │ 高等数学                        │  │
│  └────────────────────────────────┘  │
│  最近使用: (数学)(语文)(英语)(物理)(…) │  ← chips，点一下即填（见 5.1）
├──────────────────────────────────────┤
│  星期    (一)(二)(三)(四)(五)(六)(日)   │  ← chip 单选，选中=ACCENT 实心
├──────────────────────────────────────┤
│  时间                                  │
│  (第1-2节 08:00-09:35) (第3-4节 …)     │  ← 常用时段 chip（见 4.4）
│  (第5-6节 …) (第7-8节 …) (晚课…)(自定义)│
│  自定义: [08:00] — [09:35]             │  ← 选中自定义才展开
├──────────────────────────────────────┤
│  教室 [教学楼A301    ]   老师 [      ]  │
├──────────────────────────────────────┤
│  [从其他天复制此课 ▾]     [删除] [确定]  │
└──────────────────────────────────────┘
```

- 面板按钮是「确定」而不是「保存」—— 只更新编辑页草稿，不落盘，避免用户误以为整张课表已生效
- 「删除」红色文字按钮，点击后关面板 + 色块消失 + Snackbar 可撤销（见第 6 章）
- 「从其他天复制此课 ▾」：把这节课（名字/时间/教室/老师）克隆到勾选的其他星期，执行前确认

### 4.4 时间 chip 的来源（数据模型只有字符串，怎么规范输入）

- 内置一套**常用节次模板**（大学通用五段），点选后自动生成 `"08:00 - 09:35"` 格式字符串：
  `第1-2节 08:00-09:35`、`第3-4节 10:00-11:35`、`第5-6节 14:00-15:35`、`第7-8节 16:00-17:35`、`晚课 19:00-20:35`
- 模板仅是**输入辅助**，存进去的还是普通字符串；从手环同步来的 `19:30-21:00` 这类非标时间正常显示，点开编辑时若不匹配任何模板则自动选中「自定义」
- 自定义用两个 `TimePicker`（或格式化输入框），输出统一 `HH:mm - HH:mm`（与现有数据格式一致）

## 5. 课程名与课表名方案

这是两层不同的名字，方案分开定：

### 5.1 课程名（Course.name，一门课的名字，如"语文""数学"）

**同名课程怎么办 —— 允许同名，同名是正常且有用的**：

- 同名 = 同颜色（`courseColor` 按课名生成），"周一的语文"和"周三的语文"天然同色，视觉上自动归组，这是**特性不是冲突**
- 输入时自动补全：候选 = 当前课表已有课名 ∪ 本机所有课表出现过的课名（按使用频次排序）；点选已有课名 → 顺带带出该课名最近一次填的教室/老师，减少重复输入
- 面板顶部「最近使用」chips：最近用过的前 8 个课名，一键填入 —— "加一节数学"绝大多数时候就是点一下 chip
- **唯一要拦的冲突**：同一天 + 同一时间段 + 同名（完全重复）→ 确定时黄色警告「该时段已有一节数学」，用户确认仍可存（手环协议不禁止，不搞硬拦截）

**课程名为空怎么办 —— 保存时硬拦**：

- 课程名是颜色的来源、手环/插件展示的主字段，空名会导致色块没有字、无法区分课程，视觉灾难比"逼用户起个名"更糟
- 规则：确定时课程名为空 → 输入框红字提示「请输入课程名」并聚焦，不弹对话框不打断
- **不设**「未命名课程」兜底默认名 —— 多节"未命名"堆在课表里比拦截更难收拾

**要不要独立的"课程名字典"管理页 —— 不要**：

- 课名的生命周期跟着课表走，独立字典会引入"字典里有、课表里没有"的同步问题
- 自动补全候选集（5.1 第一条）已经是隐式字典，零维护成本
- 预留阶段 2：若后续做"常用课程预设"（跨课表的课名+教室组合包），再考虑轻量管理入口，本期不做

### 5.2 课表名（Schedule.name，整张周课表的名字，如"2026春季课表"）

课表名不只是显示名，**它是课表的身份**：

- sync 课表 id = `ev_watch_ + 课表名`，与手环 `list_schedules` 的名称列表对齐，**同名 = 手环侧同一套课表**
- `ScheduleStore.markSynced` 现有逻辑：本地上传后若手环已有同名课表 → 本地记录直接被手环版覆盖

因此课表名的规则：

| 情形 | 规则 |
|------|------|
| 新建课表未填名 | 兜底「未命名课表」（`addLocal` 现有行为），编辑页顶部常驻可点改名 |
| 编辑页改名 | 点顶部课表名 → 输入框改名 → 草稿保存时一并提交（`updateCourses` + name 字段更新） |
| **与已有课表重名** | 黄色警告：「手环上已有一套同名课表，同步后本课表会与它合并」——因为同名在 sync 语义下就是同一套。local 课表重名仅提示不阻断 |
| 名字长度 | 建议 ≤ 12 字，超出截断显示但不拦（手环侧显示由手环控制） |

### 5.3 两个名字的关系图

```
课表名「2026春季课表」          ← 管理一套周课表的整体（切换/同步/删除的粒度）
 └─ 周一  语文 08:00-09:35     ← 课程名是周内一门课的名字
 └─ 周三  语文 08:00-09:35     ← 同名课程 = 同色，全周统一
```

## 6. 课程删除功能

### 6.1 删除形态（单课）

| 形态 | 交互 | 定位 |
|------|------|------|
| **色块 × 角标**（主路径） | 编辑态下每个色块右上角显示小 ×，点按即删 | 最短路径："上午三节数学不要了" → 点 × 完事 |
| 面板「删除」按钮 | 单课编辑面板左下角红色「删除」 | 第二路径，编辑过程中顺手删，且可发现性最好 |
| 长按菜单「删除」 | 长按色块 → 拖动/复制/删除 菜单 | 与拖动换天共用入口 |
| ~~滑动删除~~ | — | ✗ 不做：网格里横滑与页面滚动/拖动手势冲突，收益小 |

### 6.2 删除的反馈与反悔

- 每次删除 → Snackbar「已删除"数学"（周三 第1-2节）· 撤销」，5 秒内可撤销；连续删除多条时 Snackbar 覆盖刷新（每条各自可撤，撤的是最近一条）
- 删除只改**草稿**，点「✓ 完成」才真正落盘 —— 即便错过撤销窗口，只要没点完成、放弃更改即可整体反悔
- 删除后的空格自动回归"可点添加"状态

### 6.3 批量删除（轻量）

- 「清空这一天」：长按星期表头 → 确认弹窗「删除周一全部 3 门课？」—— 换课/重排时高频有用
- 不做"选多个色块批量删"：多选状态机复杂度不值得，单课 × + 清空一天已覆盖真实场景

### 6.4 边界

- 删除的是 sync 课表时，与其他编辑一致：只改本机副本，完成后 Toast「已更新本机副本，需同步到手环才会写回」
- 删到 0 门课：允许（空课表是合法状态，`setActive` 已有"切到空课表→插件显示无课"的处理）；编辑页显示「＋ 添加第一门课」引导
- 「从手环删除整张课表」不在此范围（走课程表管理页的删除，手环删除协议现状见《课程表编辑与删除方案分析.md》第 5 章）

## 7. 保存模型：草稿 + 显式提交

```
进入编辑页
  → 从 ScheduleStore 深拷贝一份 courses 作为【草稿】（内存）
  → 所有增删改/拖动都只改草稿，色块实时刷新（即时反馈、零等待）
  → 点「✓ 完成」→ ScheduleStore.updateCourses(id, 草稿)（+ 课表名如有改动）
       ├─ active 课表 → 自动直写 CourseCache（插件/提醒联动，现成链路）
       └─ source=sync 课表 → Toast「已更新本机副本，需同步到手环才会写回」
  → 返回键且草稿≠初始 → 三选弹窗「保存更改 / 放弃 / 继续编辑」
```

为什么不用"每改一门就落盘"：中途误删 5 门课没法整体反悔；草稿模型让「放弃」有真实语义，且落盘次数少、SharedPreferences 写入压力小。

## 8. 以周为单位：语义确认

- 数据模型一套课表就是一个 `courses` 列表，**没有周次/日期维度** → 课表天然全周统一，"改一处全周生效"就是现状语义，编辑器不引入单双周/按日期排课（手环协议也不支持）
- 首页 `weekOffset` 翻周只是**视图平移**（看过去/未来的同一张周课表），编辑器固定编辑"这张周课表"，与当前翻到第几周无关
- 假期调休由 `Schedule.holiday` + `Holiday` 模块处理，不属于课程编辑范围

## 11. 风险与边界

| 风险 | 应对 |
|------|------|
| 时间字符串格式五花八门（手环同步来的） | 解析容错：能识别 `HH:mm-HH:mm`/`HH:mm - HH:mm`/含"第N节"的，识别不了原样展示、自动落"自定义" |
| 拖动手势与滚动手势冲突 | 长按 300ms 激活拖动；网格整体高度控制在一屏内 |
| × 角标热区太小难点按 | 角标热区 ≥ 32dp（视觉小、热区大），且面板「删除」按钮是兜底路径 |
| 编辑的是 sync 课表，用户以为手环已更新 | 完成时显式 Toast；列表页「同步到手环」按钮本就存在 |
| 草稿期间被自动同步覆盖 | 草稿只在编辑页生命周期内；编辑页 `onResume` 不主动刷新（以用户草稿为准），完成后统一落盘 |
| 主题切换丢草稿 | recreate 前把草稿序列化进 `onSaveInstanceState`（JSON 字符串，天然可序列化） |
| 课表重名导致手环侧合并 | 重名时黄色警告（见 5.2），文案说清"同步后会与同名课表合并" |

## 13. 总结

1. **入口**：首页周视图头部新增 ✏️ 进入编辑态独立页面（非首页就地编辑，浏览/编辑边界清晰）；首页点课程 = 只读详情 + [编辑] 快捷跳转；空格子点击即按"该列 + 下一时段 + 最近课名"预填添加，3 次点击加一节课
2. **课程名**：允许同名（同名同色是特性），自动补全 + 最近使用 chips 兜输入效率；空名保存时红字拦截，不做"未命名"兜底；不做独立课名字典页
3. **课表名**：它是课表身份（sync id = ev_watch_+名字），编辑页顶部可点改名，重名给"同步后会合并"警告，空名兜底「未命名课表」
4. **删除**：色块 × 角标主路径 + 面板删除按钮 + 长按菜单，Snackbar 撤销，草稿模型下整体可反悔；附「清空一天」批量形态；不做滑动删除和多选
5. **周为单位**：数据模型天然全周统一，编辑即全局生效，不引入周次/单双周概念
6. **保存**：草稿 + 显式 ✓ 完成，落盘复用 `updateCourses` → CourseCache → 插件/提醒现成链路；JSON 降级为高级模式，经同一套换算工具与草稿互通
