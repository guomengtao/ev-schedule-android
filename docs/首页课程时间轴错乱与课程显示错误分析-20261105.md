## 一、结论先行

首页课程的错误不是「课程名写错了」，而是**周课表网格的行模型错了**：

1. **时间轴没有按时间排序**，按的是数据插入顺序 —— 出现 `10:55` 置顶、`12:55` 排在 `11:20` 前、`18:50` 掉到 `19:40` 之后。这是主错误。
2. **时间槽按「开始时间字符串」精确去重并跨天共享行**，导致同一节课（晚一 18:45 / 18:50）被拆成两行、互留空格，且同时间多门课会被静默覆盖丢课。
3. **课程名被硬裁切**，四字课名一律只剩三字（「科学素」「职业素」「人文素」「政治素」「信息技」），无省略号、无点击看全名。
4. **列语义不可见**：截图看不到星期/日期表头，两列内容不一致却无标注，容易被误读成「两门课并列」或「同步前后对比」。
5. 附带口径问题：底部「23 门课」是整份课表 7 天的总数，画面可见 22 个课程块，二者不是同一口径（不是丢课，但会让人误以为丢了一门）。

根因集中在一个函数：`HomeActivity.weekGridWithTime()`（1041 行起）。

## 三、错误清单与代码级根因

### E1（P0）时间轴乱序 —— 时间槽未按数值排序

`HomeActivity.weekGridWithTime()` 1045-1052 行：

```java
java.util.Set<String> timeSet = new java.util.LinkedHashSet<>();
for (CourseCache.Course c : all) {
    if (c.time != null && c.time.length() > 0) {
        timeSet.add(CourseCache.shortTime(c.time));   // 只取 "HH:mm"
    }
}
java.util.List<String> timeSlots = new java.util.ArrayList<>(timeSet);  // ← 没有 sort
```

`LinkedHashSet` **保留首次插入顺序**，而 `all = s.courses` 的顺序来自手环导出 JSON，全链路没有任何按时间排序：

- `ScheduleStore.upsertFromWatch()` 321 行：`s.courses.addAll(CourseCache.flatten(dayGrouped))`
- `CourseCache.flatten()` 150-184 行：按「天数组 → classes 数组」原始顺序 `out.add(co)`，不排序
- `ScheduleStore.fromJson()` 706-713 行：按 JSON 数组顺序 `s.courses.add(...)`，不排序
- 落盘/读回同样不排序

因此左侧时间标签的行序 = **手环侧 JSON 里课程出现的先后**，不是时钟先后。手环导出若按「节次 id / 录入顺序 / 编辑顺序」排列（而不是按 HH:mm），就会呈现截图这种乱序。

对比证据：同一份代码里其它路径都做了排序 —— `CourseCache.coursesOfDay()` → `sortByTime()`（305 行）、`sortForWeek()`（290 行）、首页焦点卡 `HomeActivity.java:728` 用 `CourseCache.minutes(a.time)[0]` 数值排序。**唯独周网格的时间槽列表漏排**，属于局部漏排而非设计取舍。

影响：`午休(12:55)` 显示在 `11:20` 的课之前；`晚一(18:50)` 排在 `晚二(19:40)` 之后；「第 N 节」的语义、当前节高亮、进度判断全部失真。

### E2（P0）时间槽精确字符串去重 + `map.put` 覆盖 → 拆行 / 空槽 / 静默丢课

同函数 1045-1052、1130-1149 行：

```java
java.util.Map<String, CourseCache.Course> map = new java.util.LinkedHashMap<>();
for (CourseCache.Course c : dayList) {
    String key = CourseCache.shortTime(c.time);
    map.put(key, c);            // ← 同一天同一开始时间的第二门课被覆盖，不报错
}
for (String ts : timeSlots) {
    CourseCache.Course c = map.get(ts);
    ... else { /* empty slot */ }
}
```

三个具体后果：

1. **跨天差 5 分钟被拆成两行**：截图第 11/13 行，左列的「晚一」18:45、右列的「晚一」18:50 本是同一节课，因字符串不同各占一行，彼此留一个空格。13 个不同开始时间 → 13 行，7 天共享，天与天节次时间不齐时必然稀疏。
2. **同键覆盖**：某天同一 `HH:mm` 有两门课（例如合班/单双周），只会显示 JSON 里靠后的那门，另一门无提示地消失。
3. **10:55 整行空**：`timeSlots` 从「全部课程」收集，但该行在可见两列都无块。合理候选原因有二 ——（a）该课属于被判定为假期的天列，而 1101-1117 行的假期分支会 `continue` 整列清空、只画假期名，时间槽却仍被收集；（b）该课落在截图视口外的其它天列。**需原始课表 JSON 才能定论**，不妄断。

### E3（P1）课程名硬裁切

`courseBlockCompact()` 1165 行起：

```java
TextView tv = Ui.textMediumLh(this, disp, ...);
tv.setGravity(android.view.Gravity.CENTER);
tv.setSingleLine(true);        // ← 没有 ellipsize / marquee / 换行兜底
```

列宽约 `(屏宽 - 36dp 时间列) / 7`，在 SP_CAPTION 字号下容不下 4 个汉字，于是「科学素养 / 职业素养 / 人文素养 / 政治素养 / 信息技术」一律被裁成 3 字，且没有省略号。`ellip6()` 只用在地点行，课名没有兜底。用户无法区分「科学素养」和「科学素养（实验）」这类同名前缀课程。

### E4（P2）列语义不可见 / 当前节指示位置存疑

- `renderDateStrip()`（584 行）生成 7 格「星期 + 日期」表头，但截图里看不到（页面已向下滚动，表头滚出视口，只剩顶部一个蓝色圆角）。两列内容不一致时没有列标识，信息不可读。
- 顶部蓝色圆点/圆角若代表「今天列高亮」或「当前节」，它落在 10:55 行附近，而状态栏是 17:20 —— 与乱序时间轴叠加后，位置指示同样不可信。
- 需确认是「日期格高亮」还是「当前节指示器」，二者修法不同。

### E5（P2）口径提示：23 门课 vs 画面 22 个块

`HomeActivity.java:1015` 的 `s.courses.size()` 是**整份课表（7 天）的课程总数**；截图可见 22 个课程块，另有空槽行。这不是数据丢失，但文案「23 门课」紧贴网格，容易被读成「本屏应有 23 个块」。建议改为「本周共 23 门课」或标注口径。

### E6 版本口径提示（影响复核方式，不是错误本身）

截图的课程块是**纯饱和色块 + 白字**；当前 HEAD 的 `Ui.courseBlockBg()`（369-386 行）是「4dp 身份色条 + 浅色面 + `Ui.courseInk` 深字」（ev-ui-android v1.1）。说明**截图 APK 与当前仓库 HEAD 不是完全同一版本**。时间槽乱序逻辑在 HEAD 仍原样存在（`weekGridWithTime` 1041-1052 行可核对），但修复前应先确认线上 APK 版本号，按对应 tag 复核 E3/E4 的表现。
