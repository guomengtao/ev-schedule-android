# APK 界面 / 桌面小插件 / 主题体系 分析与方案

> 日期：2026-09-28
> 回答四件事：① APK 的 UI 是"固定"的吗？② 桌面小插件做哪几种、什么形式？③ 要不要引入 UI 框架？④ 课程表 / 学生群体用什么配色？
> 依据：逐条核对当前代码与构建链（v0.5.28），不引用外部传闻

---

## 一、结论速览

| 问题 | 结论 |
|---|---|
| APK 主题是固定的吗 | **是的，写死在 `Ui.java` 的 10 个常量里，没有主题层** |
| 手环那 10 套模板，APK 接了吗 | **没有接**。APK 现在只能写手环的 `homepage` 显示开关 + `baseFontSize` |
| 能不能做成和手环一样的模板机制 | **能**，而且 appearance 域在权限矩阵里本来就是"默认读 + 可写" |
| 要不要引入 UI 框架（Compose / Material） | **不要**。成本远大于收益，详见 §3 |
| 桌面插件做哪几种 | **先做 4×2「今日课程」+ 4×1「下一节课」两个** |
| 配色怎么选 | **默认改清爽浅色（推荐「晴空蓝」），深色留作夜间** |

## 二、先回答你最关心的问题：APK 上的 UI 是固定的吗？

### 2.1 现状：手机端是**写死**的一套

所有颜色、间距都在 `Ui.java` 里硬编码，一共 10 个常量，**没有任何主题层**：

```java
BG #0B1020 / CARD #151C30 / CARD2 #1C2542 / LINE #27314C
TEXT #E9EEF9 / MUTED #8695B4 / ACCENT #4C8DFF
OK #34C759 / WARN #FFB020 / ERR #FF6B6B
```

好处是极致简单、零依赖；代价是**想换个颜色必须改代码重打包**。

### 2.2 手环的"10 套模板"，APK 目前**完全没用上**

核对 `HomepageSettingsActivity`，APK 现在能写到手环的只有两类东西：

| 能力 | 字段 | 现状 |
|---|---|---|
| 手环首页显示开关 | `showQuickAdd` / `showStatusBar` / `showDayNavZong` / `showDayNavJin` / `showDayNavMing` / `showCustomContent` / `showTime` / `showPinnedBar` | ✅ 8 个开关可读写 |
| 手环课程字号 | `baseFontSize` | ✅ 5 档：28 / 36 / 48 / 62 / 76 px |

**没有**任何模板、主题、配色的读写——`SyncEngine` 里搜 `appearance` / `template` 是 0 结果。

所以现在的状态是：

> **手环有 10 套皮肤，手机端一套深空蓝写死，两端各说各话。**

### 2.3 好消息：技术上完全可以打通

手环的数据开放边界里，`appearance`（模板 + 字号）是 **默认读 + 可写**。也就是说：

- 手机端**跟随**手环模板自动换肤 ✅ 技术上没问题
- 手机端**反控**手环模板 ✅ 技术上没问题

⚠️ **待确认（卡住点）**：EV 侧的 `update_settings` 是否接受 `appearance` 字段？当前 APK 只发了 `homepage` + `baseFontSize`。需要先确认 EV 的协议，否则写过去会被当成未知字段忽略。

## 三、UI 框架：要不要引入？

### 3.1 先看硬约束（这是判断的基础）

| 项 | 现状 |
|---|---|
| 构建 | **无 Gradle**，手工链：`aapt2 → javac(JDK8) → d8 → apksigner` |
| 三方库 | `libs/` 只有 `xms-wearable.jar` + `zxing-core.jar` |
| AndroidX / Support / Kotlin | **源码里零引用**（已全仓搜索确认） |
| 布局资源 | `res/` 下**只有 drawable**，零 XML，全部 UI 是 `Ui.java` 手写 View |
| SDK | minSdk 24 / targetSdk 34 |
| 当前包体 | **311 KB** |

### 3.2 四个候选的可行性

| 方案 | 可行 | 理由 |
|---|---|---|
| **Jetpack Compose** | ❌ | 需要 Kotlin + Compose Compiler + Gradle，直接跟现行手工构建链冲突；我们连 AndroidX 都还没有 |
| **Material Components (MDC)** | ⚠️ | 需 AndroidX appcompat/material，以及一整条依赖链（core / fragment / lifecycle…）。要手工下载 AAR、拆出 classes.jar、逐个喂给 d8；**为一个几个卡片的工具 App 引入整套依赖，代价失衡** |
| **Glance（用 Compose 写插件）** | ❌ | 依赖 Compose，同上；且我们还得先有 theme XML |
| **手写 View + 自有 Design System（现状路线）** | ✅ | 界面元素极少：卡片 / 按钮 / 文本 / 开关 / 网格 / 列表，仅此而已 |

### 3.3 结论：**不引入框架**

三条理由：

1. **成本收益失衡**：为了一个 9 页面、元素极简的工具 App，引入 AndroidX + Compose 整条工具链；
2. **体积**：现在 311 KB，引入 AndroidX 后轻松破 MB——对一个"装了就是为了配对手环"的 App 不划算；
3. **最关键的一条**：**"好看"从来不是框架给的**。它来自四件事——**色板、间距、圆角、字号阶梯**。这四件我们完全可以自己定，而且目前 `Ui.java` 已经在做这件事（缺的只是"系统化"）。

> **真正缺的不是框架，是 Design Token。**

## 四、桌面小插件：做哪几种？

### 4.1 插件的硬约束（和主 App 完全不同）

- 必须用 **RemoteViews + XML 布局**——`Ui.java` 手写的那套在插件里**一个都用不了**
- 需要 `AppWidgetProvider` + manifest `<receiver>` + `res/xml/appwidget-info.xml`
- 不能用自定义 View，控件白名单有限
- ⚠️ 这意味着本项目要**第一次引入 XML 资源**
- 好消息：target 34，可以享用 Android 12+ 的圆角与系统圆角适配

### 4.2 建议做这 3 种（按优先级）

#### ★ ① 4×2「今日课程」（主推）

```
┌──────────────────────────────┐
│ 星期一 9月28日        更新于刚刚 │
├──────────────────────────────┤
│ ▌08:00  高等数学    A楼101    │
│ ▌10:00  线性代数    B楼205    │
│ ▌14:00  大学物理    物理楼102  │
└──────────────────────────────┘
```

- 竖条用该课程的**区分色**
- **当前/下一节高亮**（主色描边），**已结束的课程灰显**
- 为什么主推：信息密度与占地的最佳平衡，一眼看到今天要上什么

#### ★ ② 4×1「下一节课」（最小，最容易被放桌面）

```
  高等数学 · A楼101        10:00 开始（还有 25 分钟）
```

- 没课了显示"今天没课了"
- 占地极小，是**最有可能被长期留在桌面**的那一个

#### ③ 5×3「本周网格」（最有"课程表感"，但占地大）

```
     一    二    三    四    五
1   高数  英语  线代  物理  —
2   体育  —     数据结构 —   实验
```

- 学生最熟悉的形态（超级课程表 / WakeUp 都是这个）
- 但占半屏，**放到最后做**

### 4.3 明确不做

- 可编辑插件、课程详情页插件：交互复杂、RemoteViews 受限、收益低

### 4.4 落地顺序

**先做 ① + ②** —— 覆盖 90% 场景、占地小、共用同一份 `CourseCache` 数据和同一个 `ScheduleWidgetProvider`，**只换布局**。③ 留到后面。

### 4.5 插件做"好看"的关键

- 圆角 16dp；系统还会再套一层圆角 → **内层要留够 padding**，否则边缘被切
- **只用 2~3 种主色**：背景 / 卡片 / 强调。千万别塞彩虹
- 字号只留两档：标题 14sp、内容 12sp
- 信息层级不超过两级
- Android 12+ 可跟随系统强调色（可选）

## 五、主 App 界面：三条改进建议

### 建议 1：首屏改用「周视图网格」为主

刚加的是"今日课程列表"，建议升级成 **周视图网格**（今天列高亮），这是这个群体公认最好用的形态：

```
       一    二    三    四    五
  1   高数  英语  线代  物理  —
  2   体育  —     数据   —    实验
  ...
```
下方保留「今日课程」明细列表作为补充。

### 建议 2：每门课自动分配区分色

- 12 色调色板，**按课程名 hash 稳定分配**（同一门课永远同色，换个手机也一样）
- ⚠️ **这套 12 色必须手环和手机两端一致** —— 这是"看起来是一套产品"最关键的一处细节

### 建议 3：默认改浅色，深色留作夜间

现状深空蓝对 OLED 省电、夜间友好，但：

- 课程表是**白天在教室 / 户外高频扫一眼**的信息型界面
- 深色在强光下可读性明显弱于浅色
- 学生群体偏好明快清爽

**建议：默认浅色 + 跟随系统夜间模式自动切深色。**

## 六、配色推荐（针对课程表 / 学生群体）

### A. 「晴空蓝」Crisp Sky —— **推荐作为默认（浅色）**

| Token | 值 | 说明 |
|---|---|---|
| accent 主色 | `#2F6BFF` | 晴空蓝，有学生感但不幼稚 |
| 背景 | `#F4F7FB` | 带一点冷调的白，不刺眼 |
| 卡片 | `#FFFFFF` | |
| 边框 | `#E3EAF3` | |
| 主文字 | `#0F172A` | |
| 次要文字 | `#64748B` | |
| OK / WARN / ERR | `#16A34A` / `#F59E0B` / `#DC2626` | |

为什么：清爽、印刷感、深色文字在户外强光下最稳。

### B. 「夜幕蓝」Deep Space —— **保留为夜间 / 省电（现状色板）**

现有色板几乎不用改，只需把 `ACCENT` 从 `#4C8DFF` 提到 `#5B9BFF` 以提高对比度：

```
BG #0B1020 / CARD #151C30 / CARD2 #1C2542 / LINE #27314C
TEXT #E9EEF9 / MUTED #8695B4 / ACCENT #5B9BFF
```

### C. 「樱花粉」/「薄荷绿」—— 个性化补充款

主色 `#FF6B9D` 或 `#10B981`。适合作为"第 2、3 套主题"给喜欢打扮的学生，作为留存的小惊喜。

### ★ 12 色课程区分色（浅色 / 深色两套都要有）

```
#3B82F6 蓝   #EF4444 红   #10B981 绿   #F59E0B 橙
#8B5CF6 紫   #06B6D4 青   #EC4899 粉   #84CC16 黄绿
#F97316 深橙 #6366F1 靛   #14B8A6 蓝绿 #A855F7 品红
```

- 分配规则：`index = hash(课程名) % 12`（稳定，同一门课永远同色）
- ⚠️ 深色模式下用同一组但**降低饱和度 / 提亮**，保证两种模式都能区分

## 七、主题机制建议：做成什么样

既然手环已经有 10 套模板，手机端不建议各做各的，推荐：

### 7.1 方案：同一个「主题名」，两端各自实现

- 手环继续用它的 10 套模板（**不动**）
- 手机端建立 `ThemeStore`：**主题名 → 一套 token**
- **联动**：手机读到手环当前模板名 → 自动套用同名的手机端主题
  （⚠️ 前提：需确认 EV 的 `export` 是否返回模板名 —— 当前 APK 没读到这个字段）
- **反向**：手机端也能选主题 → 通过 `appearance` 写回手环（需 EV 支持）

### 7.2 落地方式：把 `Ui.java` 升级成「Token + Theme」

```
Theme: id / name / bg / cardBg / cardBg2 / line / textPrimary / textSecondary
       / accent / ok / warn / err / courseColors[12]

Ui.* 全部改为读 Theme.current() 的 token，而不是写死常量
```

关键好处：

- **加第 11 套主题 = 只改一份数据**
- 现有 9 个 Activity **几乎不用改** —— 它们已经全部走 `Ui.text` / `Ui.card` / `Ui.button`，改造集中在 `Ui.java` 内部

### 7.3 不建议做

- ❌ **自由取色自定义**：学生会调出灾难配色，还要处理对比度与无障碍；给几套精心调过的选择，比给一个调色盘更好
