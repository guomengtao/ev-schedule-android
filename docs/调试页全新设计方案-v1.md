## 0 一句话结论

调试页的核心不是「把 8 个按钮排好看」，而是**让每一步的状态自己说话，并把失败时的恢复动作送到出问题的那一步旁边**。
现在的状态表达只有「文字前缀 ✓/✕」、恢复动作却常驻在页面底部一个长文案按钮上 —— 用户看到失败后还得自己去找该怎么救。

## 1 现状诊断

先摆最硬的一条：**`grep -c "Ui\.SP_" DebugActivity.java` = 0**。
本页字号**全部裸写**，一个 token 都没用 —— 按前几页的经验，`SP_` 使用数为 0 的页面，设计语言已事实上崩塌。

| # | 现状 | 为什么是问题 |
|---|---|---|
| **H1** | 字号零 token 化；越界 3 处：`:49` `12f`、`:94` `11f`（EditText）、`:177` `13.5f` | 档位只有 22/17/15/16/13/11.5/10.5。13.5 与 11 都不在档内；且同一页出现 12 / 13.5 / 11.5 / 11 四种字号，层级是无序的 |
| **H2** | 8 个按钮平铺、**零分组标题**：全部执行/重置 \| EV是否安装/拉起EV \| 通知/清屏 \| 打开小米运动健康 \| 发送JSON \| 连接日志 | 三类语义（步骤控制 / 单项探测 / 工具）混在一起，用户只能靠文案猜。9 个入口无分组在设置页已被判定为架构病 |
| **H3** | **两个主按钮并列**：「全部执行」`Ui.button(...,true,...)` 与「发送自定义 JSON」`true` | 主按钮的意义是「本页唯一推荐动作」，两个就不成其为主 |
| **H4** | 破坏性动作露脸：「重置状态」「清屏」与常用动作**同色同大小并排** | 违反 P3。清屏会丢掉刚跑出来的日志，成本不可逆 |
| **H5** | `Ui.row`（`:57`）灰砖 | `CARD2 #EAF0F8` 与 `CANVAS #E9EAEF` 逐通道只差 (1,6,9)，卡片边界事实上消失，只剩 1dp 描边 |
| **H6** | 裸 `EditText`（`:92-96`）：无背景、无 padding、`11f` | 与页面背景融成一片，看不出是可编辑区；字号越界 |
| **H7** | 操作与反馈分离：6 组按钮在中上部，`logView` 钉在**页面最底部** | 点一步要滚到底才知道结果；页面一长就以为没反应 |
| **H8** | 步骤状态只靠 `mark = "✓ " / "✕ "` 文字前缀 + 颜色 | 前缀挤在标题里，扫视成本高；没有状态点/竖条这类可扫视的形状信号 |
| **H9** | **隐藏的恢复能力没说出来**：`openMiFitness()` 源码注释明写它是「步骤 2 超时的最常见根因」的恢复手段，却做成一个**常驻全宽长文案按钮** | 时机错了 —— 没失败时它是噪音，真失败了它又在页面另一头 |
| **H10** | 静态说明文字「按顺序点击任一步骤，逐步定位问题」（`:49`） | 步骤标题自带 1/2/3/4 编号，这句话是纯冗余；且它永远不变，占用了本可以显示实时状态的位置 |

## 2 设计原则（复用 P1–P6）

| | 原则 | 本页怎么用 |
|---|---|---|
| **P1** | 先展示，后操作 | 进页面先看到 4 步状态总览，操作按钮在下方 |
| **P2** | 一件事只说一处 | 状态只有一个真相：总览条给结论，步骤卡给明细，不再有第三处 |
| **P3** | 破坏性操作不露脸 | 重置 / 清屏降为 ghost 文字按钮 |
| **P4** | 互斥用单选语义 | 本页不适用（步骤是顺序关系，非互斥） |
| **P5** | 分层靠色彩与位置，不靠新字号 | 层级只用 4 档：17（顶栏）/ 13（正文标题按钮）/ 11.5（副文案）/ 10.5（日志表头） |
| **P6** | 零新增 token | 全部复用现有色值、字号档位、圆角、间距 |

## 3 信息架构 Before → After

| 区块 | Before | After |
|---|---|---|
| 顶部 | 静态说明文字（12f） | **状态总览条**：结论 + 进度 `n/4` |
| 步骤区 | 4 × `Ui.row` 灰砖，✓/✕ 文字前缀 | 4 × **白卡 + 左侧状态竖条 + 序号圆点**（1/2/3/4 → ✓/✕/运行中） |
| 步骤 2 失败 | 无提示；恢复动作在页面底部 | **就地琥珀建议条**（缩进对齐该步骤）+ 「去重连」按钮 |
| 步骤 3 失败 | 无提示 | **就地建议条** + 「去设置」按钮（跳系统授权页） |
| 操作 | 全部执行(主) / 重置状态 并排 | 全部执行(主) + 重置(ghost) |
| 探测 | EV是否安装 / 拉起手环EV / 手表通知 / 打开小米运动健康 混排 | 归入**「单项探测」**分组 |
| 报文 | 裸 EditText + 发送(主) | 等宽输入区（`CARD2`+描边+padding） + 发送(主) + **就地结果条** |
| 日志 | 页面最底部 mono + 独立的「清屏」按钮 | 归入**「日志」**分组，表头内置「清屏」小微标 |
| 分组 | 无 | **链路自检 / 单项探测 / 报文 · 日志** 三个 `.grp` 分组标题 |

### 决策表

| # | 决策 | 理由 |
|---|---|---|
| **D1** | 说明文字换成状态总览条 | 同一块位置，从「永远不变的指引」升级为「实时结论」，零成本换收益（H10） |
| **D2** | 步骤卡用「竖条 + 圆点」而非仅文字前缀 | 形状信号可扫视；圆点内 1/2/3/4 → ✓/✕ 的切换天然表达「这一步走到了哪」（H8） |
| **D3** | 恢复建议**只在失败时就地出现** | H9 的核心修复：时机 + 位置都对上。步骤 2 给「去重连」，步骤 3 给「去设置」，不同病因不同药 |
| **D4** | 保留「全部执行」为唯一主按钮 | 它是本页第一意图；「发送自定义 JSON」降为次级主按钮（仅报文区内的主）（H3） |
| **D5** | 重置 / 清屏降为 ghost | P3。清屏移到日志表头右侧，语义上属于日志区而非全局操作（H4） |
| **D6** | JSON 输入区用 `CARD2` + 描边 + padding，字号 11.5 | 修复 H6，且 11.5 是既有档位（`SP_CAPTION`），零新增 |
| **D7** | 日志保留在底部，但**加了就地结果条**在报文区 | H7 不靠「把日志搬上来」解决（日志是累积流，放底部合理），靠**关键结果就地反馈**解决 |
| **D8** | 「连接手环日志」归入日志分组，作为入口行 | 它是跳转而非动作，与「清屏」区分开 |

## 4 组件规格

### 4.1 状态总览条

| 项 | 值 |
|---|---|
| 容器 | 白卡 `CARD` + `LINE` 描边，`R_CARD 14`，padding `12/14` |
| 状态点 | 8dp 圆点：待执行 `MUTED` / 通过 `OK` / 执行中 `ACCENT` / 失败 `ERR` |
| 结论文案 | `SP_BODY 13`，**600** 字重 |
| 副文案 | `SP_MICRO 10.5`，`MUTED`，换行跟在结论下 |
| 进度 | `SP_CAPTION 11.5`，`MUTED`，右对齐（`n / 4`） |
| 行为 | 跟随 `states[]`：全 OK → ok；任一 FAIL → bad 且写明停在第几步；有 RUNNING → run |

### 4.2 步骤卡

| 项 | 值 |
|---|---|
| 容器 | 横向 `LinearLayout`，白卡 `R_CTRL 12`，`min-height 44`（= `TOUCH_MIN`） |
| 左侧竖条 | 宽 **3dp**，色随状态：`LINE` / `OK` / `ACCENT` / `ERR` |
| 序号圆点 | 26dp 圆；底 `CARD2`，字 `SP_CAPTION 11.5` 600；OK 时底 `OK_LIGHT` 字 `OK` 内容 `✓`；FAIL 时 `✕`；RUNNING 时 `ACCENT_LIGHT` 底保留数字 |
| 标题 | `SP_BODY 13` 600，色随状态（待执行 `TEXT`，OK `OK`，FAIL `ERR`，RUNNING `ACCENT`） |
| 副文案 | `SP_CAPTION 11.5`，`MUTED`，行高 1.4 |
| 右箭头 | 15dp chevron，`MUTED`，占位 34dp（保证右侧热区） |
| 内边距 | 文字区 `padding 11 12 11 0`（左侧由圆点列承担） |
| 热区 | 整卡可点 = `runStep(i)`；视觉可窄，**热区不缩于 44dp** |

**副文案的内容规则（本页新增，重要）**：
- 待执行：静态说明（如「检测小米穿戴服务是否可用 · 待执行」）
- 成功：**显示真实返回值**（`nodeId = 3f9a…c21`、`pong · 往返 84ms`）—— 跑完就该给结果，原实现沿用静态说明是浪费
- 失败：失败原因 + 该做什么（`未拿到 nodeId · 手环未连接`）
- 跳过：`前一步未完成，已跳过`

### 4.3 就地恢复建议条

| 项 | 值 |
|---|---|
| 时机 | **仅当该步骤 FAIL 时**出现在步骤卡下方 |
| 缩进 | `margin-left 47dp`（对齐步骤卡文字左缘，视觉上属于该步骤） |
| 底 | `WARN_LIGHT`，圆角 `R_CTRL 12`，padding `10/12` |
| 文案 | `SP_CAPTION 11.5`；病因关键词用 `WARN` 色加粗 |
| 按钮 | 高 32dp（**热区外层补到 44dp**），`WARN` 实底，白字，`SP_CAPTION 11.5` 600 |
| 步骤 2 | 文案：「小米运动健康与手环的 BLE 连接久了会自己断开 —— **把它拉到前台即可重连**」/ 按钮「去重连」→ `openMiFitness()` |
| 步骤 3 | 文案：「这一步要系统授权，App 内点不出来 —— **去系统设置放行通知权限**」/ 按钮「去设置」→ 跳系统授权页 |

### 4.4 按钮层级

| 层级 | 用于 | 规格 |
|---|---|---|
| 主按钮（唯一） | 全部执行 | `ACCENT` 实底、`ON_ACCENT` 字、`R_CTRL 12`、高 44dp、`SP_BODY 13` 600 |
| 次级按钮 | EV 是否安装 / 拉起手环 EV / 手表通知 | `CARD` 底 + `LINE` 描边 + `TEXT` 字 |
| 区内主按钮 | 发送（报文区内） | `ACCENT` 实底，但**不参与全页主次竞争** |
| ghost | 重置 / 清屏 | 透明底、无描边、`MUTED` 字、400 字重、宽度自适应 |

### 4.5 JSON 输入区

| 项 | 值 |
|---|---|
| 容器 | `CARD2` 底 + `LINE` 描边，`R_CTRL 12`，padding `10/12` |
| 表头 | `自定义 JSON`，`SP_MICRO 10.5` 600，`MUTED` |
| 内容 | 等宽字体，`SP_CAPTION 11.5`，`TEXT`，行高 1.5 |
| 落地 | `inputView.setBackground(Ui.round(Ui.CARD2, Ui.R_CTRL, Ui.LINE, this))` + padding + `setTextSize(Ui.SP_CAPTION)` |

### 4.6 就地结果条（4 级）

| 级 | 触发 | 底 / 字 |
|---|---|---|
| 进行 | `sendRaw()` 发出后等回包 | `ACCENT_LIGHT` / `ACCENT` |
| 成功 | `onReply` | `OK_LIGHT` / `OK`，文案 `<< RX len=42 · {…}` |
| 警告 | `onTimeout` | `WARN_LIGHT` / `WARN` |
| 错误 | `onError` | 红淡底 / `ERR` |

> 原始回包**只在这里给摘要**，完整内容仍进日志区。

### 4.7 日志区

| 项 | 值 |
|---|---|
| 容器 | `CARD2` 底 + `LINE` 描边，`R_CTRL 12`，高 ~104dp，可滚动 |
| 表头 | `运行日志`（`SP_MICRO 10.5` 600 `MUTED`）+ 右侧 `清屏`（同字号 400） |
| 正文 | 等宽 `SP_MICRO 10.5`，`MUTED`；`[OK]` 绿、`[FAIL]` 红、时间戳 `ACCENT` |
| 空态 | 图标 + 「还没有输出 · 执行任一步骤后在此查看」，居中 |

### 4.8 分组标题

沿用设置页 `.grp`：`SP_CAPTION 11.5` 600，`MUTED`，`letter-spacing .3`，`margin 16/16 7`。
三个分组：**链路自检 / 单项探测 / 报文 · 日志**。

## 6 落地清单（3 批，每批独立可验收）

### 批次 1 · 结构减法（风险最低，先做）

1. 删掉 `:49` 静态说明文字，换成 `sumBar`（总览条）。
2. 8 个按钮按 D1–D8 归入 3 个分组，各加 `grpTitle()` 分组标题。
3. 「重置状态」「清屏」改为 ghost（清屏移入日志表头）。
4. 删掉常驻的「打开小米运动健康」全宽按钮（:88-90）—— 改为失败时就地出现。
5. **字号归位**：`12f → Ui.SP_CAPTION`、`13.5f → Ui.SP_BODY`、`11f → Ui.SP_CAPTION`。

> 验收：本批做完，页面结构已成型，即使后两批不做也比现状好。

### 批次 2 · 核心（状态表达 + 就地恢复）

6. `Ui.row` → 自建 `stepCard(i)`：左侧 3dp 竖条 + 26dp 圆点 + 双行文字。
   - 竖条用 `GradientDrawable.setCornerRadii({r,r,0,0,0,0,r,r})`（左上/右上/右下/左下）。
7. `setState()` 改为更新 `stepCard` 的竖条色、圆点内容、标题色、副文案（**副文案按 §4.2 的内容规则走**）。
8. 新增 `fixHint(i)`：步骤 FAIL 时在该卡下方插入建议条（步骤 2 → `openMiFitness()`；步骤 3 → 跳系统授权页）。
   - ⚠️ **状态标志别被刷新清零**：建议条的显隐由 `states[i]` 驱动，不要在 `refreshXxx()` 开头清标记。
9. JSON 输入区加背景 + padding + `SP_CAPTION`。
10. 报文区加 4 级结果条。

### 批次 3 · 边界打磨

11. 日志区分色（`[OK]`/`[FAIL]`/时间戳）+ 空态插画。
12. 深色主题逐项核对 `--d-*` 映射。
13. `setFocusableInTouchMode` 逻辑保留（避免进页面弹键盘）。

## 7 风险与取舍

| # | 风险 | 退路 |
|---|---|---|
| **R1** | **步骤 3 的「去设置」跳转目标未确认**：`NOTIFY` 权限是系统通知权限，跳转 Intent 需实测（不同 MIUI/HyperOS 版本可能落到不同页） | 退路：按钮降级为**纯文案指引**（「去系统设置 → 通知管理 → 放行本 App」），不做跳转。先做步骤 2 的「去重连」（已有 `openMiFitness()` 实现，零风险），步骤 3 留文案 |
| **R2** | **建议条会让列表高度变化**，连续执行 4 步时可能出现跳动 | 退路：建议条只在**全部执行结束后**插入一次，而非每步失败即插 |
| **R3** | **副文案显示真实返回值**（nodeId / pong 耗时）依赖 `SyncEngine` 回传的 `msg`，若 `msg` 是长文本会撑破卡片 | 退路：副文案 `maxLines=2` + `ellipsize`，超长部分仍完整进日志 |
| **R4** | 本页是**开发者/排查入口**，过度打磨可能不值当 | 取舍：批次 1 + 2 是收益主体（结构 + 状态 + 就地恢复）；批次 3（空态插画、日志分色）可延后 |
| **R5** | `DebugActivity` 内含 **Countdown 单元测试**（`:255-342`，通过 `--es test countdown_all` 触发） | 保持不动，仅确保日志区仍能承载其输出；不把它纳入 UI 分组 |
| **R6** | `exported=true` 使本页可被外部 `am start` 调起 | 这是既有行为，本方案**不改 manifest**（改它会改变源码行为并引入安全面）。对验证反而是好事：可直接 `adb shell am start` |

## 8 验收标准

> `DebugActivity` 在 manifest 中 **`exported=true`**，无需绕真实入口，可直接 `am start` 验证。

| # | 断言 | 判定方法 |
|---|---|---|
| **A1** | 静态说明文字「按顺序点击任一步骤」消失，总览条出现 | `uiautomator dump` 后 grep：前者 `text=` 命中 0；存在 `text` 含「尚未执行」或「4 / 4」的节点 |
| **A2** | 出现 3 个分组标题 | dump 命中 `text="链路自检"`、`text="单项探测"`、`text="报文 · 日志"` 各 ≥1 |
| **A3** | 全页 `Ui.SP_` 使用数 ≥ 8，且**无越界字号** | `grep -c "Ui\.SP_" DebugActivity.java` ≥ 8；`grep -n "setTextSize(" ` 与 `Ui.text(..., <n>f` 中不含 13.5 / 12 / 11 |
| **A4** | 「重置」不是主按钮 | dump 中重置节点不可点击为主按钮样式；**更硬的判据**：代码中 `Ui.button(this,"重置",false,...)` → 改为 ghost 后不再走 `Ui.button`，直接断言 `grep -c "重置状态" ` = 0 |
| **A5** | 「打开小米运动健康」**不再常驻**；步骤 2 失败时才出现 | 初始 dump 命中 0；令步骤 2 失败（断开手环）后再 dump，命中「去重连」 ≥1 |
| **A6** | 步骤 4 步卡具备状态竖条 | 像素扫描：每个步骤卡左缘 3px 列存在非背景色像素（成功帧为绿、失败帧为红） |
| **A7** | JSON 输入区有可见边界 | 像素扫描：输入区上下边缘存在 `LINE` 色像素行，且内部与页面背景色不同 |
| **A8** | 深色主题下四态互不混淆 | 深色截图取色：OK / RUNNING / FAIL 三态竖条色两两不同，且与 `MUTED` 不同 |
