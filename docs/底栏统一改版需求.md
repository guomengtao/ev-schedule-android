# 底部导航统一改版 + 顶栏居中标题 —— 需求整理

> 2026-09-28 · 状态：**需求确认中（未实施）**  
> 关联：`docs/首页美化方案.md`（上一轮，底栏「选中纯色无背景」的规则将被本需求**推翻**）

## 一、需求原文（用户，2026-09-28）

> 设置页底部菜单第三个位置加入一个「导入」新按钮，连接我们已有的导入页面。底部一共四个了，选中后按钮填充为实心的，不仅仅是线框变了颜色。首页的底部也换成设置页那种底部菜单，原来的去掉。底部菜单就统一都是 4 个了，一样。底部四个菜单（页面）顶部都加入一行表头，标题居中显示，颜色配合风格显示。其他页面也是一样，标题也居中，但是多了一个返回按钮。

## 二、需求解读（逐条）

### R1 · 底栏统一为 4 个 tab

| 位置 | Tab | 页面 | 说明 |
|---|---|---|---|
| 1 | 首页 | `HomeActivity` | 现有 |
| 2 | 课程表 | `ScheduleListActivity` | 现有 |
| 3 | **导入**（新增） | `TransferActivity`（mode=import） | 连接已有导入页；原第三位「设置」顺移到第 4 |
| 4 | 设置 | `SettingsActivity` | 现有 |

- 首页现在用的**胶囊底栏（pillBar：课表/周视图/消息/设置）整体弃用**，与设置页的普通底栏合并为**唯一一套** 4-tab 底栏（`Ui.bottomBar` 改造）。
- EvBox 变体的 legacy 首页（`buildLegacyUi`）同样跟随新底栏。

### R2 · 选中态 = 实心填充

- 选中 tab：**实心填充**（主色 ACCENT 圆角块背景 + 白色图标/文字），不再是「仅变色」。
- 未选中 tab：线框色（MUTED 图标/文字），无背景。
- ⚠️ 此条**推翻** `docs/首页美化方案.md` 中「选中永不加背景」的约定——以本需求为准，并在首页美化方案文档中同步更正。

### R3 · tab 页顶部加居中表头

- 4 个 tab 页顶部各加一行**表头标题，水平居中**，颜色随主题 token（TEXT），如「首页」「课程表」「导入」「设置」。
- 原 `Ui.title()` 裸标题被替代；首页的「本周课表」大标题行、周切换器等**保留在表头之下**（表头是页面级导航条，不替代页内内容标题）。

### R4 · 子页标题居中 + 返回按钮

- 所有非 tab 子页（导入/导出、留言、调试、JSON 编辑器、高级版、主题外观、打赏支持、省电白名单、首页设置）：
  - 标题**居中**（原为左对齐）；
  - **返回按钮（chevron-left）固定在左侧**，与标题同行；
  - 布局建议：FrameLayout/三段式——返回键绝对居左，标题绝对居中，右侧对称占位保证视觉居中。

## 五、v2 方案（2026-09-28 用户演进）：第三位 tab 改为「设备」，设置按作用域拆两层

> 用户原话：导入改掉，改为「设备」，提供手环设备的管理设置。头部提供设备连接（可能多手环设备），设备里的设置——比如设置昵称、首页设置等是设备仅有的。原来设置里面移动过来，原来的设置作为 App 级设置（后台常驻、检查更新、打赏）。

### 5.1 本质：按「作用域」拆分设置，而不是按「功能罗列」

现有设置页混着两类东西：**跟着手环走**的（写了会同步到手环）和**跟着手机安装走**的（App 自身行为）。v2 把它们拆开：

```
底栏：首页 / 课程表 / 手环(设备) / 设置
  ├─ 手环 tab = 设备作用域：连接管理 + 写到手环才生效的配置
  └─ 设置 tab = App 作用域：本机行为、商业化、版本
```

### 5.2 设置项归属盘点（现有 SettingsActivity 全项）

| 现有项 | 归属 | 理由 |
|---|---|---|
| 当前昵称 + 修改昵称 | **设备页** | `setNickname` 写回手环，设备仅有的属性 |
| 首页设置（模板/字号） | **设备页** | `update_settings` 写回手环生效，文档原话「模板写回手环后生效」 |
| 手环设备（重新选择设备） | **设备页** | 本来就是设备管理，v2 的核心内容 |
| 连接状态/设备名 | **设备页头部** | 设备连接管理（多手环：preferredNodeId 已有地基） |
| 后台常驻提醒 + 省电白名单 | App 设置 | 开关的是本机前台服务，属 App 行为 |
| 上课提醒（闹钟体系） | App 设置 | 基于本地课表+系统闹钟，不依赖手环（推手环只是可选附加） |
| 主题外观 | App 设置 | 本地 10 套主题离线可用；「跟随手环」是页内一个开关，不影响归属 |
| 高级版（激活码） | App 设置 | 激活绑定 App，非某台手环 |
| 检查更新 | App 设置 | 纯 App |
| 打赏支持 | App 设置 | 纯 App |
| 本机版本 | App 设置 | 纯 App |

### 5.3 设备页内容结构（草案）

```
┌ 设备头部（连接管理）──────────┐
│ [手环图] 小米手环 8   ●已连接  │
│ 多手环时：设备列表/切换/管理    │
│ 未连接时：连接引导 + 重连按钮  │
├ 设备配置 ────────────────────┤
│ 昵称（当前值 → 点击修改，写手环）│
│ 首页设置（模板/字号，写手环）    │
├ 快捷操作 ────────────────────┤
│ 同步课表 / 手环在不 / 补发待发送│
└──────────────────────────────┘
```

### 5.4 评估结论

**优点（比「导入」tab 好）**：
1. **频率匹配**：连接状态查看/设备切换是中高频操作（连接出问题第一反应是「看看设备页」）；导入是一锤子低频操作，埋两层深都行。
2. **心智正确**：用户问「我的昵称/首页模板在哪改」→ 答「手环页」；问「后台被杀/更新」→ 答「设置页」。现在的单页混杂正是「乱」的来源之一。
3. **多手环地基**：`preferredNodeId`（多设备询问/记忆）已有，设备页是它的天然归宿，为未来多手环管理铺路。
4. **原 Q1-Q5 大幅简化**：导入不再是 tab（进课程表页或设备页快捷区），消息/周视图问题随 pillBar 废弃一并消解。

**挑战/风险**：
1. **SettingsActivity 拆页工作量**：两页布局 + 跳转关系 + EvBox 变体适配（EvBox 无「高级版」），约半天。
2. **未连接空态**：设备页大部分功能依赖连接，必须设计「未连接空态」（连接引导 + 哪些仍可用），否则用户在手环不在身边时打开是一片死按钮。
3. **双写风险**：昵称/首页设置迁移后，旧入口要移除而不是保留（避免两处改同一配置）。
4. **命名**：建议 tab 名用「**手环**」而非「设备」——用户语言里这台设备就是手环；「设备」偏工程词。（用户定夺）
5. **上课提醒归属**：建议 App 级（闹钟不依赖手环），但「推送到手环」开关在提醒卡片里，迁移时保持整卡不动即可。
