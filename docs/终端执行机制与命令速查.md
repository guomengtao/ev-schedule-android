# AI 是怎么执行终端命令的 —— 机制说明 + 本项目命令速查

> 2026-09-29 · 回答「你怎么执行的？为什么我在 VSCode 终端看不到？我也能用吗？」

---

## 一、执行机制：不是 VSCode 终端，是「无界面的子进程」

```
你（对话） → CodeBuddy 客户端（IDE 插件）
                ↓ 调用 execute_command 工具
          宿主机直接 spawn 一个 bash 子进程（bash -c "命令"）
                ↓ 捕获 stdout / stderr / 退出码
          结果回传给 AI → AI 决定下一步
```

关键事实：

| 特性 | 说明 | 你观察到的现象 |
|---|---|---|
| **不走 VSCode 终端（pty）** | 命令由插件后端直接 `spawn` 子进程执行，不经过终端模拟器 | 所以你在 VSCode 终端里看不到任何敲命令的痕迹 |
| **每条命令独立 shell** | 上一条 `cd`/`export` 不会留到下一条 | 所以我的命令总是写成一条长链：`cd xxx && A && B`，或单条内 `export PATH=...` |
| **无 TTY** | 没有 pager/交互式渲染 | 命令输出是纯文本流，`git log` 不会卡在分页器 |
| **输出回传 AI 而不是回显终端** | stdout/stderr 作为文本返回 | 稳定 = 输出可解析、可 grep、可判断成败 |
| **需要你批准** | 涉及安装/删除/推送的操作会弹确认 | 你点过不少「允许」就是它 |

**为什么显得稳定**：因为「执行 → 看输出 → 修正 → 再执行」这个闭环每一步都有机器可读的结果，AI 不会像人一样漏看报错。反过来它也有短板：

1. **交互式命令会卡死**（等你输入）：例如 `gh auth refresh` 要去浏览器输码——我的解法是丢后台 + 读日志拿配对码给你；
2. **无状态**：激活的虚拟环境、cd 的目录、alias 全都不留；
3. **管道会吞错误**：`cmd | tail -1` 会把退出码变成 tail 的 0 —— 我踩过（push 失败被吞），关键操作必须事后复核（`git rev-list --count origin/main..main`）。

**你完全可以自己做**：这些就是普通 shell 命令，没有任何魔法。下面是本项目全部高频命令速查。

## 二、命令速查表（本项目专用，直接复制可用）

### 1. 构建 + 发版三件套（手机 APK）

```bash
# 构建（版本号自动 +1，产物 apk/dist/EVSyncProbe-vX.Y.Z.apk + update-ev.json）
cd ~/Documents/guomengtao/ev-schedule-android/apk
ANDROID_SDK_ROOT=$HOME/android-sdk \
  UPDATE_LOG="本次更新说明（弹窗正文）" \
  bash build.sh

# 传 APK 到 GitHub Release
gh release create v0.5.46 dist/EVSyncProbe-v0.5.46.apk \
  --repo guomengtao/ev-schedule-android --title "v0.5.46" --notes "..."

# 更新线上升级 JSON（用 GitHub API，绕开 ssh 抖动/本地落后）
cd ~/Documents/guomengtao/ev-schedule-android
SHA=$(gh api repos/guomengtao/app-auth/contents/ev/update-ev.json --jq '.sha')
B64=$(base64 < apk/dist/update-ev.json | tr -d '\n')
gh api -X PUT repos/guomengtao/app-auth/contents/ev/update-ev.json \
  -f message="chore(ev): 发版 vX.Y.Z" -f content="$B64" -f sha="$SHA" --jq '.commit.sha[0:7]'

# 验证线上生效
curl -s https://app-auth.gudq.com/ev/update-ev.json | python3 -m json.tool
```

### 2. adb 真机（荣耀 BLN-AL20，序列号 BTF4C17222009588）

```bash
export PATH="$HOME/android-sdk/platform-tools:$PATH"; S=BTF4C17222009588; P=com.application.watch.classschedule

adb -s $S install -r -g dist/EVSyncProbe-v0.5.46.apk     # 覆盖安装+自动授权
adb -s $S shell am start -W -n $P/.HomeActivity          # 冷启动（TotalTime=启动耗时）
adb -s $S exec-out screencap -p > ~/Desktop/shot.png     # 截图（直接重定向，不要管道清洗）
adb -s $S logcat -d -s EVUpdate                          # 只看升级日志（华为砍了系统日志，App 自打日志是唯一观测）
adb -s $S shell dumpsys package $P | grep versionName    # 验证安装版本
adb -s $S shell uiautomator dump /sdcard/t.xml           # UI 树 → 自动点按定位
adb -s $S shell cat /sdcard/t.xml | python3 /tmp/taptext.py "按钮文字"   # → 中心坐标
adb -s $S shell input tap X Y                            # 模拟点击
```

### 4. 并行会话共存：不碰别人工作区的提交法

```bash
# 场景：另一个 AI 会话在本地有未提交 WIP，git pull --rebase 被阻。
# 解法：worktree 检出远端 main → 只放自己的文件 → 提交推送，本地工作区零接触
cd 仓库目录 && git fetch origin
git worktree add /tmp/wt origin/main
cp 我的文件 /tmp/wt/路径/
cd /tmp/wt && git add ... && git commit -m "..." && git push origin HEAD:main
cd 仓库目录 && git worktree remove --force /tmp/wt
# 事后本地同步：git pull --rebase（等并行会话提交完再做）
```

### 5. GitHub API 直改文件（ssh 22 抖动时的保底）

```bash
SHA=$(gh api repos/OWNER/REPO/contents/路径 --jq '.sha')     # 当前文件 sha
B64=$(base64 < 本地文件 | tr -d '\n')
gh api -X PUT repos/OWNER/REPO/contents/路径 -f message="..." \
  -f content="$B64" -f sha="$SHA" --jq '.commit.sha[0:7]'
# ⚠️ 若被并行会话的 push 挤掉：本地的 worktree push 会 non-ff 失败且报错可能被
#    `| tail -1` 吞掉——关键 push 后必须 git rev-list --count origin/main..main 复核
```

### 6. 真机 UI 自动化点按（两步式，坐标从 dump 现取）

```bash
# /tmp/taptext.py：从 uiautomator XML 解析「包含指定文字的节点」中心坐标
adb -s $S shell uiautomator dump /sdcard/t.xml
adb -s $S shell cat /sdcard/t.xml > /tmp/t.xml
XY=$(python3 /tmp/taptext.py /tmp/t.xml "按钮文字" | head -1)
adb -s $S shell input tap $XY
# ⚠️ 列表页滚动后坐标会变——每次点击前都重新 dump，不要复用旧坐标
```
