> **定位**：本文是项目默认使用的命令手册。所有命令经过多轮实机验证稳定可靠，不确定时请回看本文，**禁止随意更换命令写法**。

## 第一部分：AI 终端执行机制

### 一、怎么执行的？

AI（CodeBuddy / Trae IDE）在你 Mac 上执行命令的机制：

```
CodeBuddy 客户端  →  插件后端  →  spawn bash 子进程
                    (无界面)      ↓
                              捕获 stdout / stderr / 退出码
                                    ↓
                              回传给 AI 解析
```

**关键**：这不是在 VSCode 的集成终端里打字。插件后端直接用 `spawn`（或等效 API）fork 一个独立 bash 子进程，不经过任何终端模拟器（pty）。

### 二、为什么 VSCode 终端看不到？

因为它**根本不经过 VSCode 的终端模拟器**（pty）。

整个链路是：
- 插件后端进程 → `spawn("bash", ["-c", "你的命令"])` → 直接捕获输出
- 你的 VSCode 终端窗口看到的只是一个空白 shell，完全不知道旁边发生了什么事

你看到的现象是：对话框里出现命令 → 弹出批准按钮 → 结果回显在对话里。终端里没有任何滚动痕迹。

### 三、为什么这个机制是稳定的？

稳定性来自于**闭环反馈**：

1. **每条命令的输出是机器可读文本**（stdout + stderr + 退出码）
2. AI 能读到完整的报错信息，立即判断成败并修正
3. 没有人为操作引入的不确定性（打字错误、选错窗口等）
4. 执行环境 = 你的真实 Mac（同样的 shell、同样的 PATH、同样的文件系统）

**这就是为什么本文作为默认方式——因为它可复现、可验证、可纠错。**

### 四、三个你必须知道的短板

#### 短板 1：无状态（每条命令是独立 shell）

```
# ❌ 这个不行：
cd /some/path
ls                 # 还在原来的目录！

# ✅ 必须写成一条长链：
cd /some/path && ls
```

**原因**：每条命令 spawn 一个新的 bash 子进程，执行完就销毁。`cd`、`export`、`source` 这类修改 shell 状态的命令不会延续到下一条。

**对策**：所有需要共享状态的命令用 `&&` 或 `;` 连成一条。

#### 短板 2：交互式命令会卡死

需要用户输入的命令（如 `gh auth login`、`passwd`、`npm init` 的问答）会**永久挂起**，因为没有终端可以交互。

**对策**：
- 找非交互式替代方案（如 `gh auth token` 用环境变量）
- 丢后台运行 + 读日志文件取输出（如 `gh auth refresh` 那次的做法）
- 优先使用接受参数/环境变量的 CLI

#### 短板 3：管道会吞掉退出码

```bash
# ❌ push 失败不会被发现！
git push origin main 2>&1 | tail -1

# ✅ 关键操作后必须复核：
git push origin main && git rev-list --count origin/main..main
```

**原因**：管道的退出码是**最后一个命令**的退出码。`tail -1` 几乎总是成功（退出码 0），前面的 `git push` 失败被掩盖了。

**对策**：关键 push/部署后，**必须**用独立命令复核结果（如 `git rev-list origin/main..main` 检查有多少个本地提交还没上远端）。

#### 3. 更新线上升级 JSON（app-auth 仓库）

> **⚠️ 重要**：app-auth 的 JSON 更新**必须用 `gh api PUT`**，不能用 git push（并行会话 + SSH 抖动会导致推送被覆盖丢失）。

```bash
cd /Users/Banner/Documents/guomengtao/ev-schedule-android/apk/dist

# 获取 GitHub 上当前文件的 sha
SHA=$(gh api repos/guomengtao/app-auth/contents/ev/update-ev.json --jq '.sha')

# 上传（base64 编码 + sha 防止并发覆盖）
gh api -X PUT repos/guomengtao/app-auth/contents/ev/update-ev.json \
  -f message="release: EVSyncProbe $(grep VERSION_NAME ../version.env | cut -d= -f2)" \
  -f content="$(base64 -i update-ev.json)" \
  -f sha="$SHA"
```

> **为什么不用 git**：app-auth 是多会话共享仓库，并行 push 极易失败。`gh api PUT` 带 sha 版本号，直接操作 GitHub 文件，彻底绕开本地 ref 落后和 SSH 抖动问题。详见 MEMORY.md 2026-09-28 记录。

### 三、UI 自动化（taptext.py + uiautomator）

```bash
# 获取屏幕分辨率（计算点击坐标用）
W=$($ADB -s $S shell wm size | awk -F'[:x ]' '{print $3}')
H=$($ADB -s $S shell wm size | awk -F'[:x ]' '{print $4}')

# dump UI 树 → 用于定位元素坐标

# taptext.py：从 uiautomator XML 解析包含指定文字的节点坐标，自动点击
# 用法：先 dump UI 树，然后 python3 /tmp/taptext.py <文字>
$ADB -s $S shell uiautomator dump /sdcard/t.xml && \
  $ADB -s $S pull /sdcard/t.xml /tmp/t.xml && \
  COORDS=$(python3 /tmp/taptext.py "手环课程同步" /tmp/t.xml) && \
  $ADB -s $S shell input tap $COORDS

# ---- 直接注入点击/滑动/文字 ----

# 点屏幕中心
$ADB -s $S shell input tap $((W/2)) $((H/2))

# 点底栏区域（约 70% 高度）
$ADB -s $S shell input tap $((W/2)) $((H*7/10))

# 输入文字（%s = 空格）
$ADB -s $S shell input text 'hello%swatch'

# 返回键
$ADB -s $S shell input keyevent KEYCODE_BACK

# 上滑（300ms）
$ADB -s $S shell input swipe 500 1500 500 600 300

# ⚠️ 注意：硬编码坐标在布局改动后会失效。优先用 taptext.py 文字定位。
```

### 五、git worktree：并行会话共存提交法

> **场景**：同一仓库有多个 AI 会话同时工作，各干各的不互相覆盖。

```bash
# 创建独立工作树（在 .git 旁边，互不干扰）
cd /Users/Banner/Documents/guomengtao/ev-schedule-android
git worktree add ../ev-android-wip main

# 在新工作树里干活
cd ../ev-android-wip
# ... 改代码、构建、测试 ...

# 提交并推送
git add <自己的文件路径>           # ⚠️ 只 add 自己的！不要 -A
git commit -m "feat: xxx"
git push origin main

# 用完后清理
git worktree remove ../ev-android-wip

# 查看所有工作树
git worktree list
```

> **⚠️ 多会话共享仓库的禁忌**：
> - **禁止 `git stash` / `git stash pop`**——会误弹别人的旧 stash 到你的工作区
> - **禁止 `git add -A`**——会带上别人的 WIP 文件
> - 用 `git status --short` 先看清哪些文件是别人未提交的
> - 只 `git add` 你自己的路径

### 九、日常提交自检清单

```bash
# 1. 看当前改了哪些文件
git status --short

# 2. 检查是否有密钥泄漏
git diff --cached --name-only | grep -Ei "\.(jks|keystore|pk8|p12)$|private\.pem|certificate\.pem" && echo "❌ 有密钥！" || echo "✅ 无密钥"

# 3. 版本号（patch 位）是否需要手动 +1
grep VERSION_NAME apk/version.env
# 如果只改了文档没构建，手动 +1

# 4. 提交（只 add 自己的文件）
git add <路径1> <路径2> ...
git commit -m "feat: 摘要" -m "正文（可选）"

# 5. 推送 + 复核
git push origin main && git rev-list --count origin/main..main
```

## 第三部分：踩坑记录（速查索引）

| 坑 | 现象 | 解法 | 详见 |
|---|---|---|---|
| JDK 22 的 class 让 R8 崩 | d8 NPE `String.length()` null | javac 必须用 JDK8 | build.sh / MEMORY.md |
| SDK class 没打进 dex | 启动即 NoClassDefFoundError | d8 输入必须包含 SDK class | build.sh |
| 签名不一致 | SignatureVerifyFailedException | APK 用 rpk 同一把密钥签 | build.sh |
| 空 DN 证书 | apksigner 拒签 | BouncyCastle 包装 | BCSign.java |
| Binder 线程碰 UI | 回包死在打日志 | runOnUiThread | SYNC-RX 实现 |
| 没注册监听 | 发消息 0 回包 | 必须先 addListener 再 sendMessage | SyncEngine |
| 手环 USB 插着 | 步骤 2 超时不回调 | 拔 USB 线 / 打开小米运动健康 | DebugActivity |
| 管道吞错误 | push 失败误报成功 | 关键命令后独立复核 | 本文 §一.四.3 |
| git stash pop | 别人的 stash 弹进工作区 | 严禁在共享仓库用 stash | MEMORY.md |
| NODE_OPTIONS | rpk 构建中止 | 构建前清空 NODE_OPTIONS | 本文 §二.四 |
| adb 装错设备 | 装到手环 emulator-5554 | 必须带 `-s BTF4C17222009588` | MEMORY.md |
