# 最近访客通知 + 消息投递追踪 方案

> 目标：把 APK 后台的访问记录统一汇总为「最近访客」通知栏，支持语音播报；并补齐消息投递状态追踪，排查丢通知问题。
> 日期：2026-09-28
> 仓库：app-auth（网站后台） + ev-schedule-android（APK）

---

## 一、现状分析

### 1.1 APK 上报 —— 已就绪

`Analytics.java` 已实现页面访问埋点，每次进入页面自动上报：

```
POST https://app-auth.gudq.com/api/activate?section=visitor-track
body: { "path": "/apk/home", "query": "from=apk&v=0.5.36&connected=1&variant=ev" }
```

后台接收后写入 `visitor_logs` 表（路径、IP、时间、UA、城市）和 `tracking_events`（统一事件流）。

### 1.2 后台已有什么

| 数据表 | 用途 | 现状 |
|---|---|---|
| `visitor_logs` | 永久访客记录（path/ip/time/ua/geo） | ✅ 已有 |
| `tracking_events` | 统一事件流（kind=visit/activation/...） | ✅ 已有 |
| Redis `recent_visitors` | 最近 ~100 条访客缓存 | ✅ 已有 |
| `visitorHash → nickname` 映射 | 暂无 | ❌ 需要新增 |

### 1.3 当前问题

1. **访客记录分散**：`visitor_logs` 表里有 APK 访问记录，但没有聚合展示为「最近访客」通知
2. **没有语音播报**：管理员在后台看板时，新访客到来没有实时语音提醒
3. **消息投递状态缺失**：Redis pub/sub 推送消息给客户端后，无法追踪是否真正送达，丢通知问题无法定位

## 三、功能一：最近访客通知

### 3.1 数据模型

在现有 `visitor_logs` 基础上，新增访客通知记录：

```sql
-- 访客通知表（新增）
CREATE TABLE visitor_notifications (
  id          SERIAL PRIMARY KEY,
  visitor_hash TEXT NOT NULL,          -- 访客去重标识
  nickname    TEXT DEFAULT '',         -- 用户昵称（如有）
  city        TEXT DEFAULT '',         -- 城市
  page        TEXT NOT NULL,           -- 访问页面路径
  page_title  TEXT DEFAULT '',         -- 页面中文标题
  is_apk      BOOLEAN DEFAULT false,   -- 是否来自 APK
  os          TEXT DEFAULT '',         -- Android / iOS / Web
  ua_short    TEXT DEFAULT '',         -- UA 简短描述（如 Dalvik / Chrome）
  created_at  TIMESTAMPTZ DEFAULT now(),
  is_read     BOOLEAN DEFAULT false,
  is_voiced   BOOLEAN DEFAULT false    -- 是否已语音播报
);
```

### 3.2 页面路径 → 中文标题映射

| 路径 | 中文标题 | 来源 |
|---|---|---|
| `/apk/home` | 首页（周视图） | APK |
| `/apk/settings` | 设置页 | APK |
| `/apk/schedules` | 课程表管理 | APK |
| `/apk/message` | 留言页 | APK |
| `/apk/transfer` | 导入导出 | APK |
| `/apk/debug` | 调试页 | APK |
| `/user-guide.html` | 用户指南 | Web |
| `/ev-schedule.html` | EV 课程表主页 | Web |
| `/activate` | 激活页 | Web |

### 3.3 通知生成流程

```
visitor_logs 写入
       │
       ▼
trigger (DB trigger / 应用层 hook)
       │
       ▼
1. 提取 visitor_hash、ip、path、ua
2. 查 geo 库 → 城市
3. 查 nickname 映射 → 昵称（如有）
4. path → page_title（映射表）
5. ua 判断来源 → is_apk / os / ua_short
       │
       ▼
写入 visitor_notifications
       │
       ▼
通过 SSE 推送到管理后台页面
```

### 3.4 昵称与用户关联（关键需求）

> 用户要求：要能显示「Android 用户 某某 来自 城市 访问了 页面标题」

目前 APK 上报不传昵称。需要补上：

**方案 A（推荐）：APK 上报时带设备标识，后台关联**

```
APK 上报新增字段：
  "deviceId": "<同步引擎的 deviceId / nodeId>",
  "nickname": "<SyncEngine.nickname>"
```

- `SyncEngine` 已持有 `nickname`、`deviceId`（通过 `nodeId`），改 `Analytics.pageView()` 即可
- 后台：第一次出现该 deviceId 时自动创建 `device_nicknames` 映射表

**方案 B（降级）：APK 直接传昵称**

- 改动最小，但无法追溯历史记录（历史记录无法补上昵称）

**推荐 A**，因为可用于历史数据回填。

### 3.5 接口设计

**新增 API：最近访客通知列表**

```
GET /api/notifications/visitors?limit=50&since=<timestamp>
```

### 3.6 语音播报文案模板

```
{os}用户 {nickname} 来自 {city} 访问了 {pageTitle}
```

示例：
- 「Android 用户 张三 来自 上海 访问了 首页」
- 「Web 用户 来自 杭州 访问了 EV 课程表主页」
- 「Android 用户 来自 北京 访问了 设置页」

> 未获取到昵称时省略昵称部分，城市为必须项（由 IP 归属地保证）。

## 四、功能二：消息投递追踪

### 4.1 问题

当前 Redis pub/sub 推送消息流程：

```
后台 → Redis publish → 客户端 subscribe → ❓ 是否送达？
```

缺少送达确认，无法排查丢通知问题。

### 4.2 方案：ACK 确认机制

```
后台发送消息
    │
    ▼
1. Redis publish (channel: "notify:{deviceId}")
    │
    ▼
2. 记录 tracking_events (kind=message_sent)
    │
    ▼
3. 客户端收到 → 回 ACK
   POST /api/notify/ack
   body: { "messageId": "xxx", "deviceId": "yyy" }
    │
    ▼
4. 更新 tracking_events (kind=message_delivered)
    │
    ▼
5. 超时 N 秒未收到 ACK → 标记为 投递失败
    │
    ▼
6. 管理后台展示投递时间线
```

### 4.3 数据模型

沿用现有 `tracking_events` 表，新增 `kind`：

| kind | 含义 | payload |
|---|---|---|
| `message_sent` | 消息已发送到 Redis | `{ messageId, deviceId, channel, contentPreview }` |
| `message_delivered` | 客户端 ACK 已送达 | `{ messageId, deviceId, deliveredAt }` |
| `message_failed` | 超时未送达 | `{ messageId, deviceId, reason }` |

### 4.4 投递状态时间线

```
🕐 11:04:05  →  📤 11:04:05  →  ✅ 11:04:06
 (创建)         (sent)           (delivered)

🕐 11:04:05  →  📤 11:04:05  →  ❌ timeout
 (创建)         (sent)           (failed)
```

### 4.5 管理后台展示

```
时间         类型           状态      内容                         时间线
11:04:05    page_visit    ✅ 已送达   ip=36.113.30.111,            🕐→📤→✅
                                      city=Hangzhou,
                                      page=/user-guide.html
10:38:34    notify_push   ❌ 超时     设备 BTF4C1722...             🕐→📤→❌
                                      deviceId=xxx
10:35:00    page_visit    ✅ 已送达   Android用户张三 来自上海      🕐→📤→✅
                                      访问了 首页
```

### 4.6 补发机制

投递失败的消息：

- 状态为 `message_failed` 的可一键「🔄 重发」
- 后台根据 `deviceId` 重新 `publish` 到对应 Redis channel
- 重发时创建新的 `message_sent` 事件，带 `retryOf: <原messageId>`

## 五、语音播报（浏览器端 TTS）

### 5.1 方案

使用浏览器原生 `SpeechSynthesis API`（无需第三方库）：

```javascript
// 管理后台 JS
const eventSource = new EventSource('/api/notifications/visitors/stream');

eventSource.onmessage = (event) => {
  const data = JSON.parse(event.data);
  
  // 展示通知条
  showNotificationBanner(data);
  
  // 语音播报
  if (data.isNew && !data.isVoiced) {
    const text = buildVoiceText(data);
    speak(text);
  }
};

function buildVoiceText(notif) {
  const os = notif.isApk ? 'Android用户' : '用户';
  const nick = notif.nickname || '';
  const city = notif.city || '未知城市';
  const page = notif.pageTitle || notif.page;
  return `${os} ${nick} 来自 ${city} 访问了 ${page}`;
}

function speak(text) {
  const utter = new SpeechSynthesisUtterance(text);
  utter.lang = 'zh-CN';
  utter.rate = 1.1;
  speechSynthesis.speak(utter);
}
```

### 5.2 语音播报开关

管理后台提供开关：
- 🔔 开启语音播报（默认开）
- 🔕 关闭语音播报（静默模式，仅展示通知条）

## 六、APK 侧改动

### 6.1 Analytics.java 扩展

```java
// 新增字段
public static void pageView(Context ctx, String path) {
    // ... 现有逻辑 ...
    
    SyncEngine e = SyncEngine.get(ctx);
    JSONObject body = new JSONObject();
    try {
        body.put("path", path);
        body.put("query", "from=apk&v=" + version(ctx) 
            + "&connected=" + (e.hasNode() ? 1 : 0)
            + "&variant=" + Variant.name(ctx));
        // ✅ 新增：昵称 + 设备标识
        body.put("nickname", e.nickname);
        body.put("deviceId", e.hasNode() ? e.nodeId : "");
    } catch (Throwable ignored) {
    }
    // ...
}
```

### 6.2 消息 ACK（SyncEngine 收到推送后回执）

```java
// SyncEngine 收到 Redis 推送消息后
void onMessageReceived(String messageId, String payload) {
    // 处理消息...
    
    // ✅ 新增：发送 ACK
    JSONObject ack = new JSONObject();
    try {
        ack.put("messageId", messageId);
        ack.put("deviceId", nodeId);
    } catch (Throwable ignored) {}
    Net.postJson(Net.BASE + "/api/notify/ack", ack.toString(), null);
}
```
