> 目标页：`apk/src/com/application/watch/classschedule/BandActivity.java`（底部 tab「手环」）

## 0. 一句话结论

> **这个页面不是「不完整」，是「同一个事实说了三遍，而真正该露脸的操作躲起来了」。**
> 首屏三处在说「连接状态」、六行指标里有一行是重复的、本页最高频的「腕聊」排在第四条设置项之后、而唯一会造成断连的动作（清除设备记忆）藏在一个 11sp 的灰色小三角里。
> 所以动作是 **合并状态源 + 重排主次 + 把危险动作收进菜单**，不是换配色。

## 1. 现状诊断（H1–H9）

读完全部 582 行 `BandActivity.java` 后的结论。每条都给代码位置，不是感觉。

| # | 现状（代码位置） | 为什么是问题 |
|---|---|---|
| **H1** | **「连接状态」首屏说三遍**：① 设备卡 `devStatusView`「已连接」；② `ConnectionBar.attach()` 渲染的「已连接 · 小米手环 9 · v1.7.83」；③ 设备状态卡第一行 `<"连接", stConnView>`「已连接」 | 三条近全宽、同色调，用户不知以哪条为准；文案格式还不一致（一条带设备名+版本）。违反 **P2 一件事只说一处** |
| **H2** | **破坏性操作藏在裸「▼」里**：`caret = Ui.text(this, "▼", 11f, Ui.MUTED, false)`，点击 → `setPreferredNodeId("")` + `autoReconnect()`（**清除设备记忆并重连**，多手环会重新询问） | 这是本页唯一会**导致断连**的动作，却用最不可发现的载体承载：11sp 灰色小三角、零文案、零确认。想「切换设备」的用户找不到它，误触的用户会被突然打断 |
| **H3** | **未连接时首屏 80% 是「空」**：设备卡（未连接手环 / 未连接 / 一长句说明）+ `ConnectionBar`「离线 · 自动重连未成功…」+ 设备状态卡**六行全是「—」** + 空 `resultView` + 「连接调试」row | 一屏三处说「没连上」，外加一整张空表；真正的出路（怎么才能连上）要用户自己从文字里拼 |
| **H4** | **设备状态卡密度低 + 与设备卡重复**：六行 `statusRow(label, value)`，每行上下各 6dp 内边距、13sp | ①「连接」行与 H1 重复；② 六个两字词占掉 ≈240dp 竖向空间；③ **电量是本页最重要读数，却和其它五项同字号同色**，没有视觉锚点 |
| **H5** | **入口四条平铺、最高频的沉在最后**：昵称卡 → 首页设置 row → 工具箱 row → 腕聊 row，间距一律 6dp、权重一致 | 「腕聊」（手环 ↔ 手机实时聊天）是本页使用频率最高的动作，却排在**第四条**，且与「工具箱 / 首页设置」这两个配置项同形同级。违反 **P1 先给主操作** |
| **H6** | **昵称卡是全 App 唯一的「裸表单」**：`标签「昵称」+ 去背景 EditText + 主色实心「修改」按钮` 横排 | 全 App 卡片语言里没有第二处这种长相；且「修改」是主色实心按钮，视觉权重压过页面主轴 |
| **H7** | **「连接调试」常驻页底**：`Ui.row(this, "连接调试", "四步逐步执行，看卡在哪一步", …)` 无条件 `addView` | 排障入口对 99% 正常用户是纯噪音，却固定占位在首屏附近 |
| **H8** | **顶栏名不副实**：顶栏 `Ui.topBar(this, "穿戴设备")` vs 底栏 tab 文案「手环」 | 同一屏里同一页面有两个名字；「穿戴设备」是品类词，不是用户对它的称呼 |
| **H9** | **层级扁平**：字号 17（名称）/ 13.5（状态）/ 13 / 12.5 / 12 / 11（▼）——六种字号密集分布在 11–17 之间 | 没有视觉锚点，扫视时不知道先看哪；也说明「所有信息一样重要 = 没有重点」 |

## 2. 设计原则（P1–P6，沿用本项目既定）

| | 原则 | 在本页的体现 |
|---|---|---|
| **P1** | **先给主操作** | 腕聊提为独立主操作卡；设备卡给「呼叫手环 / 同步课表」两枚并列按钮 |
| **P2** | **一件事只说一处** | 删 `ConnectionBar`、删状态卡「连接」行 → 连接状态只在设备卡出现一次 |
| **P3** | **破坏性操作不露脸** | 「清除记忆并重连」收进 ⋯ 菜单，配副文案说明后果 |
| **P4** | **展示归展示，编辑归编辑** | 昵称从「常驻表单」→「设置行 + 底部弹层」 |
| **P5** | **分层靠色彩与位置，不靠新字号** | 电量用主色大数字做锚点，不新造字号 |
| **P6** | **零新增 token** | 色/字号/圆角/间距全部复用 `Ui.java` 既有档位 |

## 7. 风险与取舍（不是只报喜）

| # | 取舍 | 代价 | 退路 |
|---|---|---|---|
| **R1** | 昵称从「输入框常驻可改」→「点行 → 弹层」 | **多一次点击**，改昵称频率若高会嫌慢 | 保留**行内编辑**：点击行时该行原地变成输入框（不做弹层） |
| **R2** | 「连接调试」从常驻 → ⋯ 菜单 | **连不上时更难找**（正是最需要它的时候藏在菜单里）| 未连接**引导卡里保留「连接调试」文字链**（本方案已做）——即：连不上时它反而更显眼 |
| **R3** | 未连接时设备状态区整块收起 | 用户可能想「看看上次的电量/存储」 | 改为**显示上次已知值 + 「上次更新于 X」**灰字，而不是整块消失 |
| **R4** | 指标网格删掉「连接」行 | 若未来状态区需要脱离设备卡独立展示，就少了状态字段 | 让状态**只**从设备卡读；若确需重复，抽同一个 `String` 常量，禁止两处各写一份（这正是 H1 的病根）|
| **R5** | 顶栏改「我的手环」 | 术语变更，需与产品/手环端文案对齐 | 若坚持「穿戴设备」，只改 `Ui.topBar` 一处即可，其余不受影响 |
| **R6** | 设备名**不可编辑**（D10 不新增入口） | 用户可能有「把手环改名」的诉求 | 属**新功能**，不在本次 UI 重构范围；如要做，先在手环端支持写设备名 |

## 8. 验收标准（每条给可执行的判定方法）

| # | 标准 | 判定方法 |
|---|---|---|
| 1 | 页面内**不再出现** `ConnectionBar` 文案 | `uiautomator dump` 后正则 `已连接 · `（含尾空格）匹配数 = **0** |
| 2 | 「已连接」在首屏**只出现 1 次** | dump 里 `text="已连接"` 或含「已连接」的节点数 = **1**（设备卡内） |
| 3 | 顶栏标题为「我的手环」；无「穿戴设备」 | 正则 `穿戴设备` = 0；`我的手环` = 1 |
| 4 | ⋯ 菜单三项齐全 | 点 ⋯ 后再 dump：出现「切换手环 / 清除记忆并重连 / 连接调试」三个文案 |
| 5 | 未连接时无空表 | 拔掉/断开后 dump：`class="android.widget.TextView"` 且 `text="—"` 的节点数 = **0**；出现「还没有连接手环」 |
| 6 | 腕聊在首屏且为独立主卡 | 其节点 `bounds` 的 y 中值 **< 480dp**（= 直观可见区），且与「首页设置」不在同一容器 |
| 7 | 无 `CheckBox` 残留、字号合规 | dump 中 `android.widget.CheckBox` = 0；原型 HTML 里所有 `font-size` 值 ∈ {17,15,13,12.5,11.5,10.5} |
