# 连接状态条方案（4 页面统一）

> 状态：**待拍板** · 提案 2026-09-28 · 关联版本 v0.5.59+（保活心跳已上线）

## 一、背景与目标

首页有一条迷你连接状态条（`● 正在连接手环… / ● 已连接 xxx`），但其余页面看不到连接状态：
在手环页点了「呼叫手环」才知道没连上，在导出页读了半天才发现是离线缓存。

**目标**：课程表管理、导入、导出、主题外观 4 个页面顶部，统一显示一条与首页同款的
**连接状态条**——连接状态一眼可见，断开时能给出口（重连 / 调试）。

## 二、需求原话（用户）

> 每个页面都显示一个类似首页目前已连接的状态条比较直观。
> 文字结构例如：link 图标（绿色）已连接 手环型号 课程表几套（非单个默认信息）ev版本号，
> 断开时 unlink 图标（灰色）离线，是否还自动重试几次，并带着一个「调试连接」可进入调试页面，就一行。

## 三、评估：合理，3 个建议修正

### ✅ 合理的部分
1. **方向正确**：连接是全局单例（SyncEngine），状态条就该全局可见，而不是只有首页。
2. **数据现成**：保活心跳（60s 一次 ping）已经会带回 `versionName/versionCode`，
   状态条数据天然新鲜，**不需要**每个页面再发独立请求（呼应「每页独立连接」的教训）。
3. **断开给出口**：离线态带「重连 + 调试」入口，比纯提示有用。

### ⚠️ 建议 1：「课程表几套」不要实时拉
- 套数来自 `list_schedules`（一次手环往返）。状态条若每次进页面都拉，4 个页面 = 4 次请求。
- **建议**：显示连接流程/同步时缓存的 `courseCount`（已有字段），没有就省略这一段。
  课程表管理页本身有完整的清单，不缺这里的一次展示。

### ⚠️ 建议 2：一行塞不下，改为「主行 + 副行」
360dp 宽一行放 `图标 + 已连接 + 型号 + 课表套数 + EV版本 + 调试` 至少 6 段，必溢出。

| | 主行（必显） | 副行（小字，可省略） |
|---|---|---|
| 已连接 | 🔗 已连接 · 小米手环10 Pro | EV v1.6.144 · 课表 2 套 ｜ 调试 |
| 离线 | ⛓ 离线 · 点按重连 | 上次在线 10-01 20:30 ｜ 调试 |

- 若坚持单行：连接态只保留 `🔗 已连接 · 型号 · v版本`，课表套数与调试挪进点按展开。
- **待拍板 Q1**：两行（推荐）还是严格一行？

### ⚠️ 建议 3：「自动重试几次」改成「点按重连」
- 断开的根因是手环侧 EV 退出，重连动作 = 四步 connect（含 sendWake 自动拉起 EV 重试 3 次，已实现）。
- **不建议**页面级自动重连：4 个页面各自计时重连会互相打架（连接流程也是单例）。
- **建议交互**：离线态整条可点 → 触发重连，重连期间状态条显示「重连中…(1/3)」；
  连接/重连的自动重试已经在 SyncEngine 里，状态条只负责展示。
- **待拍板 Q2**：接受「点按重连」替代「自动重试」吗？

## 四、状态与文案（对照表）

| 状态 | 图标 | 主行文案 | 副行 | 颜色 |

- 「调试」为副行内的文字链接 → DebugActivity；状态条其余部分点按 = 重连（离线态）或跳手环页（已连接态）。

## 五、实现要点

1. **共享组件** `Ui.statusBar(Activity)`：单例状态 + 轻量监听器（SyncEngine 加一个
   `setStatusBarListener`，connect/心跳/ping 结果回调时通知刷新）。
   **首页迷你条迁移到同一组件**——避免 5 个页面各写一份（本次讨论的直接教训）。
2. **接入页面**（5 个）：首页（迁移）、课程表管理、导入、导出、主题外观。
3. **数据源**：型号/版本 = 心跳 pong 回填的 `SyncEngine.deviceName/versionName`；
   课表套数 = `courseCount`（有才显示）；上次在线时间 = 心跳最后一次成功时刻（新记录）。
4. **导出页不冲突**：导出页已有「本地缓存」提示（scheduleStatus，在清单卡里），
   状态条在页首，两者信息不同（连接状态 vs 数据来源），并存。
5. **课程表管理页**：已有「来自手环 · N 门课 · 最后同步」信息行，保留——它表达的是
   数据来源，不是连接状态；若嫌重复可后续合并。

## 七、不做什么

- 不做每个页面独立的连接逻辑（连接始终是 SyncEngine 单例）。
- 不在状态条里放「拉起 EV」「发送自定义 JSON」等高级动作——那是调试页的职责。
- 不做后台（退到后台后）的状态维持——后台留言由常驻服务观察者负责，已另行实现。
