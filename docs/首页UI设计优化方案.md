# 首页 UI 精细化设计优化方案

> 对象：Ev 课程表 Android 端 **首页**（`HomeActivity`）
> 重点：**周课表网格** —— 全页信息密度最高、最决定「精美度」观感的区域
> 基线版本：v0.5.136（2026-10-05） · 真机：BLN-AL20 `1080×1920 @480dpi`
> 立场：以**产品设计师**视角做「现状测绘 → 问题诊断 → 处方 → 可落地清单」，每条结论都给出可核对的数据与代码位置，不做泛泛而谈的「更好看」。

---

## 0. 结论先行（TL;DR）

直接回应你提的三个点，结论与依据如下：

| 你的疑问 | 结论 | 一句话依据 |
|---|---|---|
| 课程名之间空隙能否更小 | **能，且应该**：相邻块留白 `10dp → 4dp`，单块可用文字宽度 `24.3dp → 30.3dp`（**+25%**） | 当前 4 层留白叠加（列内边距 2 + 块外距 3 + 3 + 下一列 2），对一个仅 28dp 宽的块是奢侈的 |
| 单字状态是否做成方形更好看 | **是**：单字模式下块应收到 **近正方（≈1 : 1.15）**，而不是现在的 `28×48` 竖长条 | 竖条里一个居中的大字，上下各留 ~13dp 空白，视觉重心「悬空」；方块则稳 |
| 圆角是否合理 / 小一点更好 | **小一点更好**：块圆角 `6dp → 4dp`（圆角率 `21% → 14%`） | 6dp 落在 28dp 短边上已达 21%，接近「胶囊/按钮感」，削弱了色块作为「信息单元」的气质 |

**顺带发现 4 个「不够精致」的硬伤**（都在本轮一并说明，见 §3）：
1. **行高对不齐**：时间列行距 48dp、有课行 54dp（48+上下各 3 外边距）、空格 48dp —— 三套节奏混用，越往下越歪；
2. **日期条与网格列不对齐**：上方 7 个日期卡与表内 7 个列标签横坐标不一致（网格左侧多了 36dp 时间列）；
3. **角标误读**：「星期 + 休/班」排成一行，`一休 / 三休 / 六班` 会被读成一个词（「一休」）；
4. **圆角 token 两套**：`Ui.card` 硬编码 `14`，`Ui.cardElevated` 用 `16`，而 token `R_CARD = 16` —— 页面里同时存在两种卡片圆角。

> 本方案**全部是视觉参数级改动**（dp / 圆角 / 边距 / 字号），**不触碰数据模型、协议与交互逻辑**，回归面极小。

## 1. 现状测绘（用真机数据说话）

### 1.1 屏幕基准

| 项 | 值 |
|---|---|
| 物理分辨率 | 1080 × 1920 px |
| 密度 | 480 dpi（3.0×） |
| **逻辑视口** | **360 × 640 dp**（1dp = 3px） |

360dp 是一个**窄屏**基准（今天的 iPhone 15 / 主流安卓多在 390–430dp）。所有横向决策必须按 360dp 算，否则一到窄机就挤爆。

### 1.2 周课表网格横向几何（逐层推导）

```
360dp 视口
 └─ root 左右 padding 16（GAP_LG）            →  内容宽 328dp
     └─ 网格卡 cardElevated 左右 padding 12   →  卡内宽 304dp
         ├─ 时间列 TIME_COL_W = 36            →  剩 268dp
         └─ 7 个「天列」均分 weight=1          →  每天列 38.3dp
             └─ 天列 padding 左右各 2          →  单元格 34.3dp
                 └─ 课程块 外边距 左右各 3     →  ★ 色块实际宽 28.3dp
                     └─ 块内 padding 左右各 2  →  ★ 可用文字宽度 24.3dp
```

**关键推论**：一个汉字按 `11.5sp ≈ 11.5dp` 计，`24.3dp ÷ 11.5 ≈ 2.1` —— **当前一个课程块刚好只塞得下 2 个汉字**。这就是为什么首页在密集课表下「挤」而「碎」。

### 1.3 横向留白拆解（这就是你说的「空隙」）

相邻两个课程块之间，横向上同时存在 **4 段留白**：

```
┌──────────┐  2dp   3dp ┆ 3dp   2dp  ┌──────────┐
│  课程块   │ (列内) (外距)┆(外距) (列内) │  课程块   │
└──────────┘                          └──────────┘
                 ← 合计 10dp 空隙 →
```

**10dp 空隙 / 38dp 列 = 26% 的横向空间被留白吃掉**，而块本身只有 28dp 宽。这是「块之间看起来空」的直接原因，也是「块里塞不下字」的同一枚硬币的另一面。

### 1.4 纵向几何与「行高错位」

| 元素 | 每行占用高度 | 来源 |
|---|---|---|
| 时间列标签 | **48dp** | `HomeActivity` :836-837 |
| 有课的课程块 | **54dp**（48 高 + 上 3 + 下 3 外边距） | :924-927 |
| 空格子 | **48dp**（无外边距） | :895-896 |

→ 三套行距混跑：**时间标签每行 48dp 前进，课块每行 54dp 前进**，第 n 行的累计偏差 = `6 × n` dp。第 5 行就差 30dp，肉眼可见「时间轴与课块对不上」。（编辑态网格 `WeekEditGrid` 又是另一套：`cellH=46 / gap=3 / 圆角 8`，三处都不一致。）

## 2. 三个具体问题的诊断与处方

### 2.1 课程名之间的空隙 —— 把留白从 4 层收到 2 层

**诊断**：留白叠了 4 层（列内 2 + 外距 3 + 外距 3 + 列内 2），且每层都是「为了不贴边」而各自加的，没人统一收口。

**处方**（二选一，推荐 A）：

| 方案 | 做法 | 块宽 | 可用文字宽 | 块间空隙 |
|---|---|---|---|---|
| **A（推荐）** | 天列内边距 `2→1`，块外边距 `3→1` | 28.3 → **34.3dp** | 24.3 → **30.3dp（+25%）** | 10 → **4dp** |
| B（更激进） | 天列内边距 `2→0`，块外边距 `3→1` | 28.3 → **36.3dp** | 24.3 → **32.3dp（+33%）** | 10 → **2dp** |

- 推荐 **A**：4dp 空隙 ≈ 一张名片的缝，既有分隔感又不像「散开的方块阵」；B 的 2dp 在深色主题下块与块容易糊成一片，除非同时给块加 1px 描边。
- **顺带收益**：可用宽度从 2.1 → 2.6 个汉字。**超过 2 字的课名（如「高等数学」「数据结构」）现在必须缩写成 2 字，改后能显示 2 个半字**，`displayName` 的缩写压力直接下降。

**规则沉淀**：*色块类元素，同一方向上的「外边距 + 容器内边距」总和应 ≤ 4dp，且只由一层承担。*

---

### 2.2 单字模式的块比例 —— 从「竖长条」到「方块」

**诊断**：单字模式（首页右上「单」按钮）下，块仍是 `宽 28.3 × 高 48` 的**竖长条**，一个 15sp 的大字居中 → 上下各留约 `(48 − 15×1.33) ÷ 2 ≈ 14dp` 空。视觉上字「浮」在色条中，比例是 `1 : 1.7`，偏瘦。

**处方**：单字模式下，**块高收到与块宽同量级**，目标宽高比落在 `1 : 1 ~ 1 : 1.3`：

| 模式 | 块宽 | 建议块高 | 宽高比 | 说明 |
|---|---|---|---|---|
| 双行（课名+地点） | ≈34dp | **44dp** | 1 : 1.29 | 容纳「11.5sp 课名 + 10.5sp 地点」两行 |
| **单字** | ≈34dp | **40dp** | **1 : 1.18** | 近正方，大字稳稳落座 |

- 块在行内**垂直居中**，多出的行高留白由「行背景/时间列」承担，不再让块硬撑到 48dp。
- 方块化后还有一个隐性收益：**单字模式 = 一眼扫课表**，方块阵列比长条阵列更像「课表矩阵」，符合它的使用场景。

> 补充建议：单字模式既然主打「一扫即识」，可把单字字号从 `SP_SUBTITLE(15)` 提到 **16–17sp**（`SP_NUM`/`SP_TITLE` 档），方块 + 更大字，识别效率最高。

**规则沉淀**：*色块的宽高比应落在 `1 : 1 ~ 1 : 1.4`；单字块优先取近正方。*

---

### 2.3 圆角 —— 6dp 偏圆，收到 4dp

**诊断**：块短边仅 28.3dp，`R_BLOCK = 6dp` → **圆角率 21%**。经验值：圆角率 > 20% 观感立刻转向「胶囊 / 按钮」，< 15% 才像「信息卡片」。

**处方**：

| 元素 | 现状 | 建议 | 圆角率变化 |
|---|---|---|---|
| 课程色块 `R_BLOCK` | 6dp | **4dp** | 21% → 14% ✅ |
| 卡片 `R_CARD` | token 16，但 `Ui.card` 实际 14 | **统一 14** | 消除两套 |
| 控件 `R_CTRL` | 12dp | 12dp（保持） | 日期卡 / 按钮用，合理 |

**为什么是 4 而不是 3**：3dp 在 3× 屏上 = 9px，抗锯齿过渡只有 3 个物理像素，圆角会「糊」成直角；4dp = 12px，是**视觉上有圆角、物理上不糊**的下限。

**规则沉淀**：*圆角率 = 圆角 ÷ 短边，目标 `10%–15%`；且 `R_BLOCK < R_CTRL < R_CARD` 的层级不能乱。*

> 配套：编辑态 `WeekEditGrid` 的块圆角现在是硬编码 `8dp`、行高 `46dp`、间距 `3dp`，与首页三处不一致 —— 建议一并改用同一组 token，保证「看课表」和「改课表」两张网格是同一个设计语言。

## 3. 顺带发现的 4 个「不够精致」硬伤

### 3.1 行高对不齐（**优先级最高**）

时间列 48dp / 课块行 54dp / 空格 48dp 三套节奏（见 §1.4）。**建议统一为单一 `ROW_PITCH = 48dp`**：

- 时间列行高 = `ROW_PITCH`；
- 课块：`高 = ROW_PITCH − 2×外边距`（如外边距 2 → 块高 44）；
- 空格：同块同高，或占满 `ROW_PITCH`；
- 这样时间轴与每一行色块严格同行同高，滚动时不会「错位漂移」。

```text
修前：  时间08:00 ─────   课块 ▉ (48)
        时间08:55 ─────   课块      ▉ (54)   ← 已偏 6dp
        时间10:00 ─────   课块          ▉ (108) ← 偏 12dp

修后：  时间08:00 ─────   课块 ▉        (48)
        时间08:55 ─────   课块     ▉     (48)
        时间10:00 ─────   课块         ▉  (48)   ← 恒对齐
```

### 3.2 日期条与网格列不对齐

上方 7 个日期卡（`renderDateStrip`，格子均分 328dp）与表内 7 个列标签（`weekGridWithTime`，被 36dp 时间列挤到右侧）**横坐标不一致**，视觉上「两排星期对不上」。

**三个方案**：

| 方案 | 做法 | 评价 |
|---|---|---|
| A（推荐） | 日期条右侧让出「主标题+周切换」的空间，左缘与**表内天列左缘**对齐（即日期条整体右移 `卡内边距 12 + 时间列 36 = 48dp`），左侧 48dp 空白改放「周范围 ◀ ▶」 | 一次对齐解决，且把周切换从顶部挪到日期区，信息更聚 |
| B | 表格去掉左侧时间列，时间改为「行内左上角小字」 | 改动大、影响可读性 |
| C | 保持现状，但把表内列标签弱化/去掉（仅留日期条） | 代价最低，但损失「表内星期」的定位感 |

### 3.3 角标误读「一休 / 六班」

`星期 + 休/班` 同排拼成 `一休`、`六班`，会被读成一个词。**处方**：把「休/班」角标做成**右上角的小圆点/小方块角标**（8–10dp），或下移到日号旁，与星期字分离。这是很低成本、观感提升明显的一处。

### 3.4 两套卡片圆角

`Ui.card` = 14dp（硬编码），`Ui.cardElevated` = 16dp，token `R_CARD = 16`。**处方**：`R_CARD` 定为 **14**，并让 `cardElevated` 也走 `R_CARD` —— 一处 token 收口，全 App 卡片圆角即统一。

## 4. 布局合理化：把首页的纵向信息层级理顺

当前首页自上而下：`顶栏(标题+⊕) → 问候 → 大标题+周切换 → 日期条 → 课表卡 → 快捷2×2 → 迷你状态条 → 错误卡`。

几个可优化的点：

1. **问候与标题重复**：「Hi，某某」+「本周课表」占了两行高频空间。建议合并为一行（`本周课表 · Hi，某某`）或把问候降级为**大标题下的一行小字**，把省下的 24dp 还给课表网格（这对窄屏很重要）。
2. **迷你状态条位置偏下**：连接状态属「设备域」，放在课表与设备页之间会打断浏览节奏。建议**收敛为标题旁的一个状态圆点**（绿=已连接 / 灰=未连接，点按进手环页），把那条卡片彻底删掉，首页更「纯净 + 聚焦课表」。
3. **纵向节奏**：目前各区之间统一 `GAP_LG(16)`。建议改为**「分组内 8 / 分组间 16」**的两级节奏 —— 让「日期条 + 课表」成为一组紧凑的信息组，与上方头部、下方快捷区拉开。分组感一出来，页面立刻「高级」。
4. **快捷 2×2 卡片**：四宫格图标 + 文字目前较规整，但卡片次级底色 `CARD2` 与主卡 `CARD` 对比偏弱。建议图标底色改用主色的 8–12% 淡化块（`ACCENT_LIGHT` 同族），让四个快捷入口有「可点」的暗示。

## 6. 视觉规范小结（沉淀给后续页面复用）

1. **间距**：4dp 栅格（`4 / 8 / 12 / 16`）；**同类元素的同向留白只由一层承担，总和 ≤ 4dp**。
2. **圆角**：`R_BLOCK(4) < R_CTRL(12) < R_CARD(14)`；圆角率目标 `10%–15%`，超过 20% 会「按钮化」。
3. **色块**：宽高比落在 `1 : 1 ~ 1 : 1.4`；单字块近正方。
4. **网格**：**行距必须单一真源**（`ROW_PITCH`），任何「块/空行/时间标签」都不许自成一套。
5. **字号**：只用 7 档阶梯（`SP_DISPLAY / TITLE / SUBTITLE / BODY / CAPTION / MICRO / NUM`），禁止散落小数档。
6. **对齐**：同一信息组内的列，横坐标必须可比对（日期条 vs 网格列）。
7. **语义角标**：状态（休/班/今）用**位置或形状**区分，不与主文案同排拼读。

## 7. 依据与风险

- **依据**：真机 BLN-AL20 截图 + `HomeActivity.java` / `Ui.java` 逐行核对；几何数据为 360dp 视口下的实际推导值；可读性判据参考 WCAG 对比度（`Ui.onCourseColor` 已按 0.45 亮度阈值选深/白字）。
- **风险**：全部为视觉参数变更，**无逻辑风险**；唯一需实测的是「留白收窄后深色主题下相邻块的区分度」（若糊，给 `R_BLOCK` 色块补 `1px` 描边即可）。
- **取舍**：§2 三项是本轮**必做**；§3.1（行高统一）强烈建议同批做（它是「布局不合理」的根因）；§3.2 / §4 视排期分批。
