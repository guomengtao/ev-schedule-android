1现状诊断：这个页面真正的毛病不是"不好看"

读完 ScheduleListActivity.java 全部 710 行后的结论。没有一条是"审美"问题，全是"信息架构"问题。

#现状为什么是问题
H1 三条状态条竖直叠放：① ConnectionBar「已连接 · 小米手环 · v1.7.x」② syncView 胶囊「3 门课未同步 · 点此同步」③ deviceBar「● 在线 · 小米手环 ··a1b2 · 3 套 ▸」 三条全宽、同形、同色系，视觉重量完全一致 → 用户不知道该先看哪条。更糟的是 ① 和 ③ 说的是同一件事（设备 + 连接状态），只是措辞不同。
H2 一行纯说明文字：「本机保存的全部课表：可切换、编辑、同步到手环」（11.5sp 灰） 解释 UI 而不是服务用户。占一整行（约 26dp 竖高），却零可操作信息——用户点开界面 3 秒就懂的事。
H3 分组默认全部折叠：进页面只看到 ▸ 本地课程 · 3 套，一个课表名都看不到 这是「库」页面，核心内容就是课表清单。默认把清单藏起来 = 每个用户每次都要多点一下。管理页应当先"展示"后"操作"。
H4 卡片右上角常驻三个图标：[同步] 编辑 删除，同色同大小并排 「删除」是不可逆破坏性操作，却与「编辑」相邻、同形、无区分 → 误触风险高。且三个图标（各 ~30dp）把课表名挤压到不足 200dp。
H5 切换当前课表用 CheckBox「当前」 放在卡片右下角 语义错误：当前课表是互斥单选，却用多选控件；且这是本页最高频的动作，却用了视觉最弱、位置最偏的控件。
H6 层级扁平：课表名 14.5sp / 分组头 12.5sp / 设备条 12.5sp / 同步胶囊 12sp 全挤在 12–14.5 区间 没有明确的主次。用户扫视时找不到锚点。
H7 空态 = 一行灰字（12.5sp MUTED） 新用户首次进入看到一句灰话，没有插画、没有主 CTA，不知道下一步干什么。
H8 创建入口分裂：底部「＋ 新建本地课表」按钮 + 下方「导入 / 导出」卡（EV 变体） 三类"创建/迁移"动作（新建 / 导入 / 导出）分散在页面两处，认知上是一件事却要点两个地方。

2设计原则

页面定位：课表库是"管理"页。用户来这里只干四件事——看我有哪些课表 → 切换当前 → 同步到手环 → 增 / 删 / 改。所有决策围绕这四件事排序。

原则含义落到哪个决策
P1 先展示，后操作「库」的第一职责是把清单摊开给人看，而不是先让人点D2 分组默认展开
P2 一件事只说一处设备只有一个、连接状态只有一个真相 —— 不要三条栏说同一件事D1 合并 ConnectionBar + deviceBar；D3 同步态降级为徽标
P3 破坏性操作不露脸删除不可逆，就不能和编辑并排常驻D5 溢出菜单「⋯」收纳
P4 互斥用单选语义当前课表只能有一套 —— 控件语义必须匹配D4「设为当前」按钮 + 「使用中」徽标
P5 分层靠色彩与位置，不靠新字号字号阶梯是硬规范（7 档禁增），层级要用色 / 空间 / 描边做全部决策
P6 零新增 token落地不能牵动全局样式见 §6 映射表

7落地清单（3 批 · 每批独立可验收）

批次 1 — 结构减法（低风险，纯删/合并）

  • B1.1 顶栏标题 "课程表管理" → "课表库"；右侧加 ⊕ 圆钮 + 弹出菜单（D6）。
  • B1.2 删除 ConnectionBar.attach(...) 调用；把它显示的信息并入设备条（D1）。
  • B1.3 删除说明文字「本机保存的全部课表…」（H2）。
  • B1.4 groupHeader() 从厚卡改为细行（去背景/描边，字号降到 SP_CAPTION + MUTED）（D2）。
  • B1.5 expandedGroups 初始值改为"包含全部组 key"（默认展开）（D2）。
  • B1.6 删除底部「＋ 新建本地课表」按钮 + 导入/导出卡，并入顶栏 ⊕ 菜单（D6）。

批次 2 — 卡片重排（核心）

  • B2.1 scheduleCard() 标题字号 14.5 → SP_TITLE 17sp；当前卡标题色 ACCENT（D4）。
  • B2.2 当前卡加 4dp ACCENT 左竖条 + ACCENT 描边（用 Ui.round + 背景 drawable，或外层套一个 4dp View）（D4）。
  • B2.3 三图标行（icons）→ 单个「⋯」按钮；菜单项：编辑课表 / 同步到手环 / 从本机移除（D5）。
  • B2.4 删除 CheckBox；改为：当前卡显「使用中」徽标，非当前卡显「设为当前」描边按钮（点 → ScheduleStore.setActive）（D4）。
  • B2.5 副信息 s.sub() 拆成两段：主副行（来源 · N 门课）+ 相对时间（最后同步/—）；相对时间走 SP_MICRO。
  • B2.6 syncView 从页顶全宽胶囊 → 移入当前卡的同步徽标；点击行为不变（未连接 → 去连接页）。（D3）

批次 3 — 边界与打磨

  • B3.1 空态改为插画 + 标题 + 双 CTA，按连接状态切换主 CTA（D7）。
  • B3.2 未连接态：设备条转灰、隐藏计数徽标、徽标文案统一「未连接 · 无法同步」。
  • B3.3 组间不再需要 divider()（细行组头自带呼吸感）——确认视觉后删除。
  • B3.4 statusView 瞬时反馈行保留（~10 处调用），但上移紧贴设备条，避免与列表尾部抢位。
风险与取舍（必须先说明，不能只报喜）：
  • B1.6 有争议：把「新建」从底部常驻按钮收进顶栏 ⊕，多了一次点击。我的判断是——管理页的高频动作是「切换当前」而非「新建」，且 ⊕ 与首页入口一致、认知统一；若产品认为新建足够高频，可退回底部常驻按钮，其余决策不受影响。
  • B1.5 默认展开：多设备（3 台以上手环）时首屏会很长。缓解：保留分组折叠能力，且"其它设备"组仍可默认收——只默认展开"当前设备组 + 本地组"是更稳的折中，建议落地时二选一。
  • B2.6 同步徽标内嵌：原 syncView 在折叠当前组时仍可见，移入卡内后折叠即不可见。因 B1.5 已默认展开，实际影响很小；接受。
