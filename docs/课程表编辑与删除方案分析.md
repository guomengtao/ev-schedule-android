# 课程表编辑与删除方案分析

> 分析日期：2026-09-28
> 背景：上一阶段（首页课表方案 A）上线了「课程表管理」栏目，支持新建/切换/同步到线上。
> 本次分析补齐：**课程表编辑（JSON）** 与 **课程表删除**，并顺手重做课程表栏目的 UI（按钮笨重、观感差）。

---

## 1. 现状回顾

### 1.1 课程表管理栏目（ScheduleListActivity）

```
┌──────────────────────────┐
│  课程表管理                │
│  本机保存的全部课表…       │
├──────────────────────────┤
│  📱 示例课表（本地）✓      │
│  仅本机 · 7 门课            │
│  [  同步到线上  ]          │  ← 按钮：大、占满一行，笨重
├──────────────────────────┤
│  ☁️ 2026春季课表           │
│  来自手环 · 8 门课 · 最后同步…│
│  [ 切换为此 ] [ 同步到线上 ] │  ← 两按钮横排，文字挤
├──────────────────────────┤
│  [  + 新建本地课表  ]      │
├──────────────────────────┤
│  导入 / 导出               │
│  [ 导入 ] [ 导出 ]         │
└──────────────────────────┘
```

**问题**：
- 每张卡片只有「同步到线上」一个大按钮，浪费空间；两按钮时横排文字挤在半行里，可读性差
- 没有「编辑」「删除」入口，课表创建后只能在导入页（TransferActivity）编辑
- 新建课表后是空课表，用户要去导入页才能填课程，链路长

### 1.2 现有 JSON 编辑能力（TransferActivity）

- `exportBox` 是一个普通 `EditText`，**没有**行号、没有语法高亮、不能精确行内跳转
- `parseLoose()` 宽松解析（JSONObject / JSONArray 都试），但**没有错误提示**（解析失败只说"解析不出课程数组"）
- 有复制按钮、有更新确认，但 UI 是普通白底 EditText，**体验接近记事本**
- 这套编辑逻辑绑死在 TransferActivity，**无法复用**到课程表编辑/新建场景

## 2. 核心需求拆解

| 模块 | 关键要求 |
|------|---------|
| **编辑（JSON）** | 仅支持 JSON；文本域需：行号、换行、语法彩色高亮；复制 JSON 按钮；更新按钮（带格式校验）；提示「可复制给 AI 编辑」；界面优美 |
| **编辑器通用性** | 作为独立通用栏目，可在「编辑课表」「新建课表」等多种场景复用 |
| **删除** | 默认仅删本地；已同步课表需连接手环才能删，但支持「仅删本地」（附说明：仅删本地后下次同步会重新拉取） |
| **新建课表** | 给一个默认规范 JSON 模板 + 同样的 AI 提示，复用编辑器 |
| **栏目 UI** | 重做课程表管理页，按钮轻量化 |

## 3. 通用 JSON 编辑器（JsonEditorView）

### 3.1 定位

**独立的通用组件**，不绑死任何业务页面。对外暴露：

```
setJson(String json)        // 填充当前内容（美化缩进后展示）
String getJson()            // 取用户编辑后的原始文本
boolean validate()          // 校验 JSON 格式，返回是否合法
String getError()           // 校验失败时的错误信息（行号 + 原因）
setOnChangeListener(l)      // 内容变化回调（实时校验）
```

调用方只需关心「填充 / 取数 / 校验」，**编辑器内部自己搞定行号、高亮、复制、格式检查**。

### 3.2 布局结构

```
┌────────────────────────────────────┐
│  JSON 编辑器            [复制] [格式化]│  ← 标题行 + 操作按钮
├────────────────────────────────────┤
│  1 │{                              │
│  2 │  "name": "示例课表",          │  ← 行号区（灰色，固定宽度）+ 代码区
│  3 │  "courses": [                 │
│  4 │    {                          │
│  5 │      "name": "高等数学",       │
│  6 │      "day": 1,                │
│  7 │      "time": "08:00 - 09:35"  │
│  8 │    }                          │
│  9 │  ]                            │
│ 10 │}                              │
├────────────────────────────────────┤
│  💡 把 JSON 复制给 AI，说「帮我加一节周三第3-4节的体育，在体育馆」│  ← 提示条
├────────────────────────────────────┤
│  ✅ JSON 格式正确 (10 行)            │  ← 实时校验条：通过=绿，错误=红+行号
└────────────────────────────────────┘
```

### 3.3 行号 + 高亮实现思路

安卓没有开箱即用的代码编辑器控件，这里用**两层 View 叠加**实现：

```
FrameLayout
  ├─ LineNumberView（左侧，不响应输入）
  │     每行一个 TextView，宽度固定 ~28dp，右对齐，灰色
  └─ EditText（主输入区，monospace 字体）
        addTextChangedListener → 重绘行号 + 重刷高亮
```

**行号同步**：监听 `EditText` 的 `addTextChangedListener`，按当前换行数生成行号文本，`post()` 到 UI 线程刷新行号 View。为避免滚动错位，行号 View 与 EditText 共用同一个 `ScrollView`，或两者都设 `scrollTo` 同步。

**语法高亮**：用 `EditText` 的 `Editable` + `SpannableStringBuilder` + `ForegroundColorSpan`，按 JSON 语法着色：

| Token | 颜色 |
|-------|------|
| 字符串 key（如 `"name"`） | 主色 ACCENT（蓝） |
| 字符串 value（如 `"高等数学"`） | 强调色（绿/橙） |
| 数字 / 布尔 / null | 紫色 |
| 标点 `{ } [ ] , :` | 次要色 MUTED（灰） |

**性能**：课表 JSON 通常 < 100 行，每次输入重扫全文字符量可忽略，不需要增量解析。

### 3.4 格式校验

调用 `new JSONObject(text)` / `new JSONArray(text)` 解析：
- 成功 → 底部绿条「JSON 格式正确 (N 行)」
- 失败 → 取异常 message 中的行号（`JSONException` 的 message 通常带 `at character N`，换算成「第 X 行第 Y 列」），红条提示

```
❌ 第 5 行第 12 列：Expected ':' after name at character 123
```

换算方法：从文本开头数到 `character N`，统计 `\n` 个数 = 行号，`N - 上次行首位置` = 列号。

### 3.5 操作按钮

| 按钮 | 行为 |
|------|------|
| **复制** | `ClipboardManager` 复制全文，轻提示「已复制 N 字符」 |
| **格式化** | 解析 JSON → `toString(2)` 美化缩进回填（非法时禁用并提示） |
| **（由调用方提供）更新/保存** | 编辑器不内置保存按钮，保存逻辑由宿主页面决定（编辑页=存本地+同步，新建页=新建课表） |

> 「复制给 AI」的提示是固定文案条，始终显示在编辑器下方。

### 3.6 适用场景

| 场景 | 初始内容 | 保存行为 |
|------|---------|---------|
| 编辑已有课表 | 该课表当前 courses 的 JSON | 校验 → 更新本地缓存 → 若是 sync 课表则提示需同步手环 |
| 新建本地课表 | 默认规范 JSON 模板（示例 7 门课） | 校验 → 新建 local 课表并设为激活 |
| 导入课表（复用） | 用户粘贴 / 从文件读入的 JSON | 校验 → 导入（可沿用现有 import 协议） |

## 4. 编辑课表流程

```
课程表列表 → 某课表卡片长按 / 点「编辑」
         ↓
JsonEditorActivity（通用编辑器）
  初始内容 = 该课表 courses 的标准 JSON
  底部固定操作栏：[复制 JSON]  [更新课表]
         ↓
  用户改完点「更新课表」
         ↓
  validate() 不通过 → 红条提示，停留在编辑页
         ↓
  通过 → 确认弹窗「将覆盖 XX 课表的 N 门课」
         ↓
  ScheduleStore.updateCourses(id, parsedCourses)
         ↓
  若 id == activeId → 直写 CourseCache（插件/提醒联动）
  若该课表 source=sync → 提示「已修改本地副本，需点同步到手环才会写回手环」
```

**与手环的关系**：编辑只改手机本地；sync 课表编辑后需要用户主动「同步到线上」才会写回手环（与现有同步按钮一致）。编辑不直接操作手环协议，避免误写。

## 5. 删除课表流程

### 5.1 删除策略

```
                  ┌─────────────────────┐
                  │  点某课表「删除」     │
                  └─────────┬───────────┘
                            ↓
                  ┌─────────────────────┐
                  │  source = local ?   │
                  └─────────┬───────────┘
                       是 ↙       ↘ 否
                ┌──────────┐   ┌──────────────────┐
                │ 确认删除  │   │ 已连接手环？      │
                │ 仅本地    │   └──────┬───────────┘
                └──────────┘        是↙    ↘否
                              ┌────────┐  ┌───────────────┐
                              │双选项： │  │仅「仅删本地」  │
                              │1.删手环 │  │可用（灰掉另一个）│
                              │2.仅本地 │  └───────────────┘
                              └────────┘
```

### 5.2 三种删除结果

| 操作 | 条件 | 行为 |
|------|------|------|
| **删除本地课表** | source=local | 直接从 ScheduleStore 移除；若为 active → 自动切到最新一套 |
| **删除同步课表 · 删手环** | source=sync 且已连接 | 需手环支持删除协议；若手环暂不支持，降级为「仅删本地」并提示 |
| **删除同步课表 · 仅删本地** | source=sync（任意连接状态） | 仅从本机列表移除，**手环上仍保留**；下次自动同步会重新拉回本机 |

### 5.3 「仅删本地」的说明文案

删除确认弹窗中，选择「仅删本地」时附加说明：

> 仅从本机删除这张课表。手环上仍保留，下次连接手环同步时会重新拉取到本机。
> 如需彻底删除，请连接手环后选择「从手环删除」。

这个说明必须**显式**展示，避免用户以为删干净了。

### 5.4 手环删除协议的现实情况

当前 EV 手环协议只有 `import`（覆盖当前课表）和 `list_schedules`/`export`，**没有显式的 delete 动作**。因此「从手环删除」分两阶段：

- **阶段 1（本期）**：sync 课表删除仅提供「仅删本地」，「从手环删除」按钮置灰并提示「手环暂不支持，仅可删本地」
- **阶段 2（手环端升级后）**：增加 `{"action":"delete_schedule","name":"..."}` 协议，启用完整删除

文档要把这个边界写清楚，避免承诺不可达的能力。

## 6. 新建课表流程（复用编辑器）

```
课程表列表 → [+ 新建本地课表]
         ↓
JsonEditorActivity（通用编辑器）
  初始内容 = 默认规范 JSON 模板：
    {
      "name": "新课表",
      "courses": [
        {"name":"课程名","day":1,"time":"08:00 - 09:35","teacher":"","location":"教学楼"}
      ]
    }
  底部固定操作栏：[复制 JSON]  [创建课表]
         ↓
  点「创建课表」→ 校验 → ScheduleStore.addLocal(name, courses) → 设为激活
  提示：「把 JSON 复制给 AI，说『帮我加一节…』可快速编辑」
```

**为什么新建也用 JSON 编辑器**：
1. 避免做两套 UI（表单 + JSON），维护成本低
2. 课表字段多（name/day/time/teacher/location），纯表单 UI 长且不直观
3. JSON + AI 是这个项目既定的协作方式（TransferActivity 已有「可发给 AI 帮你规范整理」提示），统一体验

## 7. 课程表管理页 UI 重做

### 7.1 问题

- 按钮 `Ui.button` 默认高度大、占满行，列表里每张卡片塞 1-2 个大按钮，整体笨重
- 操作（切换/编辑/删除/同步）入口不清晰

### 7.2 重做方案

**卡片样式**：每行 = 图标 + 标题（课表名）+ 副信息（来源/门数/同步时间）+ **右侧紧凑操作图标行**。

```
┌──────────────────────────────────────────┐
│ 📱 示例课表（本地）            [✏️][🗑️]  │  ← 标题 + 右侧编辑/删除图标
│ 仅本机 · 7 门课                           │
├──────────────────────────────────────────┤
│ ☁️ 2026春季课表 ✓          [🔄][✏️][🗑️]  │  ↓ 多一个同步图标
│ 来自手环 · 8 门课 · 最后同步 2 小时前       │
└──────────────────────────────────────────┘
```

**操作图标**（轻量、小尺寸、只在卡片右侧）：

| 图标 | 含义 | 显示条件 |
|------|------|---------|
| ✏️ 编辑 | 打开 JSON 编辑器 | 始终 |
| 🗑️ 删除 | 删除课表 | 始终 |
| 🔄 同步到手环 | 同步到线上 | 仅 local 课表（sync 课表已是手环来的） |
| ✓ 当前激活标记 | 无操作，仅展示 | 仅 active 课表 |
| 「切换为此」文字链 | 非激活课表 | 非 active 时替换✓位置 |

**好处**：
- 不再有占满半行的大按钮，列表紧凑
- 编辑/删除变成图标，一眼可点
- 「切换」用文字链（如 `切换为此 →`）放在副信息行末尾，不抢视觉

### 7.3 「切换为此」的交互

非激活课表卡片右下角放一个文字链「切换为此 →」（ACCENT 色），点击即 `ScheduleStore.setActive`。

## 8. 数据模型与 API 补充

ScheduleStore 需新增：

```java
/** 删除一套课表（本地）；若删的是 active，自动切换到最新一套 */
public static synchronized void remove(Context c, String id);

/** 更新某套课表的课程（编辑保存用） */
public static synchronized void updateCourses(Context c, String id, List<Course> courses);
```

`updateCourses` 上一阶段已加；`remove` 需实现（含 active 自动切换）。

## 9. 实施路径

### 9.1 阶段 1：通用编辑器组件（约 1 天）

1. 新建 `JsonEditorView.java`（FrameLayout 组合：行号 View + EditText + 高亮 + 校验）
2. 新建 `JsonEditorActivity.java`（带标题、复制/格式化按钮、保存按钮槽位、AI 提示条）
3. 单元自测：粘贴非法 JSON → 红条带行号；格式化按钮 → 美化缩进

### 9.2 阶段 2：课程表页 UI 重做 + 编辑入口（约半天）

1. ScheduleListActivity 卡片改为「图标 + 标题 + 副信息 + 右侧图标行」
2. 编辑图标 → 跳 JsonEditorActivity，初始内容为该课表 courses 的 JSON
3. 保存 → `ScheduleStore.updateCourses` + 激活课表直写 CourseCache

### 9.3 阶段 3：删除（约半天）

1. ScheduleStore 新增 `remove`
2. 删除图标 → 按 source 分支弹确认框（local 直接删；sync 仅本地删 + 说明；「删手环」按钮置灰）
3. active 被删 → 自动切到最新一套；全删光 → 加载默认课表兜底

### 9.4 阶段 4：新建课表改用编辑器（约 2 小时）

1. 「+ 新建本地课表」→ 跳 JsonEditorActivity，初始内容为默认模板
2. 保存 → `ScheduleStore.addLocal(name, courses)` + 设激活

### 9.5 阶段 5：真机回归（约半天）

- 编辑器：行号同步、高亮、非法 JSON 行号提示、复制
- 编辑：改一门课 → 首页周视图更新 → 插件更新
- 删除：本地课表删除；sync 课表仅删本地 → 重连后重新拉回
- 新建：默认模板 → 改完创建 → 首页显示新周视图

## 10. 风险与边界

| 风险 | 应对 |
|------|------|
| 行号与 EditText 滚动不同步 | 两者包在同一个 `ScrollView` 内，或监听 `OnScrollChangeListener` 同步 `scrollTo` |
| 高亮 Spannable 在输入时丢失 | 输入后重新对全文 `setText(Spannable)`，而非用 `append`；光标位置用 `setSelection` 恢复 |
| 大 JSON（>500 行）高亮卡顿 | 课表场景不会到这个量级；预留阈值，超过 N 行则降级为纯文本（不高亮但仍校验） |
| 「从手环删除」不可达 | 本期置灰 + 明确提示，等手环端协议升级后再启用 |
| 仅删本地后用户困惑 | 弹窗显式说明「下次同步会重新拉取」，不静默 |

---

## 11. 总结

1. **编辑器通用化**：抽 `JsonEditorView` + `JsonEditorActivity`，编辑/新建/导入三场景复用一套 UI，行号+高亮+校验+复制+AI 提示配齐
2. **编辑只动本地**：不直接操作手环协议，sync 课表编辑后由用户主动同步
3. **删除分源**：local 直删；sync 默认仅删本地（附重新拉取说明），手环删除待协议支持
4. **栏目 UI 重做**：大按钮 → 图标行 + 文字链，列表紧凑清晰
5. **新建即编辑**：新建课表直接进编辑器，默认模板 + AI 提示，免去空课表二次编辑的链路
