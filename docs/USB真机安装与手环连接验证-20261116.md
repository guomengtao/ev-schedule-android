## 二、安装过程与关键坑：MIUI「USB 安装提示」弹窗

`adb install -r` 与 `pm install -r -g` 首次均失败：

```
Failure [INSTALL_FAILED_USER_RESTRICTED: Install canceled by user]
```

**根因**：MIUI 的 USB 安装安全确认弹窗（"正在通过USB安装此应用，是否继续？"，「继续安装」/「拒绝(9)」9 秒倒计时）在后台静默弹出，无人点确认，倒计时到点自动取消——报错文案伪装成"用户取消"，实为超时。手机屏幕截图取证确认弹窗存在（见 §五）。

**解法**：安装命令后台起，2 秒后在弹窗「继续安装」按钮坐标 (198,1345)（720×1440 分辨率）注入 tap：

```bash
adb -s c338a0677d28 install -r -g apk/EVSyncProbe.apk > log 2>&1 &
sleep 2
adb -s c338a0677d28 shell input tap 198 1345   # 点「继续安装」
wait
# → Success
```

装后核验：`pm list packages com.application.watch.classschedule` 命中，`dumpsys package` versionName=0.6.64。

> 可复用：`ev pit add` 建议登记「MIUI USB 安装 INSTALL_FAILED_USER_RESTRICTED = 弹窗超时，需定时 tap 继续安装」。

## 四、根因定位与交叉验证

**根因：手环未与这台 Redmi 6A 建立小米运动健康绑定，手机侧 `getConnectedNodes()` 拿不到节点。** 三星前提（包名一致 / 签名一致 / 小米健康保持手环连接，见 `interconnect 打通经验速查.md`）中第三条不满足，连接链路 `APK → AIDL → 小米运动健康 → BLE → 手环 → EV 快应用` 在第 3 环断开。

交叉证据：

1. 手机蓝牙 Bonded devices 数量 = 0（`dumpsys bluetooth_manager` 的 Bonded devices 段为空）——手机没有配对手环。
2. `com.mi.health:device` 进程在跑但无已连接设备节点；App 第 2 步正是查此节点。
3. Mac 侧 AstroBox 进程在跑（pid 66181），但 `ev-install.sh -c` 报「未连接」，蓝牙可见两只手环（Band 10 Pro 3ADC / Band 9 B885）——可见 ≠ 已连接。因 AstroBox 未连手环，**不存在 SPP 独占会话抢占**（pit-20261104-97 场景排除）。
4. 蓝牙状态 `ConnectionState: STATE_DISCONNECTED`。

> 注：machine 侧同时能看到两只手环（10 Pro + 9），需在小米运动健康里确认目标是哪一只。
