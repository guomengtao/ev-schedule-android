## 1. 端到端链路（全景）

```
[手环] 快应用页面 (message-inbox / tools)
   │  chatBridge.send(text)
   ▼
[手环] chat-bridge.js  ── connect.send({ data: { action:"chat", id, text, ts } })
   │
   ▼  ══ interconnect 点对点通道（手环端 EV 必须正在运行）══
   │
[手机] SyncEngine.rx  OnMessageReceivedListener.onMessageReceived(from, byte[])
   │  · 有 pending 请求 → r.onReply(text)        （手机→手环 的回包路径）
   ▼  · 无 pending     → observer.onMessage(text) （手环主动 push 的路径）★本次方向
[手机] MessageActivity.installObserver → handleUnsolicited(ctx, json)
   │  ① CommandRouter.handle(json)  —— 命中工具遥控指令则消费、不进留言流
   │  ② 校验 action=="chat"
   │  ③ markSeen(id) —— 按 id 去重，重复到达直接丢弃（禁止重复提醒）
   ▼
[手机] appendIncoming(dir="in") + alert(响铃 + 震动 [+ 前台弹窗])
   ▼
   留言列表渲染：标签「手环」（见 §5 渲染规则）
```

**一句话**：手环页面 → `chatBridge.send()` → `connect.send({data:{action:"chat",…}})` →（interconnect）→
手机 `SyncEngine` 的 `onMessageReceived` →（无待回包）`observer.onMessage` → `MessageActivity.handleUnsolicited`
→ 去重后入库 + 响铃。

## 2. 手环侧实现 · 发送

### 2.1 核心文件：`ev/class-schedule/src/data/chat-bridge.js`

职责：让 EV 课程表具备**主动**给手机发消息的能力（此前手环只能「被动回包」）。

对外 API：

| 方法 | 用途 |
|---|---|
| `register(connect)` | 由 `app.ux` 的 `initSyncReceiver()` 调用，注入 connect（并顺手挂全局桥） |
| `ready()` | connect 是否已就绪 |
| `send(text)` | 手环 → 手机：发一条聊天留言 |
| `sendCmd(type, params)` | 手环 → 手机：发一条工具箱遥控指令（`action:"cmd"`，不进留言流） |

`send()` 实际发送的报文（**关键**）：

```js
var msg = {
  action: "chat",
  id: String(Date.now()) + "-" + Math.random().toString(36).slice(2, 6), // ⚠️ 每条必须唯一（手机端据此去重）
  text: String(text ?? ""),
  ts: Date.now()
}
c.send({ data: msg })   // 官方约定：data 是 Object；直接发字符串会双重转义
```

### 2.2 调用入口（手环侧，均需**物理点击**）

- `pages/message-inbox/message-inbox.ux` → `doSend(text)`：
  ```js
  var ok = chatBridge.send(t)
  if (!ok) { prompt.showToast({ message: "设备未连接，先在手机端打开 EV 同步" }); return }
  // ok 时把回复写进本页收件箱（from:"watch"），本地即时可见
  ```
- `pages/tools/tools.ux` → `sendChatTest()`：

  ```js
  prompt.showToast({ message: ok ? "已发送，看手机端有没有收到" : "connect 未就绪…" })
  ```

### 2.3 注册点：`ev/class-schedule/src/app.ux` → `initSyncReceiver()`（约 846–970 行）


## 3. 手机侧实现 · 接收

仓库：`ev/ev-schedule-android`（APK 包名 `com.application.watch.classschedule`，与手环端**同包名**；
走 `com.xiaomi.xms.wearable` SDK 的 `MessageApi` + `OnMessageReceivedListener`，**不是** Android interconnect）。

### 3.1 `SyncEngine.java` — 收包入口（213–243 行）

```java
private final OnMessageReceivedListener rx = new OnMessageReceivedListener() {
  @Override public void onMessageReceived(String from, byte[] message) {
    final String text = (message == null) ? "" : new String(message, Charset.forName("UTF-8")); // 载荷=UTF-8 JSON
    main.post(() -> {
      ... 清超时 ...
      Reply r = pending; pending = null;
      if (r != null) { r.onReply(text); pumpNext(); return; }   // 有请求在等 → 是回包
      if (observer != null) observer.onMessage(text);           // ★ 无待回包 → 手环主动 push，交观察者
      ackIfNeeded(text);                                        // 若含 messageId 则回 ACK（投递追踪，与留言无关）
      pumpNext();
    });
  }
};
private Observer observer;
public void setObserver(Observer o) { observer = o; }           // 注册/清除观察者（267 行）
```

### 3.2 `MessageActivity.java` — 观察者安装 + 处理（363–452 行）

```java
static void installObserver(final Activity host) {              // onCreate / onResume 都装（保证弹窗落在可见页）
  SyncEngine.get(host).setObserver(json -> handleUnsolicited(host, json));
}

static void handleUnsolicited(final Context ctx, String json) {
  if (CommandRouter.handle(ctx, json)) return;                  // ① 工具遥控指令先消费
  JSONObject o = new JSONObject(json);
  if (!"chat".equals(o.optString("action"))) return;            // ② 只认 action=="chat"
  String text = o.optString("text");
  String id = o.optString("id");
  if (id.length() == 0) id = "in-" + o.optLong("ts",…) + "-" + text.hashCode();  // 兼容无 id 的老 EV
  if (!markSeen(ctx, id)) return;                               // ③ 按 id 去重（重复到达直接丢弃）
  appendIncoming(ctx, id, text, o.optLong("ts",…));             // ④ 入库
  alert(ctx, text);                                             // ⑤ 响铃 + 震动（+ 前台弹窗）
}

private static synchronized void appendIncoming(...) {
  JSONObject item = new JSONObject();
  item.put("id", id); item.put("dir", "in");                    // ★ dir="in" → 列表标签「手环」
  item.put("text", text); item.put("ts", ts); item.put("status", "sent");
  arr.put(item);  sp.edit().putString(KEY, arr.toString()).apply();
}
```

`installObserver` 在 `onCreate`（115 行）与 `onResume`（138 行）都调用；`onPause` 回落到
`SyncService.installObserverIfEnabled(this)`（125 行）——保证**应用在后台时也能收**。

### 3.3 列表渲染规则（`render()`，约 197 行）

```java
String tag = out ? (sent ? "我 · 已送达" : "我 · 待发送") : "手环";
```

- `dir="out"` → 标签「**我 · 已送达 / 我 · 待发送**」（我发给手环的）
- `dir="in"`  → 标签「**手环**」（手环发来的 ← **本条即本次验收看到的那条**）

## 4. ⭐ 核心实现：为什么必须「三级取用」（本次打通的关键）

### 4.1 问题（真机 100% 复现）

`aiot` 打包时，`app.js` 与每个 `pages/<page>/<page>.js` 各自是**独立的 IIFE + 独立 `__webpack_modules__` 表**。
所以同一个 `src/data/chat-bridge.js` 会被**分别打进两份、互不相干**的副本，**各自**带一个 `var connect = null`。

- `app.ux` 里的 `chatBridge.register(connect)` 只写进了 **app.js 那份** 副本；
- 留言板页 `require("../../data/chat-bridge.js")` 拿到的是 **页面那份** 副本；
- → 页面侧的 `connect` **永远是 `null`** → `send()` 返回 `false` → 页面弹「**设备未连接**」。
- 与手机端状态、通道活性**完全无关**（手机端显示「已连 · 全部已送达」，下行照常）。

**判据（构建产物静态分析，不必上真机）**：

```bash
cd ev/class-schedule
grep -c "CHAT-TX] connect not registered" build/app.js build/pages/message-inbox/message-inbox.js  # 两边各 1
grep -o '"\./src/data/chat-bridge\.js"'   build/app.js build/pages/message-inbox/message-inbox.js  # 各一处模块定义
```

### 4.2 修法：三级取用（取到即缓存）

`src/data/chat-bridge.js` 内 `current()`：

```js
var connect = null
var GLOBAL_KEY = "__evSyncConnect"

function fromGlobal() {            // ② 全局桥：app.ux register 时把 connect 挂到 globalThis/global
  try { if (typeof globalThis !== "undefined" && globalThis[GLOBAL_KEY]) return globalThis[GLOBAL_KEY] } catch (e) {}
  try { if (typeof global   !== "undefined" && global  [GLOBAL_KEY]) return global  [GLOBAL_KEY] } catch (e) {}
  return null
}
function selfAcquire() {           // ③ 兜底：本文件自己取一个 interconnect 实例
  try { var ic = require("@system.interconnect"); if (ic && typeof ic.instance === "function") return ic.instance() } catch (e) {}
  return null
}
function current() {
  if (connect) return connect                       // ① 本副本内 register 注入的
  connect = fromGlobal() || selfAcquire()           // ② → ③
  console.log("[CHAT] connect resolved = " + !!connect)
  return connect
}
```

`register(c)` 里同时挂全局桥：

```js
register: function (c) {
  connect = c
  try { if (typeof globalThis !== "undefined") globalThis[GLOBAL_KEY] = c } catch (e) {}
  try { if (typeof global   !== "undefined") global  [GLOBAL_KEY] = c } catch (e) {}
}
```

发送失败时把 `connect = null`，下次调用重新解析（自愈）。

> 一句话记法：**跨模块共享状态必须走 `globalThis` 或各自 `require` 自取**，
> 不能指望「同一个 `require` 路径 = 同一个模块实例」——在 aiot 多入口打包下**不成立**。

## 5. 消息协议（`chat` 是**双向** action）

| 方向 | 报文 | 说明 |
|---|---|---|
| 手环 → 手机 | `{"action":"chat","id":"<唯一>","text":"…","ts":<ms>}` | 留言本体 |
| 手机 → 手环 | `{"action":"chat","id":"<唯一>","text":"…","ts":<ms>}` | 手机法网留言（手环侧 `syncHandleChatIncoming` 收） |
| 手机 → 手环后，手环回 | `{"ok":true,"action":"chat_ack","id":"…","ts":<ms>}` | **协议层送达确认**（不是内容回复）。手机端收到后把该条 `status` 由 `pending` 改 `sent` → 标签变「我 · 已送达」 |

- **手环 → 手机方向没有 ACK**：手机端收到手环 push 时只做 `ackIfNeeded`（那是给后台投递追踪用的，
  与留言无关）→ 所以 **`chatBridge.send()` 返回 `true` 只代表「已调用发送」，不代表对方已收到**。
- `id` 必须**每条唯一**：手机端据此去重，同毫秒连发两条会撞 id → 第二条被误判重复而漏提醒
  （故 `send()` 用 `Date.now() + "-" + random` 组合）。

## 7. 已知边界与注意事项

- **无 ACK**：手环→手机方向 `send` 成功 ≠ 对方收到（见 §5）。
- **手环 9 无法远程/自动操作**：官方真机调试只支持 Watch S4；社区侧载能装包但无日志/交互回传通路。
  → 手环侧「那一下点击」**必须人工**。
- **手环端 EV 未运行时不自动唤醒**：留言走纯 `sendMessage`，**不拉起**手环 EV；
  若手环端 EV 被系统回收，手机发的留言会卡「待发送」（手环侧也发不出）。需要时用手机的
  「呼叫手环 / 上课了」（带 `launchWearApp` 唤醒）先把 EV 拉回前台。
- **去重是硬要求**：手机端 `markSeen` 按 id 去重，同一条只入库 + 提醒一次。
- **二级页能否当 entry 要逐页试**：`pages/message-inbox` 实测**可以**当 entry 完整渲染；
  但设置类二级页不行（启动即退黑屏）。
