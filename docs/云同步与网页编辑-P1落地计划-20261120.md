## 0. 决策定稿（本轮确认，实现不得偏离）

| # | 决策 | 备注 |
|---|---|---|
| 1 | **云端只写安卓端，不碰手环** | 链条单向：网页 → 云库 → 安卓本地 →（自动/手动）→ 手环 |
| 2 | **上传静默执行，不设用户确认弹窗** | 首次启动一次隐私政策同意；「备份一份」为显式告知锚点 |
| 3 | **对外可见默认关，分享开关本期做** | 默认只有持 token / 已登录者可读；开了 share 才生成公开只读链接 |
| 4 | **登录顺序：只读之后、可编辑之前** | 不做临时长效 token 过渡，写权限从上线第一天就带身份 |
| 5 | **删除只认墓碑，缺记录 ≠ 删除** | 最高优先级，见 §3 |
| 6 | **首次上云以本地为真源** | `rev` 从 1 起，绝不以云端为准，绝不因云端空而清本地 |
| 7 | **自动推手环三时机** | ①App 回前台且 `hasNode()` 为真 ②连接手环成功 ③WorkManager 15 分钟兜底 |
| 8 | **推送前自动存档** | 存 `schedule_versions(reason=pre-push)`，手机端回滚，手环侧只留当前表 |
| 9 | **备份保留策略** | 自动备份保留 7 份（每日 1 份）+ 手动备份不限 |
| 10 | **仅 `source=sync` 且 `watchKey` 非空的课表可上云** | `watchKey = watchMac ?: deviceId`（`mac_random` 机型无 MAC） |

## 1. 数据模型（Supabase）

复用现有项目 `kqzkdpmyivtpxkfmibnd`。**不做行级 courses 表**——一张表几十门课，`payload` 与手机端 `baseJson` 同构，整体替换即可。

```sql
-- 当前态
create table if not exists schedules (
  guid         text primary key,
  watch_key    text not null,              -- mac 或 deviceId，仅归属/可读定位，不做鉴权键
  watch_name   text,                       -- 「小米手环 9 NFC」仅展示
  name         text not null,
  rev          int  not null default 1,
  payload      jsonb not null,             -- 整张课表快照（课程数组）
  public_read  boolean not null default false,
  deleted      boolean not null default false,
  deleted_at   timestamptz,
  ack_rev      int  not null default 0,    -- 安卓端已落盘的最高 rev（回执用）
  ack_at       timestamptz,
  updated_at   timestamptz not null default now(),
  updated_by   text not null default 'android'   -- android | web
);

-- 历史快照（云备份 + 误覆盖回滚 + 推送前存档）
create table if not exists schedule_versions (
  id          bigserial primary key,
  guid        text not null references schedules(guid) on delete cascade,
  rev         int  not null,
  payload     jsonb not null,
  reason      text not null,               -- manual | auto | pre-push | pre-restore
  created_at  timestamptz not null default now()
);
create index if not exists idx_versions_guid on schedule_versions(guid, created_at desc);

-- 编辑凭据（P2 只读链接用；P3 换成 session，表结构保留）
create table if not exists schedule_tokens (
  token       text primary key,            -- 32 字节随机，base64url
  guid        text not null references schedules(guid) on delete cascade,
  scope       text not null default 'read',-- read | edit
  expires_at  timestamptz,
  revoked     boolean not null default false,
  created_at  timestamptz not null default now()
);
```

**约束**：所有读写都经过接口层校验 `token`/`session`，**禁止拿 anon key 直查表**。低敏不等于可以按 guid 遍历拖库。

## 2. 本地待推送队列

复用 `dirty` / `baseJson`，但队列必须**独立落盘**，否则杀进程丢改动。

`SharedPreferences: ev_cloud_queue`

```json
{
  "items": [
    {
      "guid": "…",
      "op": "upsert",            // upsert | delete
      "baseRev": 7,              // 本次改动基于的云端 rev（乐观锁用）
      "payload": { "courses": [...] },
      "attempts": 2,
      "nextAt": 1795000000000,
      "enqueuedAt": 1794999000000
    }
  ],
  "state": {
    "guid": { "lastPushRev": 8, "lastAckRev": 7, "lastError": "", "lastTryAt": 1795… }
  }
}
```

规则：

- **合并**：同一 `guid` 已有 `upsert` 待推时，新改动覆盖旧项（只推最新态），`baseRev` 保留最早的一个；
- **重试**：指数退避 30s → 2min → 10min → 1h，上限 24h；**全程不弹提示**；
- **条件**：该 `guid` 的 `cloudEnabled == true`（用户点过「网页大屏编辑」或「备份一份」）才入队；其余表零请求；
- **离线**：无网时不发请求、不报错、不阻塞，队列继续积压。

## 3. 删除与冲突协议（最高优先级）

| 情形 | 判定 | 动作 |
|---|---|---|
| 本地有、云端无记录（首次开通 / 断网新建） | 云端还没收到 | 上传新建，`rev` 从 1 起，**绝不动本地** |
| 云端 `deleted=true`，本地活数据，且本地 `baseRev` < 云端 `deletedRev` | 删除是较新意图 | 本地进「回收站」保留 30 天，不物理消失 |
| 云端 `deleted=true`，但本地在删除后又有编辑（`baseRev` 覆盖 tombstone 之后） | 复活 | 上传活数据 `rev+1`，清 tombstone |
| 两边都活、`payload` 不同 | 并发编辑 | `If-Match: rev` → 409 → 字段级合并；重叠字段交用户选 |
| 云端返回 404 / 空 | **不做任何删除推断** | 视为「云端无此表」，按第 1 行处理 |

**三条铁律**：

1. 服务端缺失记录 **永不**被解释为删除；
2. 行不物理删除，墓碑至少留 30 天；
3. 首次开通云同步 **一律以本地为真源**全量上传。

## 4. 接口形状

统一前缀 `https://app-auth.gudq.com/api/sched`，鉴权 `Authorization: Bearer <token|session>`。

| 方法 | 路径 | 作用 | 关键字段 |
|---|---|---|---|
| POST | `/publish` | 开通某张表的云同步（一次性） | `{guid, watchKey, watchName, name, payload}` → `{rev, token, url}` |
| POST | `/push` | 静默上传（队列消费） | `{guid, op, baseRev, payload}` + `If-Match: <rev>` → `{rev}` / 409 `{rev, payload}` |
| GET | `/pull` | 拉取最新态 | `?guid=` → `{rev, payload, updatedBy}` |
| GET | `/state` | 三级回执 | `?guid=` → `{rev, ackRev, ackAt, publicRead, updatedAt}` |
| POST | `/ack` | 安卓端上报「已落盘到本地」 | `{guid, rev}` |
| POST | `/share` | 分享开关 | `{guid, publicRead}` → `{url?}` |
| POST | `/backup` | 手动备份一份 | `{guid, reason}` → `{id}` |
| GET | `/versions` | 版本列表 | `?guid=&limit=20` |
| POST | `/restore` | 恢复到某版本 | `{guid, versionId}` → 写 `schedules` 且 `rev+1` |

回执三级（网页端只读不猜）：`saved`（rev 已增）→ `delivered`（`ackRev == rev`）→ `applied`（安卓端上报已推手环，事实陈述非保证）。

## 6. 隐私与分享

- 首次启动：一次隐私政策同意（之后永不再现），正文写明「课程表数据会同步至云端，用于多端查看与备份」；
- 上传：静默、无提示、失败无提示；
- 可见性：`public_read` 默认 false；用户主动「分享」才生成只读链接，可随时关闭；
- 未成年人数据：不额外收集身份信息；云端只存课表本身，不存学生姓名以外的可识别字段（课表内的教师/班级以用户输入为准，不做增强）。

## 7. 验收清单（P1 完成判据）

1. 断网编辑一门课 → 无任何报错/弹窗 → 恢复网络后自动补推，云端 `rev` 正确；
2. 云端手动删掉某行记录 → 手机端同步后 **本地课表不受影响**（缺记录不当删除）；
3. 本地删一门课 → 云端出现 `deleted=true` 且 `payload` 保留（墓碑），30 天内可恢复；
4. 首次开通某表云同步 → 云端 `payload` 与本地逐字段一致，`rev=1`；
5. 未开通云同步的课表 → 抓包确认零请求；
6. 「备份一份」→ `schedule_versions` 新增 `reason=manual`；恢复后 `rev+1` 且内容等于快照；
7. `public_read=false` 时，外人用同 URL 打开只能看到「未分享」，拿不到数据；
8. 网页保存后手机端 `ackRev` 追上 → `/state` 返回 `delivered`。
