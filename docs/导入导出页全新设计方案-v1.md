# 导入 / 导出页 全新设计方案 v1

> 对象：`TransferActivity`（1164 行）——**一个 Activity 承载两个模式**（`MODE_IMPORT` / `MODE_EXPORT`，由 `EXTRA_MODE` 切换）。
> 入口：首页 ⊕ →「导出课程 / 导入课程」；课表库 ⊕ →「导出课程表 / 导入课程表」。
> 设计语言：`Ui.java` 权威 token（字号 22/17/16/15/13/11.5/10.5；圆角 14/12/4；间距 4/8/12/16；热区 44dp）。
> 本方案**零新增 token**，且顺带消灭本页全部越界字号。

---

## 一、一句话诊断

> 导入导出页不是「功能没做」，而是**把一条流程拆成三张等权卡、把结果写在离按钮最远的地方、并且全页没有用过一个设计 token**。

本页是全系列**唯一 `SP_` 使用数 = 0** 的一页 —— 所有字号、间距都是裸写的魔数，其中 `12.5f / 12f / 11f` **三个值根本不在 7 档字号内**（共 12 处）。它同时也是**继高级版之后第二处没执行「反馈就地化」**的页面。

## 二、现状诊断（H1–H12）

| # | 发现 | 代码位置 | 为什么致命 |
|---|---|---|---|
| **H1** | **零 token 化**：全页 `SP_*` / `GAP_*` / `R_*` 使用数 **= 0**；字号全是裸写的 `12.5f / 12f / 11f / 13f / 11.5f` | 全页 | `12.5f`(6 处) / `12f`(5 处) / `11f`(1 处) **不在 7 档内**。前几页各只有 1 处越界，本页一口气 **12 处**——设计语言的事实性崩塌 |
| **H2** | **两条反馈通道互相打架**：`infoView`（人类可读，**约 18 种语义**）+ `resultView`（原始 JSON 回包） | `infoView` 写点 ~19 处 / `resultView` 写点 ~16 处 | 用户同时看到「导入成功，共 12 门课」和一大坨 `{"ok":true,...}` 原文，不知道哪个是结论 |
| **H3** | **反馈长在页面最底部，按钮在中上部** | 导入页 `infoView:296`/`resultView:299` 在最后；触发它的「解析并预览」在 `:240` | 点完看不到回应，用户重复点。**设置页/高级版刚确立「反馈就地化」，本页是唯一还没做的一页** |
| **H4** | **一个动作三个按钮都叫「读取」** | 导出页「重新读取清单」`:175`、「读取当前课表」`:178`、「读取该课程表数据」`:192` | 三个都在读，语义无从分辨；且「读取当前课表」与「读取该课程表数据」调的是同一个 `readFromBand()`，只有 `selectedIndex` 之差 |
| **H5** | **一条流程拆成三张等权白卡** | pick `:160` / read `:188` / exportCard `:199` | 「选课表→读数→导出」是一件事的三步，却各占一张平级卡；首屏两张卡都在说「读取」，真正要导出的内容被挤到第三屏 |
| **H6** | **危险动作与安全动作并排等权** | `:211-217`「复制 JSON」(安全) 与「更新到手环」(**覆盖手环当前课表**) 同用 `Ui.grid` | 破坏性写操作与只读操作视觉权重完全相同，误触代价是覆盖手环课程 |
| **H7** | **`ConnectionBar` 残留** | `:125` | 全项目只剩 **2 个使用点**（本页 + `ThemePickerActivity:40`）；手环页 / 课表库 / 高级版均已删除 |
| **H8** | **`Ui.mono` 四段工程师说明** | `:219` `:226` `:267` `:302` | 其中 `JSON_SPEC_HINT`（`:106-109`）是 3 行字段规范，把操作页当 API 文档用 |
| **H9** | **死代码 `pasteToBox()`** | `:661` 定义，**全项目 0 个调用点** | 「剪贴板→粘贴框」能力早由 `JsonEditorView` 内置工具栏接管，这段 18 行代码永远不会执行 |
| **H10** | **`showSaveButton()` 靠遍历子 View 找按钮** | `:680-692` 按文本 `"保存到下载目录"` 反查，用 `root.getChildCount() - 2` 插入 | 按钮出现的位置取决于布局结构，改一下卡片顺序就错位；且「保存」按钮**只有读取成功后才有**，用户事前不知道导出会落在哪 |
| **H11** | **预览列表里「字段完整」不可见** | `:844-861` 完整与不完整项**套同一个格式**，只在缺字段时写「（缺 name）」 | 用户必须逐条读文字才知道哪几门有问题；`previewInfo` 只说「其中 N 门完整」 |
| **H12** | **名称输入在流程中间、报错在页脚** | `nameCard:257` 夹在 paste 与 preview 之间；报错「请先填写课程表名称」写在 `:879`（页底 `infoView`） | 用户按下导入才发现没填名，而提示在屏幕最下方 |

另外：导出页标题 `"手环上的课程表（选择要导出的那一套）"`（`:161`）是长句内嵌括号，不是标题写法；导入页「生成示例课表」（`:243`）是开发自测功能，却与主按钮并排等权。

## 三、设计原则（P1–P6）

| # | 原则 | 说明 |
|---|---|---|
| **P1** | **一个页面一条主动线** | 导出 = 选表 → 读 → 导出；导入 = 贴 → 预览 → 写回。每步一张卡，步与步之间有先后，不并列。 |
| **P2** | **反馈就在手指边** | 结果条长在**触发它的那张卡内部**；瞬时动作按钮自反馈。页面级两个反馈 View 全部删除。 |
| **P3** | **破坏性动作必须离手** | 「覆盖手环课表」类动作**不与其他按钮并排**，单独一行、靠下、`ERR` 色描边，且保留二次确认。 |
| **P4** | **状态只说一遍** | 连接状态全页唯一一处；未连接时用引导卡（含「去连接」），已连接时**不占位**。 |
| **P5** | **正文不承担文档职责** | 字段规范、导出位置、同名检测规则 → 顶栏 ⋯ 弹层；页面只留一句必要的短提示。 |
| **P6** | **零新增 token** | 所有字号/间距/圆角回到 `Ui.java` 既有档位，并顺手消灭 12 处越界字号。 |

## 四、设计决策（D1–D10）

### D1 —— 删 `ConnectionBar`，改为「未连接引导卡」

- 已连接：**不显示任何连接状态**（顶栏之下直接是内容卡）。
- 未连接：顶栏下方一张 `CARD2` 引导卡 —— 8dp `WARN` 点 + 「手环未连接」+ 副文案「导入与导出都需要手环在线」+ 右侧「去连接 ›」。
- 对应 H7、P4。删掉后 `ConnectionBar` 全项目只剩 `ThemePickerActivity` 一个使用点（建议后续单独收口）。

### D2 —— 删 `resultView`，反馈就地化

- **删除**页面级 `resultView`（`:223` / `:299`）与其全部写入点。
- `infoView` 一分为 N：**每张卡各自持有自己的结果条**（`CARD2` 底、`R_CTRL` 圆角、`SP_CAPTION 11.5f`），4 级语义：

  | 级别 | 色 | 用法 |
  |---|---|---|
  | 进行中 | `MUTED` + 转圈文案 | 「正在读取清单…」 |
  | 成功 | `OK` | 「已读取 3 套，当前激活：秋季课表」 |
  | 警告 | `WARN` | 「清单读取超时，可点下方直接读取当前课表」 |
  | 错误 | `ERR` | 「没能读出清单：<原因>」 |

- **永久隐藏**原始 JSON 回包（`resultView.setText(json)`）——那是开发者诊断信息，不是给用户的结论。
- 对应 H2、H3、P2。

### D3 —— 导出页：三卡 → **两卡**（选表 / 导出）

```
[卡1 选择要导出的课表]                 ← pick + read 合并
  · 「选择要导出的课表」标题 + 副文案「手环上共 N 套 · 当前使用中：X」
  · 单选清单（当前激活行带「使用中」徽标）
  · 卡内结果条
  · 主按钮 [读取选中的课表]   ← 唯一读取入口
  · 清单读取失败时，同一按钮文案自动变 [直接读取当前课表]（兜底，不再另设按钮）
[卡2 导出内容]                          ← 读完才出现
  · 标题「导出内容」+ 副文案「N 门课 · 读取于 04:52」
  · JSON 编辑区（等宽 SP_MICRO 10.5f）
  · [复制 JSON] (主)   [保存为 JSON 文件] (主)
  · ─── 分隔线 ───
  · [更新到手环]（ERR 色描边，单独一行，破坏性）
```

- 「重新读取清单」降为卡1标题右侧的 ↻ 图标（44dp 热区）。
- 对应 H4、H5、H6、H10。

### D4 —— 导出动作三选一，权重分明

| 动作 | 类型 | 位置 | 样式 |
|---|---|---|---|
| 复制 JSON | 只读 | 卡2 主按钮区 | `ACCENT` 实心 |
| 保存为 JSON 文件 | 只读 | 卡2 主按钮区 | `ACCENT` 实心 |
| 更新到手环 | **破坏性写** | 卡2 底部独立一行 | `ERR` 描边 + 保留二次确认 |

「保存到下载目录」不再动态插入，**固定出现在卡2**；导出位置说明（`下载 / EVSync`）写进卡2 副文案一行小字，不另起 `Ui.mono`。
对应 H6、H10、P3。

### D5 —— 导入页：名称输入下移到预览卡，紧邻导入按钮

```
[卡1 课程 JSON]
  · 「课程 JSON」标题
  · JsonEditorView（含内置工具栏）
  · 卡内结果条
  · [解析并预览] (主)   [选择文件] (描边)
[卡2 预览与导入]                          ← 解析成功才出现
  · 标题「待导入 N 门」+ 副文案「其中 M 门字段完整；缺字段的已标黄」
  · 课程列表（勾选框 + 课名 + 星期·时间 + 教室/老师）
      · 字段缺失 → 该行文字用 WARN 色 + 行首 ⚠ 标记
  · [全选] / [全不选]（小字文字链，不再占两个大按钮）
  · ─── 分隔线 ───
  · 「课程表名称（必填）」输入框        ← 从卡外移到此处
  · [导入到手环]（ERR 色描边，破坏性 + 二次确认）
```

- 对应 H11、H12。
- `confirmImportSelected()` 的「未填名」校验失败时，错误就地显示在**名称输入框正下方**，不再写到页脚。

### D6 —— 「生成示例课表」收进顶栏 ⋯

开发自测用功能，不该与主按钮并排。移入顶栏 ⋯ →「生成示例数据（自测用）」。

### D7 —— `Ui.mono` 四段拆解

| 原文 | 去向 |
|---|---|
| `JSON_SPEC_HINT`（`:219`，3 行字段规范） | 顶栏 ⋯ →「字段说明」弹层 |
| 「导出结果保存到「下载 / EVSync」」（`:226`） | 卡2 副文案一行（`SP_MICRO`） |
| 「导入时会先检查手环上是否已有同名课程表」（`:267`） | 删除（导入确认弹层已说明「同名将覆盖」） |
| 「必填：name + day + time / 覆盖提示」（`:302`） | 顶栏 ⋯ →「字段说明」弹层第二段 |

对应 H8、P5。

### D8 —— 顶栏 ⋯ 唯一信息入口

导入 / 导出两模式的顶栏右侧统一为 **⋯**，弹层内容随模式不同：

- **导出**：字段说明 · 导出到哪 · 手环需要什么版本
- **导入**：字段说明 · 覆盖与备份说明 · 生成示例数据（自测用）

对应 D6、D7。

### D9 —— 删死代码 `pasteToBox()`

`:661-678` 全项目 0 调用点，随本轮一并删除（能力已由 `JsonEditorView` 工具栏覆盖）。
对应 H9。

### D10 —— 字号全量 token 化

| 现值 | 出现 | → 目标 | 说明 |
|---|---|---|---|
| `12.5f` | 6 处 | `SP_BODY 13f` | 卡标题（与设置页行标题同级） |
| `12f` | 5 处 | `SP_CAPTION 11.5f` | 清单加载态 / 结果条 |
| `11f` | 1 处（`exportBox:205`） | `SP_MICRO 10.5f` | 等宽 JSON 正文 |
| `13f` | 3 处 | `SP_BODY 13f` | ✅ 已合规 |
| `11.5f` | 2 处 | `SP_CAPTION 11.5f` | ✅ 已合规 |

对应 H1、P6。

## 八、取舍与边界

| # | 取舍 | 理由 |
|---|---|---|
| **R1** | **保留「复制 JSON」与「保存为文件」双出口** | 两者都是真实主路径：复制给 AI 整理 / 存盘留档。不合并。 |
| **R2** | **「更新到手环」不藏进 ⋯** | 它虽是破坏性操作，但**是导出页的正当用途之一**（导出→改→写回）。藏起来会让功能不可发现；改为「独立一行 + ERR 描边 + 二次确认」。 |
| **R3** | **清单读取失败时不新设按钮** | 复用主按钮改文案（「直接读取当前课表」），避免 H4 那种「三个读取按钮」。 |
| **R4** | **`JsonEditorView` 不动** | 它是编辑 / 新建 / 导入三处复用的共享组件，本轮只调整它在卡内的位置与行数，不改其内部。 |
| **R5** | **导入页保持「解析后才出现名称输入」** | 有用户会先贴 JSON 再想名字；也有用户已想好名字。放预览卡内 = 两者都只需一次滚动。 |
| **R6** | **两模式仍共用一个 Activity** | 保持 `EXTRA_MODE` 分发结构不变，落地只在 `buildImport` / `buildExport` 两个方法内动刀。 |
