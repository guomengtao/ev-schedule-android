# EV 课程表「中文输入黑屏 + 完成键闪烁」根因分析报告

> 单号：`evtask-D-evclass-sche-261017-w4w2dc` · 花名：定盘星⭐ · 日期：2026-10-17
> 对象：ev-schedule-android（手机端 APK）· 机型：华为荣耀 BLN-AL10（EMUI）
> 方法：代码级深挖（全量 grep + 行级取证）。**真机当前离线，第五节附待真机验证方案**；所有结论标注了代码行号，可逐条复核。

---

## 一、故障现象（按用户原话拆解）

| 用户描述 | 技术定位 |
|---|---|
| 「中文输入」 | 输入法处于中文模式（拼音组合输入 / composing text 阶段） |
| 「任何页面进入输入法后」 | 与具体页面无关的**共性机制**（全 App 16 个输入框、15 个 Activity 同配置） |
| 「点击键盘某个键的时候，黑屏」 | 按键瞬间 App 窗口 surface 被销毁或被 IME 窗口接管 |
| 「'完成'按钮在闪烁」 | **不是 App 的按钮**——全代码 grep `"完成"` 为 0 处；这是**输入法键盘右下角的 IME action 键**在反复重绘 |

两条症状合并指向同一个方向：**App 窗口与输入法（IME）窗口的层级/附着关系被反复重建**。黑屏是"重建的空档"，闪烁是"重建的动作"。

## 二、共性配置取证（为什么"任何页面"都中招）

对全部源码与清单的量化扫描结果：

| 扫描项 | 结果 | 说明 |
|---|---|---|
| EditText 创建点 | **16 处**（Toolbox×3 / JsonEditor / Band×2 / Debug / CourseSheet / FastActivate×4格 / Message×2 / CourseEdit / Home / Transfer×2） | 输入面很广 |
| `setImeOptions` / `imeOptions` | **0 处** | 无一处设置 `IME_FLAG_NO_EXTRACT_UI` |
| `setInputType` | 仅 4 处（时间类 3 + 激活码格 1） | 其余 12 个输入框未限定输入类型 |
| Activity 的 `windowSoftInputMode` | 6 处 `stateAlwaysHidden\|adjustResize`，**11 处仅 `stateAlwaysHidden`** | 配置分裂，见 H1 |
| onResume 主题 recreate 检测 | **15 个 Activity 全部有**（`lastThemeVersion != Ui.themeVersion → recreate()`） | 见 H2 |
| App 内"完成"按钮 | **0 处** | 用户所见"完成"= 输入法的键 |

**结论：这不是某个页面的 bug，是全局默认配置缺失 + 一个跨页面隐患链的共同结果。**

## 三、根因假设（按代码证据强度排序）

### H1（主嫌）：全量缺失 `IME_FLAG_NO_EXTRACT_UI` + 软键盘模式分裂 → 中文输入法 extract 窗口接管

**机制**：Android 输入法在特定条件下会进入**全屏提取模式（fullscreen extract mode）**——用输入法自带的编辑窗口**整体接管屏幕**（App 界面被盖住，视觉上就是"黑屏/页面消失"），该窗口自带一个大编辑区和**"完成"按钮**。竖屏单行框通常不触发，但以下条件会显著提高触发率：

1. **未设 `IME_FLAG_NO_EXTRACT_UI`**（本 App 16/16 处缺失）——系统允许输入法自行决定是否 extract；
2. **多行输入框**：MessageActivity `setMaxLines(4)`（:193）、JsonEditorView、Toolbox 输入栏——多行是 extract 的高发条件；
3. **`windowSoftInputMode` 不含 `adjustResize` 的 11 个页面**——窗口不做 inset 协商，部分 ROM（EMUI 尤甚）的输入法在按键/切换中英文/开符号面板时走"重建窗口"路径，表现为 surface 销毁重建 → 黑屏一瞬 + 键盘重绘（完成键闪烁）；
4. **华为 EMUI 输入法**对 extract 与 inset 的处理与 AOSP 有差异，本机型（BLN-AL10）正是高发环境。

**解释力**：完整覆盖"中文输入 + 点键 + 黑屏 + 完成按钮"四要素，且"任何页面"成立（配置缺失是全局的）。**优先级最高。**

### H2（代码级隐患链）：`themeVersion` 被 Widget 后台刷新推高 × onResume recreate 检测 → 输入法相关生命周期事件触发窗口重建

这条链是本报告在代码里**实际挖到的缺陷**，可独立解释"按一下键黑屏闪一下"（一次性 recreate，非常年黑屏）：

```
① WidgetProvider.onUpdate（周课表/下节课/今日 三个桌面小部件）
     → Ui.applyTheme(ctx)（WeekWidgetProvider:68 / NextWidgetProvider:45 / TodayWidgetProvider:57）
     → themeVersion++（Ui.java:219，每次调用无条件自增）
② 时钟类 widget 分钟级刷新 / 手环主题同步（"跟随手环"开启时 WatchAppearance → applyTheme）
     → 用户无感知，但 themeVersion 已静默变化
③ 中文输入过程中，输入法弹出/切换面板/点按键会间接引起 Activity onPause→onResume
     （EMUI 上输入法窗口事件更容易触发生命周期抖动）
④ onResume 检测：lastThemeVersion != Ui.themeVersion → recreate()（15 个 Activity 同款代码）
     → 窗口销毁 + 重建 = 黑屏；键盘随新窗口重新附着 = 完成键位置/状态重绘闪烁
```

**佐证**：`recreate()` 后新实例 `lastThemeVersion=0`，首次 onResume 只记录不 recreate——所以现象是**单次闪烁**而非无限循环，与用户"点某个键的时候黑屏"（一次性）吻合。

**解释力**：强。它不需要输入法 extract，仅凭"输入法引起的生命周期抖动 + 后台 themeVersion 漂移"就能制造完全相同的视觉症状。**与 H1 可能同时成立、互相叠加。**

### H3（次要）：中文组合输入与自定义输入组件的摩擦

- `FastActivateActivity:670-699` 四格输入框：有 `distributing` 防 `setText` 递归，但 `onTextChanged` 里 `s.length()>1 → distribute()` + `requestFocus()` 跳格逻辑对中文 composing 期间的文本变化模式未做适配——可能出现焦点错乱跳格（**解释不了黑屏**，仅列入）；
- `JsonEditorView.setOnChangeListener`（:321）：JSON 实时校验在中文组合期高频触发，校验态闪烁（非黑屏）。

### H4（待排除）：输入法自身问题

华为/第三方中文输入法在 EMUI 上的已知渲染 bug 类别。**零成本二分法：换 Gboard 复现对比**——若换输入法即消失，则 H1/H2 退居次要。

## 六、修复建议（分级，P0 可立即执行）

### P0——IME 配置规范化（治 H1，低风险，建议随下一版发出）

1. **所有 EditText 统一封装**：在 `Ui.java` 增加 `Ui.editText(ctx)` 工厂方法，内部统一：
   ```java
   e.setImeOptions(EditorInfo.IME_FLAG_NO_EXTRACT_UI
           | EditorInfo.IME_ACTION_NONE);        // 禁用输入法全屏提取模式
   ```
   逐步替换 16 处裸 `new EditText(...)`（MessageActivity:186/1000、ToolboxActivity:173/235/241、TransferActivity:417/511 优先）。
2. **Manifest 统一软键盘模式**：11 处纯 `stateAlwaysHidden` 的 Activity 一律补成 `stateAlwaysHidden|adjustResize`（与现有 6 处对齐），消除 inset 协商分裂。

### P1——斩断 recreate 隐患链（治 H2，本报告核心发现）

3. **`Ui.applyTheme` 的 `themeVersion++` 改为"内容变了才自增"**（Ui.java:219）：调色板与上次完全相同时返回 false、不自增——widget 分钟级刷新不再制造"假主题变化"；
4. **Widget Provider 的 applyTheme 调用去重**：widget 走 `Context`（非 Activity），不需要 `setTheme`，可在 applyTheme 内对非 Activity Context 跳过版本自增；
5. **onResume recreate 检测加防抖**：15 处同款检测增加"上次 recreate 距今 >30s 才再检测"之类的抑制，防止生命周期抖动窗口内的连环重建。

### P2——输入组件加固（治 H3）

6. `FastActivateActivity` 四格显式声明"仅接受大写字母数字"的 InputFilter 语义已有（AllCaps），补一层 `TYPE_TEXT_FLAG_NO_SUGGESTIONS` 的说明注释即可，优先级低；
7. `JsonEditorView` 的 onChange 加 200ms 节流，避免中文组合期高频校验闪烁。

## 七、结论

1. **"完成"按钮不是 App 的**——是输入法的 IME action 键；症状本质是 **App 窗口与输入法窗口的反复重建**。
2. **H1（imeOptions 全量缺失 + 软键盘模式分裂）是主嫌**，完整解释四要素且"任何页面"成立；
3. **H2 是代码里实际挖到的隐患**：`applyTheme` 无条件 `themeVersion++`，被三个桌面 widget 的后台刷新持续推高，叠加 15 个 Activity 的 onResume recreate 检测——输入法引起的生命周期抖动即可点燃，症状与用户描述逐条吻合；
4. H3/H4 为次要/待排除项，第五节判别矩阵 + 真机验证方案可在 BLN-AL10 上线后**半天内定案**；
5. **修复成本很低**：P0 是一个工厂方法 + 11 行 Manifest；P1 是三处小改动。不需要动架构。
