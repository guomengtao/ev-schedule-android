# 课表套数不一致分析（导出 7 套 / 首页 3 套）

> 2026-09-29 · 状态：分析 + 首页口径已修正 · 用户期望：**显示手环真实套数，不是本地**

## 一、现象

| 页面 | 显示 | 数值来源 |
|---|---|---|
| 导出（在线） | 7 套 | ✅ 手环真实：`list_schedules` 返回的清单长度 |
| 首页迷你条 | 手环课表 3 套 | ❌ 本地镜像：`ScheduleStore` 里 source=sync 的条数 |
| 课程表管理「手环课表」组 | 3 套 | ❌ 同上（本地镜像） |

## 二、根因：三个页面三种数据源

1. **导出页（在线）**：每次都向手环要清单（`list_schedules`）→ 手环真实套数。
2. **首页/课程表管理**：统计的是 **ScheduleStore 本地镜像**里 source=sync 的条目数。
   本地镜像只会包含「被拉取过」的课表——手环上 7 套里只有 3 套被拉到过本地，
   所以本地永远是 **手环的子集**（4 套从未导出过的课表本地根本不知道）。
3. 深层原因：手环上有 7 套课表，多半是导入测试期间累积的（生成示例课表 → 导入 → 手环上越攒越多），
   从来没有清理过。

## 三、口径修正（已实施）

- **权威数据源**：`list_schedules`（手环真实清单）。SyncEngine 新增
  `bandScheduleCount`（最近一次清单读取的 names.length，-1=未知），三处刷新：
  1. 首页连接成功后的拉取流程（本来就要 list_schedules 拿课表名）；
  2. 其他页面自动重连成功后的 `pullAndStore`（同样走 list_schedules）；
  3. `refreshBandScheduleCount()`（需要时主动要一次，静默）。
- **首页迷你条**：连接成功后显示 `手环课表 {真实套数} 套`；清单还没读回来时
  先显示本地镜像数并标注「以手环为准」，清单一到就刷新（状态回调驱动）。

## 四、仍存在的口径差异（有意保留 / 待定）

| 位置 | 口径 | 说明 |
|---|---|---|
| 导出页（在线） | 手环真实 | 权威，不变 |
| 首页迷你条 | 手环真实（连接后） | 已修正 |
| 导出页（离线） | 最后已知（上次清单缓存/本地镜像） | 断网时不可能知道手环现状，标注「上次连接时」 |
| 课程表管理「手环课表」组 | 本地镜像 | 卡片操作（编辑/删除/同步）的对象是**本地条目**，保持镜像合理；可加一行「手环上共 N 套」提示（未实施） |

## 五、建议：清理手环上的测试课表

手环 7 套里有多套是测试/随机课表（大学随机课表等），建议在手环 EV 上删到只剩真实使用的，
套数口径自然干净。App 侧「从手环删除」仍未开放（需手环端支持）。

## 六、不做

- 不在首页/状态条做实时轮询套数（每次心跳都多一次往返）——连接/重连时刷新一次足够。
- 不把课程表管理的卡片列表改成手环真实清单（操作对象是本地条目，改了语义就乱了）。
