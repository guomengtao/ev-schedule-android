- 页面：底栏「课表」→ `ScheduleListActivity` → 分组内标记「使用中」的当前课表主卡
- 状态：待修复（本记录先于代码改动落盘）

## 一、现象

当前课表主卡（截图中「示例课表（本地）」）是一个圆角矩形，左边缘有一条 4dp 主色（`Ui.ACCENT`）竖条。竖条的**上端与下端保持直角**，没有跟随卡片的 `R_CARD` 圆角收口：在卡片左上角、左下角各顶出一个蓝色小尖角（像两根小刺），并在色条与卡片轮廓之间留下一道细白缝。

对照：底栏「首页」里的课程块（高 / 数 / 大 / 线 / 程 / 体 …）同样是「浅底圆角块 + 左侧 4dp 身份色条」，其色条端头平滑沿圆角收口，**无尖角**。两处视觉设计同构，表现不一致。

证据截图（改前）：

- `apk/shots/deploy-v0.6.8-schedule.png`（2026-11-05 19:45，课表页，可见左上 / 左下尖角）
- `apk/shots/deploy-v0.6.8-home.png`（同期首页，色条正常，作为正确范例）

## 二、复现

1. 打开同步器 → 底栏「课表」。
2. 至少存在一套课表且已被设为「使用中」（当前课表）。
3. 观察当前课表主卡左缘色条的上下两端。
4. 放大 4× 看圆角过渡处，可见两个直角小刺 + 一道浅色缝。

非当前课表（次卡）没有竖条，不触发。

## 三、根因

三层叠加：

1. **形状不同心**：卡片是 `R_CARD` 圆角 + 1dp 主色描边；竖条是独立的 `View`，`setBackgroundColor(Ui.ACCENT)` + 宽 4dp / 高 `MATCH_PARENT`，是一个**纯直角矩形**。
2. **依赖父容器轮廓裁剪**：现有实现想用 `card.setClipToOutline(true)` + 自定义 `ViewOutlineProvider.setRoundRect(...)` 把直角竖条裁出圆角。这条路径在本项目不可靠：
   - `ViewGroup` 的 outline 裁剪对子 View 是否生效，依赖硬件加速与系统版本；
   - `setClipToOutline(true)` 在 `setOutlineProvider()` **之前**调用，替换 outline 提供器后不保证重建裁剪；
   - 背景 `GradientDrawable` 的描边画在轮廓内侧，竖条画在子 View 上，两者抗锯齿边缘不完全重合。
   
   结果：竖条端头在圆角处**溢出卡片轮廓**，形成两个尖角。
3. **绕过了唯一入口**：`docs/EV-UI-Android-v1.md` 的「色条实现（v1.3 硬约束）」规定色条必须走 `Ui.CourseBlockDrawable` 的 `色条矩形 ∩ 卡片圆角轮廓`（`Path.op(INTERSECT)`）。但该约束表格只写了「课程块底」，`ScheduleListActivity` 据此认为自己拼一张课表卡片不受约束，于是用了「子 View + clip」的旧思路 —— 属于**规范覆盖不到位的漏网实现**。

## 五、修复方案（与首页同构）

唯一原则：**色条不作为一个独立的 View 存在，而是画进卡片自己的背景 Drawable 里**，用 `Path` 交集让「左侧 4dp 矩形」与「卡片圆角轮廓」求交，端头必然沿圆角收口。

1. `Ui.java`
   - `CourseBlockDrawable` 构造器重载，支持传入 `radiusDp / barDp / strokeDp`（原 `courseBlockBg()` 行为不变）。
   - 新增公开唯一入口 `Ui.stripCardBg(c, fill, barColor, strokeColor, radiusDp, barDp, strokeDp)`。
2. `ScheduleListActivity.scheduleCard()`
   - 当前卡背景由 `Ui.round(...)` 改为 `Ui.stripCardBg(...)`：fill = `Ui.CARD`、bar / stroke = `Ui.ACCENT`、radius = `Ui.R_CARD`、bar = `Ui.COURSE_BAR_DP`、stroke = 1dp。
   - 删除 `setClipToOutline` / `ViewOutlineProvider` 与竖条子 `View`。
   - `inner` 左内边距统一为 `Ui.GAP_MD`（色条改由背景绘制后不再占布局宽度，保证当前卡与次卡标题左缘仍严格对齐）。
   - 次卡保持 `Ui.round(Ui.CARD, Ui.R_CARD, Ui.LINE, this)` 不变。
3. `docs/EV-UI-Android-v1.md`
   - 「色条实现」硬约束的适用范围由「课程块」扩到**所有「圆角卡 + 左色条」**，唯一入口补 `Ui.stripCardBg`，并明确禁止「竖条子 View + `clipToOutline`」。
   - 追加修订记录一行。

### 为什么不继续给 clipToOutline 打补丁

调整 provider 调用顺序、或给竖条单独设圆角 drawable，都仍是「两个形状事后拼合」：4dp 宽的 `GradientDrawable` 圆角半径会被 clamp 到半宽（2dp），永远比 `R_CARD`（≈12dp）更方，端头必然顶出轮廓；而 clip 又依赖运行时渲染路径。只有把两个形状放进**同一个 Drawable、同一次绘制**里做几何交集，才是与分辨率 / API / 硬件加速无关的解。
