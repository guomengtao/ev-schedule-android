# 「课程表」栏目精细优化方案（Ev课程表同步器 · App 端）

> 对象：`ev/ev-schedule-android/apk/` 的底部导航「课程表」Tab = `ScheduleListActivity`
> 基线：v0.5.99 源码（2026-10-03 摸底）· 上游定位文档：`docs/apk-positioning-sync-vs-course-table.md`
> 目标形态（已定）：**手环课表的手机端管理器** —— 手环为真源，本机做分组缓存与编辑
> 本文只做「课程表」栏目本身的精细优化，不动协议、不动其它 Tab

---

## 一、结论先说：Top 5 该修的

| # | 问题 | 一句话 | 严重度 |
|---|---|---|---|
| 1 | **自动拉取全程无感知** | 手环有新课表时静默补入，无 loading、无成功/失败提示、失败无重试入口 | 🔴 |
| 2 | **设备分组靠 `startsWith` 猜** | 组名与手环名前缀匹配来归组，同名/前缀重叠就串组 | 🔴 |
| 3 | **整页 removeAllViews 重建** | 切激活/展开收起/状态回调都全量重建，闪烁且丢滚动位置 | 🟠 |
| 4 | **ScheduleStore 吞掉一切异常** | 存储损坏时用户无感知，表现为课表列表静默清空 | 🟠 |
| 5 | **「从手环删除」缺位** | 只能删本地记录，手环侧课表删不掉，管理器名不副实 | 🟠 |

## 二、现状快照（优化前必须知道的事）

### 2.1 页面结构（`ScheduleListActivity.buildUi()` :92-181）

```
topBar「课程表管理」(:94)
 └ ConnectionBar 连接状态条 (:95-96)
 └ 副文案 (:99-100)
 └ syncView   同步状态条：「N 门课未同步 · 点此同步 / 已同步 ✓」(:104-120, 502-525)
 └ deviceBar  设备条：「● 在线 · 手环名 ··后4位」点击展开当前设备分组 (:124-150, 264-289)
 └ listBox    分组课表列表：当前手环 / 未识别 legacy / 本地课程 (:185-261)
 └ 「＋ 新建本地课表」(:160)
 └ EV 变体「导入/导出课程表」→ TransferActivity (:164-177)
```

底部导航 4 Tab：首页/课程表/手环/设置 = 4 个独立 Activity + `FLAG_ACTIVITY_REORDER_TO_FRONT`（`Ui.java:419-428, 456-464`），本页经 `Ui.wrapWithBottomBar(this, root, 1)` 挂底栏（:179）。

## 三、优化项（按优先级，含验收标准）

### A · 状态与反馈（P0，直接决定"好不好用"的观感）

#### A1 自动补齐要有存在感
- **现状**：`onCreate` 注册 status callback，`pullMissingFromWatch` 静默触发（:68-70）；期间列表无任何变化提示。
- **问题**：新课表"凭空出现"，用户不知道发生了什么；失败更是无声无息。
- **方案**：
  1. pull 开始时在 `syncView` 显示「正在从手环同步清单…」+ 禁点；
  2. 成功补入 N 套时 toast「已从手环同步 N 套课表」；N=0 不打扰；
  3. 失败时 `syncView` 转 ERR 色并给「重试」点击区（复用既有 statusView 染色机制，OK/WARN/ERR 三态已在 :502-525 实现，只差失败态入口）。
- **验收**：断手环进页 → 3s 内出现失败提示与重试；连手环且有新课表 → 2s 内 toast + 列表出现新卡片。

#### A2 30s 节流改成「节流 + 事件触发双通道」
- **现状**：`lastPullAt > 30000` 才 pull（:68-69），用户刚在手环上建了课表、马上切回 app 可能看不到。
- **方案**：保留节流，但把 `ConnectionBar` 从「断开→连上」的**边沿事件**作为强制 pull 触发（连上瞬间不计入节流）；Tab 首次进入（`onResume` 且本次会话未拉过）也强制一次。
- **验收**：手环侧新建课表 → 切回 app 首页 → 进课程表 Tab，清单即含新课表，无需等 30s。

#### A3 空态升级
- **现状**：一行灰字「还没有课表，点下方按钮新建」（:193）。
- **方案**：空态区分三种语境给不同引导——①手环已连接且拉到 0 套：「手环上还没有课表」+ 引导去手环侧新建；②手环未连接：「连接手环后可自动导入已有课表」；③有本地课表但当前设备组为空：说明多设备隔离逻辑。
- **验收**：三种场景空态文案各不相同且指向明确动作。

#### A4 手动刷新入口
- **现状**：无下拉刷新、无刷新按钮（全靠 onResume + 回调 + 节流）。
- **方案**：`deviceBar` 右侧加刷新图标（复用 Lucide 图标行机制 :386-399），点击 = 强制 pull + 旋转动画；不引入 SwipeRefreshLayout（整页重建未解决前，下拉刷新会放大闪烁，见 C1）。
- **验收**：点击刷新有转圈反馈；pull 期间重复点击被节流。

### B · 数据一致性与可靠性（P0，错了会丢课表）

#### B1 设备分组不再靠前缀猜
- **现状**：`label.startsWith(curName)` 判定「这是当前手环的课表」（:234）；代码注释自认 deviceId 有恒空的兜底补丁（:221-223）。
- **问题**：设备叫「小米手环」与「小米手环9 Pro」会互相串组；legacy 课表永远进「未识别」。
- **方案**：
  1. 分组键一律用 `deviceId`，`deviceName` 只做显示；
  2. 对存量 `deviceId` 为空的记录做**一次性迁移**：连上手环时先 `get_device_id`，把 `deviceName` 精确相等（`equals`，非前缀）且 source=sync 的记录回填 deviceId；
  3. 迁移不了的才落「未识别」组，组名改「其他课表（未关联设备）」。
- **验收**：造两台同前缀设备名的数据 → 各归各组；升级后旧数据重启一次完成回填，不再回退到 startsWith。

#### B2 ScheduleStore 不许静默失败
- **现状**：`ScheduleStore.java:32` 注释「所有方法吞异常：存储是锦上添花」——但课表数据对用户不是锦上添花。
- **方案**：
  1. 读失败（JSON 损坏）：把坏文件改名 `ev_schedules.corrupt-<ts>` 留证，内存置空并 toast「本地课表数据损坏，已保留损坏备份」；
  2. 写失败：返回 false 并在调用点（save/delete/setActive）toast，不再假成功；
  3. 写入改 `commit()` → `apply()` 后读校验（写入后立即回读比对 size 或 dirty 标记）。
- **验收**：手工塞坏 JSON 启动 → 有提示且不丢手环侧数据（可重新 pull）；写失败场景能感知。

#### B3 激活切换的回执一致性
- **现状**：`setActive` 只改本地标记；若该课表 `dirty`，首页渲染的是手环上的旧数据。
- **方案**：切激活时若目标课表 `dirty=true`，状态条显示「当前课表有未同步修改」，并让 `syncView` 的「点此同步」直接针对该课表；同步成功才清掉提示。
- **验收**：编辑未同步 → 切激活 → 状态条出现未同步提示 → 同步后消失。

### C · 渲染性能（P1，闪烁与状态丢失）

#### C1 从「整页重建」到「按卡片 diff」
- **现状**：`render()` 每次 `listBox.removeAllViews()` 全量重建（:186），切激活、展开收起、每次 status 回调都触发；`expandedGroups` 只存内存（:53），离开页面即丢。
- **问题**：列表闪一下；展开状态跨页丢失；status 回调高频时浪费。
- **方案**（渐进，不做 RecyclerView 大改）：
  1. 第一层：status 回调只更新 `syncView`/`deviceBar` 文案，不触发 `render()`；pull 完成才 render；
  2. 第二层：卡片级更新——切激活只改目标/原卡片的勾选态与「当前」标记（`scheduleCard` :372-430 拆出 `bindActive(state)`），不重建整列；
  3. `expandedGroups` 持久化到 `ScheduleStore`（key `ui.expandedGroups`），回页恢复。
- **验收**：切激活不再全列闪烁；展开「当前手环」组 → 去设置页回来 → 展开态保持。

#### C2 status 回调节流
- **现状**：`SyncEngine` 的 status callback 每次连接状态变化都进 UI 线程更新。
- **方案**：UI 侧对同值去重（状态机未变不刷 UI），200ms 合并窗口。
- **验收**：蓝牙抖动场景（快速断连重连）UI 无高频跳动。

### D · 功能补全（P1-P2）

#### D1 「从手环删除」（P1）
- **现状**：本期置灰，只删本地（:31 类注释、:486）。
- **方案**：
  1. 需手环侧协议支持：新增 `{"action":"delete_schedule", payload:{scheduleId}}`，**这要走手环侧守门人审批**——write 策略从「显式用户动作」扩大范围，须手环侧确认允许删除哪些课表（建议：仅允许删非激活课表，激活课表先切走再删）；
  2. app 侧：删除按钮去掉置灰，二次确认弹窗文案明确「将同时从手环删除」；手环侧回执失败时本地不删并提示；
  3. 未连接时按钮置灰 + 长按提示原因。
- **验收**：连手环删非激活课表 → 手环 `list_schedules` 复查确实少了；删激活课表被手环拒绝 → app 提示且数据完好。
- **⚠️ 前置**：本项跨端，先在手环侧（class-schedule）立协议变更单，app 侧等协议冻结再动工。

#### D2 多选批量同步（P2）
- **现状**：只能逐套点同步图标。
- **方案**：组头加「全部同步」；卡片长按进多选模式，底部浮条「同步 N 套 / 删除」。顺序执行，失败列表单独汇报（哪套失败、原因）。
- **验收**：5 套课表批量同步，4 成功 1 失败 → 汇总明确指出失败那套。

#### D3 导入冲突预览（P2）
- **现状**：`TransferActivity` 导入前有同名检测与覆盖确认（`TransferActivity.java:900-929`），但只看名字，内容差异不可见。
- **方案**：确认弹窗里给 diff 摘要（课程数、时间网格变化数、增/删/改课程名列表前 5 条）。
- **验收**：导入同名不同内容课表能看到「+2 门 / -1 门 / 改 3 门」级别摘要。

## 四、建议执行顺序

```
第 0 批（半小时，零风险）
  E1 死代码删除 · E3 主题 token · E4 exported 收紧

第 1 批（P0 体验，1 天内）
  A1 自动补齐反馈 → A2 节流双通道 → A4 手动刷新 → A3 空态

第 2 批（P0 数据，半天 + 真机回归）
  B1 分组键迁移（先写迁移，后删 startsWith）→ B2 存储异常显性化 → B3 激活一致性

第 3 批（P1 渲染）
  C1 两层渐进改造（先 status 分流，再卡片级更新 + expandedGroups 持久化）→ C2 回调节流

第 4 批（跨端，需手环侧配合）
  D1 从手环删除（协议先冻结）→ D2 批量同步 → D3 导入 diff 预览
```

**排序理由**：A/B 是"用户已经被坑"的项（无声失败、串组）；C 是"看着难受"；D1 依赖手环侧排期，先立项等协议。E 顺手清掉降低后续 diff 噪音。

## 五、回归清单（每批做完必过）

1. **不连手环**：进页不崩、空态正确、新建本地课表→编辑→删除全链路可用
2. **连手环（有 2+ 套课表）**：清单自动补齐、激活切换后首页周视图跟着变、同步状态条三态正确
3. **同前缀设备名**：B1 后不串组
4. **双变体**：EV 与 EvBox 各装一次，主题色/文案/入口（导入导出卡片仅 EV 有）各自正确
5. **升级路径**：用 v0.5.99 产生的旧 `ev_schedules` 数据直接覆盖安装 → B1 迁移完成、无数据丢失
6. **杀进程重进**：展开态、滚动位置、激活标记与重进前一致
