# 手环 ↔ 手机：EV App 作为「能力网关」的场景分析

> 2026-09-28 · 状态：**方案分析（未实施）**  
> 前提事实：interconnect 双向 JSON 通道已通（`SyncEngine` send/Receive）；`SyncService` 前台服务常驻（收手环消息不依赖前台 UI）；手环 EV 快应用可加按钮/菜单（手环侧需发版）。

---

## 一、核心洞察

> 手环只要给个信息，EV App 能做的事手环都能触发。

准确。这套系统的本质是：

```
手环 = 零输入遥控器 + 预设指令面板（小屏、无麦克风、无独立网络）
EV App（手机）= 能力网关：网络 API / 本地硬件 / AI / 系统能力 的执行器
双向通道 = JSON action 路由（已有 chat / get / export / update_settings 等）
```

**决定可行性的唯一关键变量：手环端的输入成本。**
手环没有麦克风、屏幕 1.6 寸、打字靠滑——所以「一键指令」全部可行，「自由文本」全部痛苦。评估任何场景先问：手环上要点几下？

## 二、需要补齐的架构件（一个路由器，工作量小）

现在手环 → 手机消息按 action 分发（留言/chat、导出等），但没有统一的「遥控指令」入口。补一个：

```
手环（预设按钮）→ {"action":"cmd","type":"find_phone","params":{}}
                     ↓ SyncService（常驻，无需打开 App）
手机 CommandRouter：白名单分发 → 执行器（本地/网络/AI）
                     ↓ 回传
手环 ← {"action":"cmd_result","type":"find_phone","ok":true}（或直接 NotifyApi 推卡片）
```

- 路由器放 `SyncService`（已常驻），**手环遥控不需要打开手机 App** ✅
- 结果回传两条路：手环 EV 界面刷新（cmd_result）或手机直接推系统通知（NotifyApi 已通）
- **安全**：命令必须白名单；涉账号/花钱/对外发送的（邮件、AI 高级操作）默认要求手机端确认或限模板化

## 三、场景分级清单

### T0 · 纯本地，零输入，立即可做（性价比之王）

| 场景 | 手环操作 | App 执行 | 备注 |
|---|---|---|---|
| **找手机** | 点「找手机」 | 手机响铃（MediaPlayer 最大音量循环）+ 震动 + 亮屏闪光 | 用户点名场景；静音状态也响（勿扰可加绕过开关）|
| 手机状态回传 | 点「手机状态」 | 电量/静音状态/蓝牙/今日步数（如有）回传手环 | 手环找手机前先看一眼手机是不是没电了 |
| 静音/恢复 | 点「静音」 | AudioManager 切静音/振动/普通 | 开会一键静音 |
| 倒计时/闹钟 | 选预设时长 | AlarmManager 定时 | 「10 分钟后提醒我回教室」——预设 5/10/30 分钟按钮 |
| 打开指定 App | 选 App | Intent 启动 | 「打开支付宝扫码」等（受 Android 11 包可见性约束，白名单声明）|

### T1 · 网络查询，参数预设，可行（第二梯队）

| 场景 | 手环操作 | App 执行 | 备注 |
|---|---|---|---|
| **查天气** | 点「天气」（城市预设） | App 调天气 API → 回传今日/明日摘要卡片 | 用户点名场景；**城市在手机端预设**，手环零输入；免费源：和风/高德（有 key 即可）|
| 今日日程 | 点「今天」 | 读系统日历 → 回传列表 | 与上课提醒互补 |
| 导航回家 | 点「回家」 | 拉起地图 App 导航到预设地址 | 通勤一键 |
| 热榜/新闻摘要 | 点「资讯」 | 抓取聚合 → 回传标题列表 | 手环小屏读摘要刚好 |

### T2 · AI 接入（EV App 做中间人，可行但要绕开输入瓶颈）

| 场景 | 手环操作 | App 执行 | 备注 |
|---|---|---|---|
| **AI 快问** | 点预设问题按钮 | App 调 LLM API → 回传短答案 | 预设：「今天穿什么」（结合天气+课表）、「下节课带什么」、「明天第几节有课」——**答案受限于 200 字，prompt 模板约束输出** |
| 通知 AI 摘要 | 点「摘要」 | 把攒的通知喂 LLM → 三句话总结 | 免打磨 |
| 定时 AI 简报 | 手机端定时 | 每天早上生成「今日简报」推手环 | 手环零操作，最舒服的 AI 场景 |

> AI 自由对话的瓶颈：手环无法打字/语音。**解法不是手环输入，而是「手机端输入 + 手环看答案」或「预设问题」**。若未来换带麦克风的手环（Watch S 系列），自由对话才成立。

### T3 · 高输入成本 / 涉外部账号，谨慎（原型验证后再上）

| 场景 | 评估 |
|---|---|
| **AI 编辑课程 → 转导入** | 用户点名。**方向反了更顺**：手环描述需求太痛苦；正确姿势是「手机上跟 AI 说（语音/文字随便）→ AI 生成 JSON → 一键转导入 → 同步手环」。手环侧只适合「确认/拒绝」一步。技术上通（App 内已有 JSON 编辑器 + 导入管线，LLM 输出对齐 schema 即可），做成**手机端 AI 助手**，手环只做结果同步 |
| **发邮件** | 可行但要**强模板化**：预设收件人（妈妈/老板）+ 预设短语（「我到家了」「马上到」）→ 手环一键发送。自由撰写不现实。且涉对外发送，建议发送前手机弹确认（或仅限白名单短语免确认）。需要 App 申请邮件发送能力（Intent 走邮件客户端最简单，零 SMTP 依赖）|
| 支付/智能家居 | 涉钱与账号安全，不建议从手环直达；「米家一键场景」可以列 T2 观察 |

## 四、推荐路线图

**第一批（一周内可上线，全是 T0）**：
`找手机` + `手机状态` + `静音` + `倒计时` —— 纯本地、无外部依赖、手环端只需 4 个按钮。
改动面：手环 EV 加「手机」菜单（手环侧发版）+ App 端 `CommandRouter` + 2 个执行器。

**第二批（T1）**：`天气`（需申请天气 API key）+ `今日日程` + `导航回家`。

**第三批（T2，AI 上桌）**：`AI 快问`（3~5 个预设问题）+ `每日简报`（早上定时推）。之后再看使用数据决定要不要做「手机端 AI 课表助手」（T3 的正确形态）。

## 五、约束与风险备忘

1. **手环侧发版是前置**：所有入口依赖手环 EV 快应用加按钮——需要手环侧配合发版（像 1.6.139 那次一样）。
2. **通道可靠性**：interconnect 在息屏/后台偶发延迟，找手机这类「即时反馈」场景要给手环「已触发/失败」回执，避免按了没反应的挫败。
3. **安全白名单**：CommandRouter 只认白名单 action；涉对外的（邮件）必须手机确认。手环丢失 = 遥控器丢失，别让它能发邮件花钱。
4. **电量**：双向 JSON 心跳类通信功耗很小，但「持续轮询天气」不要做——手环点一下查一次。
5. **勿扰冲突**：找手机要能穿透静音（独立音轨 + 勿扰豁免开关），否则场景失效。

## 六、第一批实施记录（2026-09-28，commit 9c99efb，v0.5.62+）

**已落地**（手机端全部就绪，手环侧按钮待 EV 快应用发版）：

| 组件 | 说明 |
|---|---|
| `CommandRouter` | 白名单分发：`{"action":"cmd","type":"find_phone/phone_status/mute/countdown","minutes":N}` → 执行 → `{"action":"cmd_result",...}` 回传手环；未知 type 消费但不执行 |
| 挂接点 | `MessageActivity.handleUnsolicited` 开头（SyncService 与页面两条 observer 路径都经过，单点覆盖）；`cmd` 指令不再进留言流 |
| 找手机 | MediaPlayer ALARM 音轨循环（**穿透静音/勿扰**）+ 波形震动 + 亮屏 WakeLock + 30 秒自动停 + 通知栏「停止」按钮（ToolboxReceiver） |
| 静音切换 | 响铃 ↔ 振动（不进静音档，防「找不到手机」） |
| 倒计时 | `AlarmManager.setExactAndAllowWhileIdle`（1/5/10/30 分钟预设）→ 到点高优先级通知 + 震动（跨进程重启可达） |
| 手机状态 | 电量%/充电/响铃模式/手环连接（sticky BATTERY 广播，零权限） |
| `ToolboxActivity` | 手机端面板（找手机/静音/倒计时/状态），入口在「手环」页——手环侧未发版前先用于验证 |

**手环侧待办**：EV 快应用「工具箱」菜单加 4 个按钮，点击发对应 cmd JSON 即通。
