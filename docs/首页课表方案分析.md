# 首页方案分析：课程表周视图 vs 维持现状

> 分析日期：2026-09-28  
> 背景：目前首页已有一个「首屏课表卡」隐藏在连接流程之下，占据信息层级较次要的位置。  
> 本次分析讨论：**是否应该把课表（尤其是周视图）提升为首页的核心主视觉区域**，以及随之而来的导航栏重构。

---

### 1.2 现存问题

- 用户打开 App 的第一眼看到的是 **"正在连接"** 的进度和状态，而不是课程表
- 课表卡在 `buildUi()` 里初始设置为 `View.GONE`，只有连上后才能看到——断线时用户看到的是一片空白或错误提示
- 虽然已有周视图 `weekGrid()`，但它是课表卡内的一个切换选项，存在感很低
- 底部导航栏 "留言" 占据一个常驻 Tab，但留言本质上是一个低频功能（不是实时 IM）

## 2. 方案 A：首页 = 课表周视图（推荐）

### 2.1 核心思路

"EV 课程表" 这个 App 的名字就叫课程表，首页就应该是一张课程表。

打开 App → 直接看到一张**本周课表周视图**，手机屏幕够大（1080×1920 真机实测），7 列周视图排版宽松、可读性好。

### 2.3 关键设计要点

#### 2.3.1 默认本地课表（确保始终有数据显示）

- App 内置一份**出厂默认课表**，存储在 `res/raw/default_schedule.json`
- 用户首次打开，没有任何缓存时，直接加载这份默认课表渲染
- 手环同步后，用同步数据覆盖
- **始终保证屏幕上有课程表可看**，不会因为"未连接"而显示空白

#### 2.3.2 多课表管理 + 底部「课程表」栏目

底部导航栏从 **首页 / 留言 / 设置** 改为 **首页 / 课程表 / 设置**：

| Tab | 用途 |
|-----|------|
| 首页 | 当前选中课表的**周视图**（大屏主打）+ 快捷操作 |
| 课程表 | **课表列表**：所有本机课表，含本地/同步状态、切换、管理 |
| 设置 | 保持现有功能（昵称、主题、调试等） |

#### 2.3.3 课表唯一 ID 字段

必须新增的数据字段，用于区分 / 去重 / 管理课表：

```java
class CourseSchedule {
    String scheduleId;    // 课程表唯一ID（云端/手环分配）
    String name;          // 课表名称（如"2025计算机科学课表"）
    String source;        // "local" | "sync"
    long syncedAt;        // 最后同步时间
    List<Course> courses; // 课程列表
}
```

- **本地课表** (`source = "local"`)：`scheduleId` 为空字符串，表示尚未同步，没有线上唯一 ID
- **同步课表** (`source = "sync"`)：`scheduleId` = 手环/云端分配的唯一 ID
- 本地课表点击「同步到线上」→ 上传到手环 → 手环返回 `scheduleId` → 更新本地记录，`source` 改为 `"sync"`

#### 2.3.4 手环连接后自动下载课表

保持现有机制：连接成功 → `loadProfile()` 拉取手环课表 → `CourseCache.save()` 保存。

新增逻辑：
- 拉到的课表带 `scheduleId`，与本机已有的对比
- 如果是新 ID → 自动添加一条课表记录（`source = "sync"`）
- 如果是已有 ID → 更新对应课表记录
- 多个已同步课表 → 自动切换到最新的

#### 2.3.5 留言功能重新定位

留言从底部 Tab 移除，但仍保留访问入口：
1. **首页快捷按钮「留言」**：弹出底部对话框，快速发送文字留言
2. **「呼叫手环」按钮**：发送特定格式提醒，手环端响铃/震动

#### 2.3.6 快捷操作按钮设计

首页在课表下方放置 2×2 快捷按钮网格：

| 按钮 | 行为 | 发送内容示例 |
|------|------|-------------|
| 🔔 呼叫手环 | 发送提醒，手环震动+响铃 | `{"action":"call","text":"请查看手机"}` |
| 📢 上课了 | 提醒手环「上课了」 | `{"action":"notify","text":"上课了！","type":"class_start"}` |
| 📝 留言 | 弹快速留言发送框 | 用户输入文本 |
| 👋 下课了 | 提醒手环「下课了」 | `{"action":"notify","text":"下课了！","type":"class_end"}` |

### 2.4 同步机制总览

| 场景 | 触发方式 | 行为 |
|------|----------|------|
| 手环首次连接 | 自动 | 拉取手环课表，本地新建一条 sync 记录 |
| 手环重复连接 | 自动 | 对比 scheduleId，同 ID 则更新，新 ID 则新增 |
| 首页同步按钮 | 手动点击 | 触发一次完整 export，刷新当前课表 |
| 课表列表"同步到线上" | 手动点击 | 将本地课表 POST 到手环，拿回 scheduleId |
| 切换课表 | 手动选择 | 切换 activeId，刷新首页周视图 |

## 3. 方案 B：维持现状（小幅优化）

### 3.1 核心思路

保持现有布局不变，只做局部增强：
- 课表卡仍然在连接完成后才显示
- 保留 首页 / 留言 / 设置 三 Tab
- 新增功能以按钮形式嵌入现有页面

### 3.2 优点

- **零风险**：不改变用户已有操作习惯
- **改动量最小**：约 2-3 小时工作量
- 现有代码已经稳定跑通，不做结构性变更

### 3.3 缺点

- 课表永远是「二级信息」，断线时看不到
- 「EV 课程表」App 的首页不像课程表，更像一个「连接工具」
- 留言 Tab 占据常驻位置但使用频率低
- 与手环端 EV 首页（手环首页也是课表）定位不一致

---

## 4. 两方案对比

| 维度 | 方案 A：首页=课表 | 方案 B：维持现状 |
|------|-------------------|------------------|
| 第一眼体验 | ✅ 打开就是课表，名副其实 | ❌ 打开是连接状态 |
| 离线可用性 | ✅ 默认本地课表兜底，断线也能看 | ❌ 断线时课表卡片隐藏 |
| 课表管理 | ✅ 支持多课表切换、本地/同步区分 | ❌ 只有一份缓存 |
| 与手环一致性 | ✅ 和手环首页（也是课表）呼应 | ⚠️ 手机端定位模糊 |
| 留言可用性 | ⚠️ 需从快捷按钮进入，多一步 | ✅ 底部 Tab 直达 |
| 开发工作量 | ~2-3 天 | ~半天 |
| 风险 | 中等（导航栏重构 + 数据模型变更） | 低 |

## 5. 实施路径（方案 A）

### 5.1 阶段 1：数据层（约半天）

1. 新增 `CourseSchedule` 数据类：`scheduleId`、`name`、`source` 字段
2. 多课表存储：从存一份改为存列表 `{"schedules": [...], "activeId": "..."}`
3. 出厂默认课表：`res/raw/default_schedule.json`
4. 迁移逻辑：首次启动时把旧版 `ev_course_cache` 迁移到新格式

### 5.2 阶段 2：UI 层（约 1 天）

1. 首页重构 `HomeActivity`：课表周视图提升为第一层级，连接状态缩小为迷你条
2. 新页面 `ScheduleListActivity`：课表列表管理（替换原留言 Tab）
3. 底部导航栏改为 `[首页] [课程表] [设置]`，新增图标资源

### 5.3 阶段 3：交互层（约半天）

1. 课表切换、本地同步到线上、快捷按钮实现
2. 自动同步 + 手动刷新按钮

### 5.4 阶段 4：测试与兼容（约半天）

1. 旧版数据迁移测试、断网/未连接场景
2. Widget 刷新验证、EvBox 双变体兼容

## 8. 总结

**推荐方案 A**：把首页做成课表周视图。

理由：
1. 这个 App 叫「EV 课程表」，首页应该是课程表
2. 手机屏幕大（1080p），7 列周视图非常合适
3. 默认本地课表确保离线也能看，不会出现空白尴尬
4. 多课表管理 + 同步机制让「课程表」从一个缓存副产品升级为一级功能
5. 留言功能虽从底部 Tab 移除，但通过首页快捷按钮仍可一键触达，且多了「呼叫手环」「上课了」等更实用的快捷发送
6. 与手环端 EV 首页（也是课表）定位一致，体验统一

工作量约 **2-3 天**，风险可控，收益明显。
