# 安卓端「标准版 / 高级版」身份识别与功能限制方案

> 目标：安卓同步器（`EVSyncProbe`）能识别当前设备是**标准版**还是**高级版**，在合适位置显示身份；
> 标准版点「导入课程」弹窗提示升级；标准版「首页设置 / 编辑时刻」禁止操作并弹窗提示升级。
> 全部结论带 `文件:行号` 证据，均为 2026-10-05 实测核对。

---

## 一、需求拆解

| # | 需求 | 验收口径 |
|---|---|---|
| ① | 安卓端**获取**用户版本身份（标准 / 高级） | 冷启动、激活后、切设备后都能拿到可信身份，含有效期 |
| ② | 高级版在**合适位置显示**身份 | 设置页明确显示「高级版 · 永久有效 / 到期日」；首页有轻量标识 |
| ③ | 标准版点「**导入课程**」→ 弹窗提示升级 | 拦得住、文案明确、引导到激活页；高级版不受影响 |
| ④ | 标准版「**首页设置 / 编辑时刻**」禁止操作 → 弹窗提示升级 | 控件置灰不可点，点击（或进入）即弹升级提示 |

## 二、现状勘察（关键结论 + 证据）

### 2.1 安卓端**完全没有**版本/授权概念

全仓 `apk/src` 搜 `premium / isPro / isActivated / license / 授权状态` **零命中**（只有 BLE「权限授权」这类假阳性）。
`getSharedPreferences` 的全部调用点都是 node / 课表 / 统计 / 留言，**没有任何 auth 存储**。

与"高级版"相关的只有两处**动作**，没有**状态**：

- `apk/src/com/application/watch/classschedule/SettingsActivity.java:172-175`：设置页有一行「高级版」，且仅在 `Variant.isEv` 时显示，点了跳激活页。
- `apk/src/com/application/watch/classschedule/FastActivateActivity.java:89`：整页只做「输 4 位码 → 激活」。

### 2.2 唯一能拿到的授权信息：`activate` 的回包（但**只显示、不落库**）

```
apk/src/com/application/watch/classschedule/FastActivateActivity.java:658-668
    String disp = o.optString("displayStatus");
    String status = o.optString("status");
    ...
    resultView.setText("激活成功！" + disp + "\n可在手环上打开「EV 课程表 → 高级版」查看有效期。");
```

回包来自手环侧（`ev/class-schedule/src/app.ux:546-555` 构造），字段：`{ok, action, status, displayStatus, expireAt, months}`。
**问题**：`disp/status/expireAt` 用完即弃，没有写进任何本地存储 → App 冷启动后**不可能**知道自己是高级版。

### 2.3 授权真源在手环端（这点决定了方案走向）

| 项 | 位置 | 说明 |
|---|---|---|
| 存储键 | `ev/class-schedule/src/data/storage-tables.js:87` | `premium_unlocked`「高级功能解锁状态」 |
| 认证数据 | `ev/class-schedule/src/data/storage-tables.js:99-102` | `auth_data`（`activated / activationDate / expiryDate / deviceId / isTrial`） |
| 判定入口 | `ev/class-schedule/src/data/auth-store.js:232` `checkStatus()` | → `buildStatus()` `:249`，输出 `status / displayStatus / expireAt / isExpired` |
| 文案口径 | `auth-store.js:256`、`:345` | `displayStatus` 取 **`"高级版"`** / **`"标准版"`**；`status` 取 `permanent / active / trial / basic` 等 |
| 回退逻辑 | `store.js:818-844` `isPremiumUnlocked()` | 先看 `premium_unlocked`，落空回退 `auth_data` 的 `isActivated || isPermanent` |
| 手环功能门禁 | `settings.ux:324`、`schedule-manager.ux:543`、`statistics.ux:132`、`homepage-settings.ux:176`、`backup-restore.ux:121`、`reset-data.ux:229`、`vibration-lab.ux:229`、`schedule-qrcode.ux:117` | 全部调 `requirePremium(...)` |

### 2.6 需求④ 的落点：「首页设置」有，**「编辑时刻」两边都不存在这个词**

- 安卓端**有**首页设置页：`apk/src/.../HomepageSettingsActivity.java`

  - 入口在**手环页**：`BandActivity.java:469-470`（`toolCell(..., "首页设置", "模板 / 字号", ...)`）。
- 手环侧同名页 `ev/class-schedule/src/pages/homepage-settings/homepage-settings.ux`：这 8 项**全部**包在 `requirePremium()`（定义 `:176-181`，调用 `:244/251/258/265/272/279/286/293`），「自定义」子项 `openCustomContentEdit :61-63 / :323-327`。

**⚠️ 因此产生一个高价值发现**：
> 手环端把「首页设置」全部当高级功能，**而安卓端的同 8 项开关没有任何门禁** → 标准版用户只要在手机上改，就能绕过手环端的限制。这是现存的**旁路漏洞**，本需求正好一并堵上。

「编辑时刻」的**两种候选解释**（需你确认，见 §5-Q1）：
1. **= 课程的时刻（上课时间/节次）编辑**：安卓端 `CourseEditUtil.java:35`（常用节次模板）、`:80-81`（行号↔节次时段）、`CourseSheetDialog.java:246-250`（新增课程弹层的「时间」行）、`CourseEditActivity.java:347-350/481`；手环端 `add-course.ux:33`、`add-course-v2.ux:312`「上课时间」。
2. **= 首页设置页里的时间相关控件**：安卓端就是 `{"showTime","时钟"}`（`HomepageSettingsActivity.java:38`）。

## 三、方案设计

### 3.1 身份获取：三条路对比（推荐 B 先上、A 为正解）

| 路径 | 做法 | 优点 | 缺点 / 前置 |
|---|---|---|---|
| **A. 手环协议开只读**（正解） | 手环侧把 `auth` 改为 `read:"explicit"`（或加 `{"action":"get_auth"}` 动作），回 `{status, displayStatus, expireAt, isExpired}`；App 加 `SyncEngine.getAuth()` | 唯一权威、可随时刷新、天然跟随设备 | **要改跨仓 `class-schedule` + 手环发版**；当前 `app.ux:600` 是 `never`，需先解冻协议 |
| **B. 激活回包本地落库**（**立即兜底**） | `FastActivateActivity.java:658` 拿到 `displayStatus/status/expireAt` 后写 `SharedPreferences`（按 `deviceId` 存 + `activateAt`），App 启动读缓存并按 `expireAt` 判过期 | **不改手环、本轮就能上**；已激活用户立即生效 | 只有"在本 App 激活过"才有值；换设备/手环侧变更/续期后无法刷新；`expireAt` 需自己算到期 |
| **C. 服务端查状态** | `Net.java:21`（`BASE=https://app-auth.gudq.com`）新增 `GET /api/auth-status?deviceId=…` | 真源、跨端一致、可解绑 | 需服务端开发 + 设备标识打通；离线不可用 |
| ~~D. 裸 BLE 直连~~ | `bandauth/src/.../ProbeActivity.java:44-60` | — | **不可行**：注释明确"band state / schedule / device control commands 不在范围" |

**推荐路线**：`B`（本周兜底，覆盖"激活过的用户"）→ `A`（协议解冻后做正解，覆盖全量）→ `C`（可选，做真源与解绑）。

### 3.2 身份模型（建议新增一个类，单点判定）

建议 `apk/src/.../AuthState.java`（建议名，职责与 `ScheduleStore` 同级）：

```java
// 伪代码：字段与判定规则
state       : PREMIUM / STANDARD / UNKNOWN     // 直接驱动门禁
displayStatus: "高级版" / "标准版"              // 与手环 auth-store.js:256/345 同口径
expireAt    : long（0=永久）                    // 到期后判为 STANDARD
source      : "activate-cache" / "watch-sync" / "server"   // 便于排查
deviceId    : 与 SyncEngine.currentDeviceId() 绑定（:212）
fetchedAt   : long                              // 缓存新鲜度
```

**判定规则（顺序）**：
1. 有 `expireAt` 且 `now > expireAt` → `STANDARD`（并在 UI 提示"已到期"）。
2. `isPermanent || status=="permanent"` → `PREMIUM`。
3. `status ∈ {active, trial}` 且未过期 → `PREMIUM`（试用可显示"试用中 · 剩 N 天"）。
4. 其余（含拿不到值）→ `UNKNOWN`。

**`UNKNOWN` 的策略（重要，建议"失败开放"）**：拿不到身份时**不拦**功能，但身份位显示「未知 · 连接手环后可识别」。
理由：这是**限制类**改动，误伤高级版用户（把他当标准版拦掉）比暂时漏放更糟；身份一旦读到立刻生效。

### 3.3 需求② 身份显示位置

| 位置 | 建议 |
|---|---|
| **设置页**（主） | 扩展现有「高级版」行（`SettingsActivity.java:172-175`）：高级版显示绿色徽标「高级版 · 永久有效 / 到期 2026-11-05」；标准版显示灰色「标准版 · 点击升级」；未知显示「未知」 |
| **首页**（轻量） | `HomeActivity` 顶部/设备卡附近加小徽标（仅高级版显示，避免首页噪音） |
| 受限功能页 | 导入课程页、首页设置页副标题显示当前身份（点升级可直接跳 `FastActivateActivity`） |

### 3.4 需求③ 导入课程门禁（**双层拦截**）

| 拦点 | 位置 | 行为 |
|---|---|---|
| ① 菜单项 | `HomeActivity.java:487` 的「导入课程」 | `state==STANDARD` → 不跳转，弹升级弹窗 |
| ② 导入按钮 | `TransferActivity.java:289-291` | 兜底（防深链/其它入口直接进 TransferActivity）；标准版置灰 + 点击弹窗 |

统一弹窗（复用 `Dialogs.confirm`）：

```
标题：升级高级版后可导入课程
正文：导入课程属于高级版功能。当前为标准版，升级后可：
      · 从手机把课程表导入/覆盖到手环
      · 首页设置、自定义栏目等高级功能
主按钮：去升级 → 跳 FastActivateActivity（输入 4 位兑换码）
次按钮：以后再说 → 留在原页（不改变任何数据）
```
> 交互要点：**不要静默失败**（点了没反应最恼人）；也**不要先跳转再弹**（用户白跑一屏）。

### 3.5 需求④ 首页设置 / 编辑时刻门禁

**（a）首页设置页（`HomepageSettingsActivity`）— 建议整页只读**
- `state==STANDARD` 时：8 个开关 + 模板选择 + 字号 **全部 `setEnabled(false)` + 视觉置灰**（需补一个 `Ui.disabled(view)` 样式方法，把背景/文字色降到 40% 透明度，目前只有原生 `setEnabled`，见 `:174-178`）。
- 整页顶部加一条提示条：`标准版不支持修改首页设置 · 点此升级`（点击弹升级弹窗）。
- 理由：手环端这 8 项**全部**是 `requirePremium`（`homepage-settings.ux:244/251/258/265/272/279/286/293`），App 端放开就等于绕过——按端对齐语义，App 端也应当整页禁改。
- 注意：**只禁"改"，不禁"看"**（进入页面仍可查看当前值，避免"功能消失"的困惑）。

**（b）「编辑时刻」**
- 若指**课程的时刻/上课时间**（§2.6 解释 1）：在 `CourseSheetDialog.java:246-250` 的「时间」行与 `CourseEditUtil.java:35` 的节次模板入口上加同样门禁（标准版：显示但不可改，点了弹升级）。
  ⚠️ 需先和手环端确认口径：手环端「上课时间」当前**是否**属于高级功能（`add-course.ux` 未见 `requirePremium`），**两端若不一致会互相打架**。
- 若指**首页设置里的时间控件**（§2.6 解释 2）：已包含在 (a) 的整页只读里。

### 3.6 一并顺手做掉的工程项

1. **文案收口**：新建 `UiText.java` 或 `AuthText`，把"升级高级版…"系列文案集中（现在全内联，5 处会漂移）。
2. **身份缓存落库键名规范**：建议 `ev_auth_cache`（含 `deviceId`，多设备不串）。
3. **可测性**：`AuthState` 加一个调试入口（DebugActivity 里可强制设为 PREMIUM/STANDARD/UNKNOWN），方便三个版本各自回归。
