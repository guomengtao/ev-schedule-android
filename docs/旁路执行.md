# 旁路执行

> **⚠️ 强制规则**：本项目的**唯一**终端执行方式为旁路执行（`spawn bash` 子进程）。**非明确允许，禁止使用其他终端方式**（包括 VSCode 集成终端、系统 Terminal.app、iTerm2 等）。所有命令必须通过 IDE 的旁路执行通道发出，AI 自动构造并执行，不经过任何终端模拟器。

> **定位**：本文定义项目的默认且唯一终端执行方式——**旁路执行**。所有 AI 执行的命令都走 `spawn bash` 子进程通道，不经过 IDE 终端模拟器。这是经过多轮验证的最稳定方式。

---

## 一、什么是旁路执行？

**旁路执行**是指：AI（CodeBuddy / Trae IDE）不经过 VSCode/IDE 的集成终端（pty），而是通过插件后端的 `spawn`（或等效 API）直接 fork 一个独立 bash 子进程来执行命令。

```
IDE 插件后端  →  spawn("bash", ["-c", "你的命令"])  →  捕获 stdout / stderr / 退出码
   (无界面)                                                   ↓
                                                       回传给 AI 解析
```

**"旁路"的含义**：命令执行完全绕开了你眼睛看到的那个终端窗口。终端窗口里什么痕迹都没有，而命令的结果直接出现在 AI 对话里。

---

## 二、为什么旁路执行是默认方式？

### 2.1 稳定性来自闭环反馈

```
发出命令 → 执行 → 捕获输出（stdout + stderr + 退出码） → AI 读到完整报错 → 立即修正
```

- 每条命令的输出是**机器可读文本**
- AI 能读到**完整的报错信息**，不会漏掉任何一行
- 没有人为操作引入的不确定性（打字错误、选错窗口、终端切走了等）
- 执行环境 = 真实 Mac 环境（同样的 shell、同样的 PATH、同样的文件系统）

### 2.2 可复现、可验证、可纠错

- 同样的命令每次产生同样的行为
- 退出码明确标示成功或失败
- 报错原文一字不落地传给 AI，AI 可以精准定位问题

### 2.3 和 IDE 终端对比

| | 旁路执行（spawn bash） | IDE 集成终端 |
|---|---|---|
| 命令发出方式 | AI 自动构造并执行 | 你手动打字 |
| 是否需要人工操作 | 不需要 | 需要 |
| 输出捕获 | 完整机器可读 | 需要人眼看 |
| 错误处理 | AI 立即解析修正 | 你看了再告诉 AI |
| 打字错误风险 | 无 | 有 |
| 适合重复性操作 | 非常适合 | 低效 |

## 三、三条核心规则（必须遵守）

### 规则 1：无状态——每条命令是独立 shell

每条命令 spawn 一个**全新的** bash 子进程，执行完就销毁。`cd`、`export`、`source` 等修改 shell 状态的命令不会延续到下一条。

```
# ❌ 错误写法（分两条命令）：
cd /some/path
ls

# ✅ 正确写法（用 && 或 ; 连成一条）：
cd /some/path && ls
```

**所有需要共享状态的命令，用 `&&` 或 `;` 连成一条。**

### 规则 2：交互式命令会卡死

需要用户输入的命令（如 `gh auth login`、`passwd`、`npm init` 的问答）会**永久挂起**，因为没有终端可以交互。

```
# ❌ 会卡死：
gh auth login

# ✅ 替代方案：
# 1. 找非交互式替代（如 gh auth token 用环境变量）
# 2. 丢后台 + 读日志文件取输出
# 3. 优先使用接受参数/环境变量的 CLI
```

### 规则 3：管道会吞掉退出码

管道的退出码是**最后一个命令**的退出码，前面命令失败会被掩盖。

```
# ❌ push 失败不会被发现：
git push origin main 2>&1 | tail -1

# ✅ 关键操作后必须独立复核：
git push origin main && git rev-list --count origin/main..main
```

**push、部署等关键操作后，必须用独立命令复核结果。**

## 四、典型使用场景

### 场景 1：构建 APK

```bash
cd /Users/Banner/Documents/guomengtao/ev-schedule-android/apk && ANDROID_SDK_ROOT="$HOME/android-sdk" bash build.sh
```

一条命令完成目录切换 + 构建，旁路执行直接返回构建日志和退出码。

### 场景 2：USB 调试

```bash
ADB="$HOME/android-sdk/platform-tools/adb" && S="BTF4C17222009588" && PKG="com.application.watch.classschedule" && $ADB -s $S install -r -g apk/EVSyncProbe.apk && $ADB -s $S shell am force-stop $PKG && $ADB -s $S shell am start -W -n $PKG/.HomeActivity
```

一条命令完成安装 + 启动，所有环境变量在命令内部定义。

### 场景 3：GitHub 操作

```bash
cd /Users/Banner/Documents/guomengtao/ev-schedule-android && git push origin main && git rev-list --count origin/main..main
```

推送 + 复核在一条命令里，确保 push 结果被验证。

### 场景 4：并行会话（git worktree）

```bash
cd /Users/Banner/Documents/guomengtao/ev-schedule-android && git worktree add ../ev-android-wip main
```

创建独立工作树后，在另一条命令里切换到新工作树干活。

## 五、快速诊断

如果旁路执行出问题，按以下顺序排查：

| 现象 | 可能原因 | 检查方法 |
|---|---|---|
| 命令卡住不返回 | 触发了交互式输入 | 改用非交互式替代方案 |
| cd 不生效 | 分成了多条命令 | 用 `&&` 连成一条 |
| push 显示成功但实际失败 | 管道吞了退出码 | 加独立复核命令 |
| 环境变量找不到 | 上一条 export 已失效 | 在命令内部定义变量 |
| 权限不足 | spawn 的 shell 环境不同 | 用绝对路径，明确设置 HOME |
