# 主题切换后多页面不同步问题分析

> 分析日期：2026-09-28
> 问题：在「主题外观」页切换到新主题后，只有「首页设置」页面同步了，其他大多数页面仍显示旧主题配色。

---

## 1. 问题复现路径

```
首页 (深色主题) → 设置 → 首页设置 → 返回设置 → 主题外观 → 选「晨光白」
     ↓ ThemePicker 已变浅色 ✅
返回设置 → 设置页 (仍深色 ❌) → 返回首页 → 首页 (仍深色 ❌)
```

重新进入「首页设置」→ 浅色正常 ✅（因为该 Activity 是新 startActivity 进入，走 onCreate）。

---

## 2. 根因分析

### 2.1 颜色是静态可变字段，但 View 创建后就固化了

Ui.java 中所有颜色 Token 是 public static 可变字段（BG, CARD, CARD2, LINE, TEXT, MUTED, ACCENT, OK, WARN, ERR 共 10 个）。

Ui.applyTheme() 负责按当前模式（跟随手环 / 本地选择 / 系统深浅色）刷新这些静态字段，同时调 Activity.setTheme() 设置系统级明暗。

所有 Activity 在 onCreate() 里调用 Ui.screen() → applyTheme()，然后在构建视图时把当时的静态颜色值传递给 View：

```java
// Ui.text() 中：
t.setTextColor(color);   // color 参数 = 调用时 Ui.TEXT 的值（按值传递）
```

**关键问题**：int 是 Java 基本类型，按**值**传递。TextView.setTextColor(xxx) 之后，颜色值就写进了 TextView 内部的 Paint。之后即使 Ui.TEXT 被改成新值，已创建的 TextView 不会自动感知。

### 2.2 ThemePickerActivity 只重建自己

ThemePickerActivity.pick() 的流程：

```java
private void pick(String id, String name) {
    WatchAppearance.setLocalTheme(this, id);   // 保存到 SharedPreferences
    recreate();   // 重建当前 Activity
}
```

recreate() 只重建 ThemePickerActivity 自己：
- 走 onCreate() → Ui.screen() → applyTheme() ✅ 静态字段被刷新
- 回退栈里的其他 Activity（HomeActivity、SettingsActivity 等）不重建 ❌

### 2.3 回退栈里的旧 Activity 不会走 onCreate

从 ThemePickerActivity 按返回键，调用链是：onRestart() → onStart() → onResume()

- onCreate() ❌ 不走
- onResume() 中：HomeActivity 只做埋点/观察者/昵称刷新，不检查主题；SettingsActivity 等 6 个 Activity 根本没有 onResume()

### 2.4 底部导航栏不重建 Activity

Ui.bottomBar() 的跳转逻辑：

```java
Intent it = new Intent(a, targets[idx]);
it.addFlags(Intent.FLAG_ACTIVITY_REORDER_TO_FRONT);
a.startActivity(it);
```

FLAG_ACTIVITY_REORDER_TO_FRONT：Activity 已存在时直接提到前台，不重建。主题切换后通过底栏切 Tab，看到的仍是旧实例 + 旧颜色。

### 2.5 为什么「首页设置」(HomepageSettingsActivity) 同步了？

因为它不在频繁操作的回退栈路径上。用户通常从 SettingsActivity 新 startActivity 进入 → 走 onCreate() → 拿到新主题。如果它恰好在回退栈里，同样不会同步——只是概率更低。

## 3. 影响范围

10 个 Activity 全部受影响（仅 ThemePickerActivity 自身正常）：

| Activity | 问题 |
|---|---|
| HomeActivity | onResume 只做埋点/观察者/昵称，不检查主题 |
| SettingsActivity | 无 onResume |
| MessageActivity | onResume 只重载留言列表，不检查主题 |
| DebugActivity | 无 onResume |
| TransferActivity | 无 onResume |
| FastActivateActivity | 无 onResume |
| DonateActivity | 无 onResume |
| BatteryGuideActivity | onResume 只刷新电池状态，不检查主题 |
| HomepageSettingsActivity | 无 onResume |
| ThemePickerActivity | ✅ pick() 调了 recreate()，自身正常 |

## 4. 修复方案

### 方案 A（推荐）：themeVersion + onResume 检查

Ui.java 新增版本号：

```java
public static int themeVersion = 0;

// applyTheme() 末尾加一行：
themeVersion++;
```

每个 Activity 在 onResume 开头加版本检查：

```java
private int lastThemeVersion = 0;

@Override
protected void onResume() {
    super.onResume();
    if (lastThemeVersion != 0 && lastThemeVersion != Ui.themeVersion) {
        recreate();  // 主题变了，重建整个页面
        return;
    }
    lastThemeVersion = Ui.themeVersion;
    // ... 原有 onResume 逻辑 ...
}
```

改动量：Ui.java +2 行，每个 Activity +~6 行，总计约 50 行。

### 方案 B：提取 BaseActivity 基类

```java
public class BaseActivity extends Activity {
    private int lastThemeVersion = 0;

    @Override
    protected void onResume() {
        super.onResume();
        if (lastThemeVersion != 0 && lastThemeVersion != Ui.themeVersion) {
            recreate();
            return;
        }
        lastThemeVersion = Ui.themeVersion;
        onResumeReady();
    }

    protected void onResumeReady() {}
}
```

所有 Activity 改为继承 BaseActivity，原 onResume 重命名为 onResumeReady。

---

## 5. 总结

| 维度 | 结论 |
|---|---|
| 根因 | 颜色是静态 int 字段，View 创建时按值固化；主题切换后只有当前页 recreate，回退栈旧 Activity 不动 |
| 为什么首页设置同步 | 它是新 startActivity → 走 onCreate → 拿到新颜色 |
| 为什么其他页不同步 | 返回键复用旧实例 / 底栏 FLAG_ACTIVITY_REORDER_TO_FRONT 不重建 |
| 修复核心 | onResume 中比较 themeVersion，不一致则 recreate() |
| 改动量 | Ui.java +2 行 + 每个 Activity +~6 行 |
