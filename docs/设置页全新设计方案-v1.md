## 0. 一句话结论

> **这个页面不是「内容太多」，是「没有分组、没有重点，而且所有反馈都跑到屏幕外」。**
> 9 个入口全部平铺、零分组；同一页混用两种容器语言（6 个灰砖 `Ui.row` + 3 张白卡 `Ui.card`），
> 而灰砖的标题字号 **13.5sp 反而比功能卡的 12.5sp 还大**（层级倒挂）；
> 灰砖底色 `CARD2 #EAF0F8` 与页面画布 `CANVAS #E9EAEF` 只差 `(1,6,9)`，几乎融进背景；
> 最要命的是 —— 所有操作的反馈 `resultView` 钉在**页面最顶端**，而触发它的按钮在屏幕中下部，
> 用户点完「重排提醒」根本看不到任何回应。
> 所以动作是 **分组化 + 行化 + 反馈就地化**，不是换配色。

## 2. 设计原则（P1–P6，沿用本项目既定）

| | 原则 | 在本页的体现 |
|---|---|---|
| **P1** | **先给主操作** | 首屏第一组就是「提醒」（本页最高频的设置），把外观看/支持看压到后面 |
| **P2** | **一件事只说一处** | 开关行不再复述「已开启/已关闭」，只写补充信息；「关于」的检查更新与版本号合并 |
| **P3** | **低频/破坏性动作不露脸** | 「测试提醒 / 重排提醒」从并列按钮 → 收进展开区的文字链；「调试」降为支持组末行 |
| **P4** | **分层靠位置与容器，不靠新字号** | 分组标题（`SP_CAPTION`）+ 统一 `CARD` 容器，删掉 `13.5sp` 的灰砖语言 |
| **P5** | **反馈就地发生** | 瞬时动作 → 按钮自身变「已发送 ✓」；持续问题 → 行内常驻副文案（琥珀） |
| **P6** | **零新增 token** | 色/字号/圆角/间距全部复用 `Ui.java` 既有档位 |

## 7. 风险与取舍（不是只报喜）

| # | 取舍 | 代价 | 退路 |
|---|---|---|---|
| **R1** | 反馈从「页面顶部一行」改成「按钮自身变字」 | 反馈**更局部但更短暂**，用户可能正在看别处而错过 | 需要「留痕」的消息（如权限缺失）走**常驻副文案**而非瞬时；两者分工写进 §4 |
| **R2** | 「提前时间」从循环按钮 → 点开弹层 | **多一次点击**，且弹层比循环重 | 若嫌重，退为行内 `− 15 分钟 +` 步进器（仍是设置行，不新增组件） |
| **R3** | 「测试提醒 / 重排提醒」收进展开区文字链 | 排障时多一步展开 | 它们本就是低频动作；未开启时压根不显示，减少误触 |
| **R4** | 三个开关卡合并进一张「提醒」卡 | 若未来某项要独立成卡（如加更多子项），要再拆 | 卡内已有视觉分隔（`CARD2` 展开区 + 1dp 分隔线），拆卡成本低 |
| **R5** | `13.5sp` 档随本页 6 处 `Ui.row` 一起消失 | 若别处仍在用 `Ui.row`，会产生「同一 API 两种字号」的裂缝 | **已核实的调用点**：全项目 `Ui.row(` 共 **7 处** —— 本页 6 处 + **`DebugActivity.java:57`（调试步骤行）1 处**。落地建议：本页 6 处迁移后，**保留 `Ui.row` API 供 DebugActivity 使用**（步骤行的语义确实合适），但把它内部的 `13.5f` 收敛到 `SP_BODY 13f`，随本轮一并消除第 8 档 |
| **R6** | 「外观」组仅一行 | 单行分组略显空 | 后续「深色模式 / 跟随手环」等外观项可自然补入 |
