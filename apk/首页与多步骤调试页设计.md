# EV 课程表同步器 · 首页与多步骤调试页设计

> 版本：v0.5.0（已实现，见 `apk/dist/EVSyncProbe-v0.5.0.apk`）
> 日期：2026-09-26
> 说明：本文是**界面与交互的设计说明**，同时已落地为代码；后续改版请同步更新本文。

---

## 一、设计目标

1. **打开就能用**：进来自动连接，不用记"先点 2 再点 4"这种内部顺序。
2. **过程可见**：4 个步骤实时显示，并给出「预计还需 ~N 秒」。
3. **失败可行动**：出错时不说"连接失败"，而是告诉用户**具体该做什么**（打开 EV / 检查小米运动健康）。
4. **调试与日常分离**：日常用首页，排障进调试页 —— 调试页不自动化，纯粹用于定位"哪一步不通"。

## 四、首页详设

### 4.1 三种状态

| 状态 | 欢迎语 | 状态行 | 进度区 | 错误卡 | 功能入口 |
|---|---|---|---|---|---|
| **连接中** | 欢迎！ | 正在连接手环… | 4 步 + 倒计时 | 隐藏 | 隐藏 |
| **已连接** | **欢迎，XXX！** | 已连接 小米手环10 Pro · EV 1.6.103 (code 932) · 课表 21 节（绿色） | 「连接完成」 | 隐藏 | 显示 |
| **失败** | 欢迎！ | 未连接（红色） | 「连接未完成」 | **显示** | 显示 |

### 4.2 自动连接：4 步 + 预计剩余时间

```
1. ○ 初始化穿戴服务      — 检测小米穿戴服务是否可用
2. ○ 查找已连接设备      — 拿到 nodeId
3. ○ 申请设备权限        — DEVICE_MANAGER + NOTIFY
4. ○ 连接 EV 课程表      — ping 手环上的 EV
```

状态符号：`○` 待执行 / `◐` 进行中（蓝）/ `✓` 完成（绿）/ `✕` 失败（红）

**倒计时规则**（`estimateSeconds()`）：

```
剩余秒数 = 未完成的步骤数 × 1 秒
若已进入"读取资料"阶段：+ 2 秒（export 聚合多个异步读取，最长约 2 秒）
```

每秒 tick 一次，文案「预计还需 ~N 秒」→ 归零后显示「马上就好…」。
连接完成显示「连接完成」（绿），失败显示「连接未完成」（红）。

### 4.3 昵称获取流程

```
connect 成功（拿到 versionName）
      ↓
发 {"action":"export"}          ← 自动进行，无需用户操作
      ↓
解析 data.nickname / data.schedule
      ↓
「欢迎，XXX！」+ 版本号 + 课表节数
```

昵称读不到时兜底显示「欢迎，同学！」，不阻塞其他功能。

### 4.4 失败指引映射（**这是首页最重要的设计**）

| 失败发生在 | 展示给用户的指引 | 附带按钮 |
|---|---|---|
| 穿戴服务不可用 | 请安装并打开「小米运动健康」App，并让它在后台运行 | 重试 / 打开手环 EV |
| 设备列表为空 | 请在「小米运动健康」里确认手环已连接，并保持连接 | 重试 / 打开手环 EV |
| 权限被拒 | 权限申请失败，请在小米运动健康中允许本应用访问 | 重试 / 打开手环 EV |
| **签名校验失败** | 签名校验未通过：本 APK 与手环 EV 课程表不是同一把签名 | 重试 |
| ping 超时无回应 | 请先在手表上打开一次「EV 课程表」，然后回到本页重试 | 重试 / **打开手环 EV**（一键拉起） |
| EV 版本过低 | EV 课程表返回了异常回包，请确认手环上的版本不低于 1.6.62 | 重试 |
| 回包无法解析 | 收到回包但无法解析，请更新手环上的 EV 课程表 | 重试 |

> 设计原则：**每一条错误都要配一个用户能立刻执行的动作**，不能只报错。
> 「打开手环 EV」按钮走 `launchWearApp`（uri = 包名，实测可唤起）。

### 4.5 布局顺序

```
标题「EV 课程表」+ 副标题「安卓同步器」
  ↓
[欢迎卡]   欢迎，XXX！ / 状态行
  ↓
[进度卡]   预计还需 ~N 秒 + 4 个步骤
  ↓
[错误卡]   （仅失败时）指引文案 + [重试连接] [打开手环 EV]
  ↓
[功能入口] [导入课程表] [导出课程表]
           [设置（昵称）] [调试]
  ↓
底部：包名 + 版本号（便于远程排错时确认装的哪一版）
```

## 五、多步骤调试页（DebugActivity）

**与首页的区别**：首页自动跑完；调试页**每步独立可点**，用于定位到底卡在哪一步。

```
[1 初始化穿戴服务]   ○ 待执行        ← 点击执行
[2 查找已连接设备]   ○ 待执行        ← 点击执行
[3 申请设备权限]     ○ 待执行        ← 点击执行
[4 连接 EV 课程表]   ○ 待执行        ← 点击执行

[全部执行]  [重置状态]
[EV 是否安装] [拉起手环 EV]
[手表通知(验下行)] [清屏]
[ 输入框：{"action":"ping"} ]
[发送自定义 JSON]
────────────────
日志区（len + 原文，可选中复制）
```

| 辅助动作 | 用途 |
|---|---|
| EV 是否安装 | `isWearAppInstalled` —— 一眼确认包名/签名是否被系统认 |
| 拉起手环 EV | `launchWearApp`，解决"EV 没运行导致收不到" |
| **手表通知(验下行)** | `sendNotify` 让手环弹通知，**不经过 EV、不动任何数据**，单独证明「手机→手环」通不通 |
| 发送自定义 JSON | 直接试协议报文 |

「全部执行」按 1.5 秒间隔串行推进；**前一步失败则后续跳过**，避免误判。

## 六、设置页（SettingsActivity）

```
当前昵称
  <从手环读到的昵称>（大字）
修改昵称（会写入手环）
  [ 输入框，预填当前昵称 ]
  [ 保存到手环 ]
────────────────
底部：手环 / EV 版本
```

- 保存走 `{"action":"update_settings","payload":{"nickname":"…"}}`
- 三种结果：成功（绿）/ 手环拒绝（显示 `reason`）/ 超时或错误（红）
- 成功后回写 `SyncEngine.nickname`，返回首页即可看到新昵称

## 七、导入 / 导出（TransferActivity，按 mode 复用）

### 导入

```
[选择 JSON 文件] → 系统文件选择器
  → 解析并预览「解析到 N 门课」
  → 弹确认框（明确告知会覆盖 + EV 会自动备份）
  → 发送 import
  → 结果：导入成功，共 N 门课 / 手环拒绝 reason / 超时
```

支持的包装：`[]` / `{courses}` / `{schedule}` / `{schedules}` / `{payload}` / **格式 A** / **EV 导出包**。

> ⚠️ **必须做 `flattenFormatA()`**：EV 的 export 产出是「按天分组」的格式 A，而 import 只认「一条课一个对象」。直接回灌会因顶层缺 `name`/`time` 被**整批跳过**（`convert empty`）。

### 导出

```
[读取手环数据] → export
  → 预览：昵称 / 版本 / 每天几节 / 合计
  → [保存到下载目录] → 「下载 / EVSync / ev-export-<时间>.json」
```

保存用 MediaStore（Android 10+），低版本回落到应用私有目录。

## 九、实现文件

| 文件 | 职责 |
|---|---|
| `Ui.java` | 配色常量与卡片/按钮/行/网格等组件 |
| `SyncEngine.java` | SDK 封装：4 步连接、单步动作、回包路由与 6 秒超时 |
| `HomeActivity.java` | 首页（启动页） |
| `DebugActivity.java` | 多步骤调试页 |
| `SettingsActivity.java` | 昵称设置 |
| `TransferActivity.java` | 导入 / 导出 |

> 硬规矩（写在 `SyncEngine` 里，别改）：**拿 nodeId → 授权 → 注册监听 → 发消息**。
> 不注册监听就发消息，必然 0 回包。
